## 背景

- V11 要验的是 mediatool 隔离容器的可用性与耗时（05 第 5 节；计划 第 8.6 节）。本地部分归 X-02：体检、抽封面、AI 标识写入并回读三个操作可用；无网络、无密钥、只读根等约束全部成立；约 200MB 的文件“体检 + 封面”不超过 10 秒（D5 第 16 节 P9）。
- 约定全文在 D5 第 6.6 节，本包照它做，不放宽。不通过的退路是云端接口体检，AI 标识改人工须法务接受，否则没有退路（03 第 9 节 R9）。
- E17 的验证用样片没有到。按计划 第 4.1 节 E17 行，全部用自制测试片：镜像里的 ffmpeg 现场生成，不入库。
- 环境：开发机（Apple Silicon，Docker Desktop，Docker 29.6.1，linux/arm64，cgroup v2）。mediatool 容器限 1 核、1GB。CI（linux/amd64）上的结果待 PR 的工作流补。

## 决定

mediatool 按 D5 第 6.6 节的约定在本地可行，V11 的本地部分通过，不走退路。镜像定义、容器内服务、调用端与验证办法在 `infra/docker/mediatool/` 与 `packages/services/src/providers/mediatool/`，W1-22 与 G3-A 直接用。下面是照做的细则。

### 1. 镜像

| 项 | 取值 |
| --- | --- |
| 基础镜像 | `node:24-slim@sha256:0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6`（多架构清单的摘要；Node 24.21.0，Debian 12）。取自 Docker Hub 官方库，2026-10-05 |
| ffmpeg / ffprobe | 5.1.9，Debian 12 官方仓库的包 `ffmpeg=7:5.1.9-0+deb12u1`，`apt-get install --no-install-recommends`，版本号写死在 `Dockerfile`；装完当场核对版本 |
| 软件源 | 走 HTTPS（`https://deb.debian.org`）。基础镜像没带系统根证书，用 Node 自带的那一份给 apt 验证书，装完即删，软件源文件改回原样 |
| 其余 | 拿掉 npm、yarn、corepack；用户 `1000:1000`（基础镜像自带的 `node`）；`/work` 属于它；自带 `HEALTHCHECK` |
| 大小 | 约 239MB（基础镜像约 81MB）。ffmpeg 连带装了 196 个包 |

没有换官方静态构建：任务书 第 11 节第 2 项说的是仓库里的 ffmpeg 读不回 AIGC 或不支持所需参数时才换，5.1.9 都支持。

### 2. 调用方式

- 用 D5 写的那一种：共享目录里的 Unix 套接字（`/work/.sock/mediatool.sock`）上的 HTTP + JSON。共享目录是一个命名卷，mediatool 与调用端两个容器各挂在 `/work`，两个容器都是 `network_mode: none`：可用。没有用到“请求 / 应答文件”的退路。
- 宿主机进程直连套接字：命名卷时够不着；在 macOS 的 Docker Desktop 上把宿主机目录挂成 `/work` 试过，宿主机连接得到 `EINVAL`。Linux 上没有试。只记录，不作判据。
- 命名卷第一次挂载时沿用镜像里 `/work` 的属主，所以 mediatool 要先于调用端启动，调用端用同一个用户。

### 3. 输入约束

- 每次调用 ffmpeg / ffprobe 都带：`-protocol_whitelist file`；`-f <解复用器>`（调用端按登记的扩展名给，只认 `mov`、`mp3`、`wav`、`aac`）；`mov` 另加 `-enable_drefs 0 -use_absolute_path 0`；`-probesize 5000000 -analyzeduration 5000000`；路径带 `file:` 前缀。
- ffmpeg 另带 `-nostdin`。ffprobe 5.1.9 没有这个选项（给了会报“Option not found”），它的标准输入接空设备。
- 子进程只拿到 `PATH` 与 `LC_ALL` 两个环境变量；抽封面时线程数写死为 1（容器只有 1 核，且进程数上限是 128）。
- 请求里的路径：共享目录下的相对路径，至少“任务目录/文件名”两段，每段以字母或数字开头、只含字母数字与 `._-`；解析符号链接之后必须还在原处；输入必须是普通文件；输出必须写回输入所在的任务目录。
- 硬超时：体检、封面各 30 秒，加标（含回读）90 秒，到点向整个进程组发 SIGKILL。请求可以带 `timeoutMs` 把它调短（最小 1 秒），不能调长。
- 并发 2，其余排队，最多排 32 个，再多返回 `busy`。
- 子进程的 `oom_score_adj` 写成 1000：容器内存见底时内核先杀 ffmpeg，不杀服务进程。

### 4. 加标与回读

- 参数照 D5：`-map 0 -c copy -metadata AIGC=<JSON> -movflags +faststart+use_metadata_tags -f mp4`。
- 先写到 `<输出>.part`，容器自己回读一遍，读回的与写入的逐字节相同才改名成输出；不相同即删掉并报错。调用端拿到应答后再核对一遍。
- 已有标识的文件再加标会被覆盖。“上游已有标识原样保留”（D5 第 12.1 节）靠调用端先体检再决定调不调，归 G3-A。
- 七个字段的取值本包全用占位值，不定口径（D5 第 20 节 Q9）。

### 5. 调用端

- 独立的客户端 `createMediaToolClient`，不改 `providers/types.ts` 的十二个接口（任务书 第 11 节第 1 项）。怎样挂到 `media` 接口由 G3-A 定。
- 把容器的输出当不可信数据：应答不超过 4MB 且过 Zod；封面由调用端自己从共享目录读，要是普通文件、不经过符号链接、不超过 1MB、是 JPEG，返回的字节就是校验过的那一份；加标产物的大小由调用端自己量，与输入相差不超过 1MB。
- 结果是 `ProviderResult`，不抛错。连不上、没应答、排队满、超时、子进程被杀是 `unavailable`；其余是 `rejected`。

### 6. 容器自查

服务多一个 `GET /selfcheck`：如实报出网卡、路由、用户、能力位、哪些目录可写、cgroup 上限、环境变量的键名。验证用例靠它核对容器里的事实，预发复测可以直接用；调用端要不要在启动时调一次、约束不齐就不用这个容器，由 G3-A 定。

## 理由

实测（开发机；命令与输出见 X-02 的 PR 评论；CI 的运行待补）：

| 任务书 第 7 节 | 结果 |
| --- | --- |
| 第 1 条 镜像可构建 | 通过。镜像里 `ffmpeg -version` 是 5.1.9-0+deb12u1 |
| 第 2 条 写后读回一致 | 通过。读回的 AIGC 与写入的逐字节、逐字段相同（含一个带中文的字段）；各流的编码、时长、帧数、旋转不变；产物大小与输入相差几百字节；`moov` 由后变前 |
| 第 3 条 反例 | 通过。同样的命令去掉 `use_metadata_tags`，产物读不回 AIGC；不带 `-metadata` 的流拷贝重封装也会把已有的 AIGC 丢掉 |
| 第 4 条 体检与封面 | 通过。容器、编码、档次、像素格式、显示尺寸（带旋转元数据的按旋转后算）、时长、帧数、音轨数、`moov` 位置都对；封面是合法 JPEG，1080×1920 的一帧约 70–130KB（合成画面） |
| 第 5 条 容器约束 | 通过。除回环外没有启用的网卡、没有地址、路由表为空，连外部地址得到 `ENETUNREACH`；写 `/`、`/app`、`/etc` 得到 `EROFS`；用户 1000；能力位全 0；`NoNewPrivs` 为 1；`/tmp` 是 64MB；cgroup 里进程数 128、内存 1GB、CPU 1 核；`docker inspect` 的十三项配置都对 |
| 第 6 条 恶意输入 | 通过。见下面的对照 |
| 第 7 条 调用端不信任输出 | 通过。19 条用例 |
| 第 8 条 耗时 | 通过。约 200MB、200 秒的片子，几次运行、每次五轮：体检与封面各不到 0.4 秒，合计每轮不到 0.6 秒（线是 10 秒）；加标含回读 0.3–1.3 秒。不含下载；片子是刚写进共享卷的，读的是内存里的缓存 |

恶意输入的对照（同一个文件，带约束与不带约束各跑一次；不带约束的那一次是造片脚本直接调的 ffmpeg）：

| 输入 | 不带约束 | 经服务（带约束） |
| --- | --- | --- |
| 内容是播放列表的 `.mp4` | ffprobe 5.1.9 把它认成 `hls`，读了它引用的本地文件，还去取它引用的 `http` 地址（被 ffmpeg 自带的白名单挡住） | 按 `mov` 解不开，报 `demux_failed`；它引用的文件没有被读过（按访问时间判） |
| 带外部引用的 mov | 打开 `enable_drefs` 时读了被引用的文件并抽出了帧 | 不跟随：抽不出帧；被引用的文件没有被读过 |
| 只有一个同步帧的片子，抽末尾一帧 | 不调短硬超时：要 6 秒以上才出结果（同一个容器里量的） | `timeoutMs` 给 1 秒：1 秒多一点返回 `timeout`，容器里没有残留的 ffmpeg，没有留下半成品，服务照常可用 |
| 带 `..`、绝对路径、符号链接、跨任务目录的路径 | — | 一律 `bad_path` |

附带的观察（不是验收项）：把内存上限调到 256MB 且不给交换区，约 200MB 的片子三个操作照常；调到 128MB，加标时 ffmpeg 被内核杀掉，服务返回 `killed` 并继续可用，体检与封面照常。预发节点内存 1.87GB（ADR-041），mediatool 的上限要调低时可以参考，以预发复测的数字为准。

## 放弃的备选

| 备选 | 为什么不选 |
| --- | --- |
| 官方静态构建的 ffmpeg | FFmpeg 项目自己不发布二进制，所谓静态构建都出自第三方；Debian 仓库里的包已经够用 |
| 换成 Debian 13 的 ffmpeg 7.1 | 要换基础镜像；任务书点名 `node:24-slim`，5.1.9 已满足全部要求 |
| 软件源固定到 snapshot.debian.org 的某个时间点 | 能让构建永久可复现，但那个服务限速，CI 上不稳。改为版本号写死：Debian 撤掉旧版本时构建失败，由人改版本并重跑验证 |
| 请求 / 应答文件代替套接字（D5 第 16 节 P9 的退路） | 套接字在两个容器之间可用，用不着 |
| 用例等满 30 秒来验硬超时 | 要造一条在任何机器上都解码超过 30 秒的片子，体积与生成时间都大。改为请求可带只能调短的 `timeoutMs`，用例调到 1 秒，走的是同一段代码 |
| 每个任务起一个一次性容器 | worker 要能调 Docker，等于把宿主机交给它，比常驻一个无权限的容器危险 |

## 代价

1. 镜像约 239MB，ffmpeg 带进来 196 个包。Debian 给 ffmpeg 出安全更新后旧版本会撤掉，镜像构建会失败：改版本号、重跑验证、单独成 PR（`infra/docker/mediatool/README.md` 第 7 节）。
2. 容器内服务约 870 行（含注释与空行），比 D5 第 6.6 节说的“约两百行”多：多在体检报告的整形、路径核对、排队与自查。
3. 带数据轨的 mov（如时间码轨 `tmcd`）按 `-map 0` 流拷贝成 mp4 会失败，报 `remux_failed`。剪辑软件导出的 mov 常带这条轨。G3-A 要定：拒收并提示导出时去掉，还是把参数改成只带音视频轨（改参数要回写 D5 第 6.6 节）。
4. 没有验的：硬超时的 30 / 90 秒上限没有用跑满的输入验过；`mp3`、`wav`、`aac` 三个解复用器在白名单里但没有验；封面只做结构检查，不解码；抖音、视频号的上传页能否读到标识（任务书不做，业主手验后记入 V11 备注）；业主的真实样片（放到 `~/.lyx/samples/x02/` 后重跑 `pnpm mediatool:verify` 即加测）。
5. Docker Desktop 的内核会给无网络的容器也建隧道占位设备（`tunl0`、`gre0`、`sit0` 等），关着、没有地址。任务书写的判据“没有除回环以外的网卡”照字面不成立，改成了“除回环外没有启用的网卡、没有地址、路由表为空、连外部地址失败”。
6. D5 里与事实不符、而 D5 不在本包允许目录里的三处，没有改，请业主安排勘误：第 6.6 节“ffprobe / ffmpeg 参数一律 `-nostdin`”（ffprobe 没有这个选项）；第 6.6 节“约两百行的 Node 服务”；第 2 节 `MediaToolProvider` 的签名（实际多了可选的 `timeoutMs`，`poster` 返回校验过的字节与尺寸，`probe` 的报告字段以 `schema.ts` 为准）。
7. 还没做的验证：CI 上的运行（任务书 第 7 节第 9 条，PR 开出来才有）；预发复测（M6，V11 的另一半）。
