## 1. 目标

提供失败定时器、出站死信、回调收件箱的真实查询与受限恢复；后台单页只执行服务端允许动作，所有人工写入留审计。
补受限告警确认/关闭与死信回调重置CLI，不能开放任意SQL、任意流程状态或批量“全部重投”。
“重新排期”只把failed timer恢复scheduled，不接受新fire_at；业务到期时间仍由业务事务维护。

要落地的接口（7条）：

| operationId | schema/约束 |
| --- | --- |
| `admin.outboxDelivery.list` | 真实AdminPage页码/筛选；OutboxDeliveryView，默认死信范围按契约 |
| `admin.outboxEvent.retry` | OutboxRetryBody subscriber必填/note可选；仅该事件该订阅者dead→retry |
| `admin.timer.cancel` | failed→cancelled，ReasonRequiredBody 5–200字，不取消scheduled/running业务timer |
| `admin.timer.list` | 实际运输状态/主体/kind筛选；TimerView，无业务副作用 |
| `admin.timer.reschedule` | failed→scheduled、attempts=0/retry_at=null；NoteOptionalBody，不收新fireAt |
| `admin.webhookEvent.list` | provider/state/date/eventType/cursor；默认failed/dead，只脱敏摘要 |
| `admin.webhookEvent.retry` | dead→received、next_attempt_at=now，NoteOptionalBody；不再写webhook.received |

表：timer、outbox_delivery、outbox_event（只读）、webhook_event、alert_event、audit_log；业务领域表不直接改。
状态机：上述正式运输迁移；告警open→acked、人工open/acked→resolved，使用正式技术状态守卫/公开服务，不直接update绕校验。
事件：人工webhook重置不发重复webhook.received，扫描按next_attempt_at恢复；告警/恢复审计按正式规则，不能用重发业务事件代替运输重投。
页面：system.flow_ops `/sys/flow-ops`，no-board/query-table；默认inMenu=true，移除指向未作代码前置的system.logs父入口，M3媒体页签由W3-08增量，本包不新增第二页面。
x01：alerts_ack（cli.alerts.ack / 关闭告警、重置死信回调），不实现探针/备份/证书任务。
读权限system≥v或flow.ops.view，写flow.ops.manage及注册表stepup/确认照常；实际API全pipeline，列表不泄payload密文/签名/token。
subscriber不能任意创建，事件无对应投递404，非dead/failed状态409；重复required请求不重复审计/重置，成功重读真实详情/actions。
默认CLI只接受ack、close、reset-webhook三个明确subcommand，必须给--staff、唯一告警/收件UUID与5–200字--note；告警ack/close校验sys.health.manage，回调复位校验flow.ops.manage，stdout只摘要，不打印连接串/密钥。
告警认领只open→acked，保留fingerprint/首次时刻；后续重复通知间隔×4由W2-24告警求值器消费acked状态，本包不改告警生成与通知；人工关闭open/acked→resolved，必填note/同TX审计且不发恢复通知，与probe连续3正常恢复区分。
后台日期/目标URL用validateSearch，Transport状态独立显示；失败原因脱敏裁剪，二次确认使用W2-02构件，409刷新不强制覆写。
