## 1. 目标

只实现四路由、关联事件订阅者与S3，复用A核心锁/状态/移交，不重写创建或staff来源。
assign仅无负责人，reassign目标非当前负责人；改变owner但不重置承诺时限。
未来域事实经公开只读端口/事件载荷，缺能力受控拒绝，不拉整个M3–M6为依赖。

本包要落地的接口（完整operationId）：

- `admin.serviceTicket.assign`
- `admin.serviceTicket.reassign`
- `admin.serviceTicket.ref.create`
- `admin.serviceTicket.ref.batchRemove`

本包页面：

- 无。

本包x01：

- `support.onBizEvent`

准确输入与边界：

- assign/reassign：serviceTicketId，body={toStaffId,reasonCode,note?}，note去空白1–100。
- assign持service.ticket.assign且主管；transfer持service.ticket.transfer并核负责人/主管/超级管理员例外。
- 接手staff active、持reply、在操作者允许员工集合；ASSIGNEE_INVALID保not_active/role_mismatch/same_as_current/out_of_scope。
- ref.create={refType,refId}，仅drama_order/billing_order/delivery_ticket/ad；审批关联不可手工添加。
- ref.batchRemove={refs:[{refType,refId}]}，1–5且不重复，不能移除approval_request。
- 前三业务存在且同storeId；billing_order按entityId；范围外统一404。
- 事件按payload父对象匹配且只认关联后发生事件，一事件一工单一条，createdAt取occurredAt。

输出与公口所有权：

- support定义/注册四用例、onBizEvent与S3 full/none/P2；关联唯一键及entry(outbox_event_id,ticket)共同去重。
- 保createAdCancelApprovalRefCompanion原caller事务，审批ref由原取消/退款公口拥有。
- 补/删关联写activity审计；分配/转派按原同态迁移写history/events，不自造核心状态。
- 员工禁用消费A已注册公开改派，不在B另写批量owner SQL。
