M0 各包交的内核件拼成一条跑得通的样例链路，一条命令能重放给业主看；M0 的退出条件逐条对到用例与命令，列成一张核对表；台账的三张汇总与四个计数有脚本可出。之后各里程碑的合流包（W1-21 起）沿用这里的命令与写法。

移交表（`docs/plan/tasks/README.md` 第 5 节）里归本包的各项，与各状态文件“往后移交”里交给本包的事：

| 出处 | 事项 | 本包怎么办 |
| --- | --- | --- |
| 第 9 行 ①、③ | 工作分钟端口的实现；同名检查只查有枚举对应的条目 | 不做：W0-30a 已办 |

## 5. 不做什么

- 不新造业务：样例链路只用 M0 已有的样例登记、测试支架与真实的状态机表，名字带 `lyxtest`，只在测试装配里挂。
- 不改内核各件（kernel、events、flow、timers、audit、ops）的实现，不改已有的检查脚本、反例、工作流里已有的步骤，不改 `layers.json` 与锁序常量。
- 不降待落地基线；不接启动自检；不做接口级的端到端运行器（第 1 节表）。
- 不替业主填看样结论；不打 `m0-done`（会话不合并）。
- 不改库结构，不加依赖。

## 7. 验收

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 样例链路贯通 | `pnpm --filter @liyoxi/services exec vitest run src/testing/m0-chain.db.test.ts` | 一条链路走完：测试装配 → 带幂等键的写用例 → `flow.transition`（加锁、改状态）→ 状态历史、审计、出站事件各多一条 → 中继与派发到订阅者，订阅者执行一次 → 定时器到点执行一次 → 全量不变量 0 违规。同键重放返回同一结果，各表行数不变 |
| 2 | 演示 | `pnpm demo:m0` | 以 0 退出：自己建 `lyx_` 开头的演示库，跑迁移与种子，逐步用中文打印做了什么、库里多了什么，末尾打印四个计数；跑完删掉自己建的库与 Redis 键，可反复跑；有一步不符即非 0 退出 |
| 3 | 故障注入套件 | `pnpm test:fault` | 各包的故障注入、并发、性质测试一条命令跑完，全过；清单在退出核对表里，按“造什么故障、断言什么”分行 |
| 4 | 三张汇总 | `pnpm plan:summaries`；`node infra/ci/plan-summaries.mjs --check` | 由单项文件生成留桩、变更、外部验证三份汇总（不入库）；单项文件缺键、状态取值不对时非 0 退出并指出文件与项。`--check` 进 CI 的 `verify` |
| 5 | 四个计数 | `pnpm counts:report`；加 `--require M0` | 打印已落地接口数、待落地数、留桩数、未实现页面数，按里程碑分列，另出 x01 归属的未落地清单；`--require` 的里程碑有一项没清零即非 0 退出 |
| 6 | 退出条件逐条有测试 | `pnpm exec vitest run infra/ci/test/m0-exit.test.ts` | 退出核对表里自动化九项每一项都点到了用例或命令，点到的文件在仓库里、根脚本在 `package.json` 里 |
| 7 | 不带坏已有门禁 | `pnpm lint && pnpm format:check && pnpm typecheck && pnpm depcheck && pnpm test`；`node infra/ci/classify-gate-changes.mjs --base origin/main` | 退出码 0；门禁改动只有只增 |

进 `gates:selftest` 的反例：一份状态取值写错的留桩文件使 `plan-summaries.mjs --check` 失败；一份有 M0 应回补留桩的清单使 `four-counts.mjs --require M0` 失败。

要登记的留桩：无。

要同 PR 回写的文档：`docs/plan/README.md` 与各子目录 README、模板里“脚本随 W0-30”“按生成物处理”的句子；计划 第 9.3 节“台账”行；`packages/services/src/testing/README.md`；`infra/ci/README.md`；`CLAUDE.md` 第 9 节。

## 9. 交付与收尾

- 一个 PR。提交顺序就是阅读顺序：任务书 → 样例链路 → 三张汇总与四个计数 → 演示命令 → 故障注入套件 → 类型收尾 → 退出核对表 → 说明、状态文件与命令。
- PR 描述按 `.github/pull_request_template.md` 写，各节几句话。
- 不推送、不开 PR、不合并。
