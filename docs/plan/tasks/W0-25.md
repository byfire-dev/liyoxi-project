## 1. 目标

给 M1 的 27 个包四样写用例时反复要用的东西，都从 `@liyoxi/services/testing` 引：

1. **工厂**：一张表一个，直接插一行并返回它。缺省值过得了库的 CHECK 与外键，字段可以覆盖；没给的上级行按外键顺序自动造。主键 UUID v7，时间取注入的时钟。
2. **带种子的干净库**：测试文件里一行拿到“迁移 + W0-21 种子”的库；另有一条命令，在一轮测试之外建一个这样的库（演示、手工排查用）。
3. **表快照比较器**：记下若干张表在两个时刻的行，报增、删、改，可以忽略指定的列。幂等与回放测试用（D7 第 10.2 节 P5）。
4. **假 Provider 支架**：在 W0-19 的十二个替身之上，一次装好（接上“事务内不调外部服务”的断言），并把十二个替身的调用合成一条时间线供断言。

移交表（`docs/plan/tasks/README.md` 第 5 节）归本包的一行：第 25 行后半——“带种子的干净库”调 `runSeed`，不另抄数据。

“N 分组” = `docs/data-model/` 下对应编号的文档；D7 是 `docs/appendix/design/d7-platform.md`。

## 5. 不做什么

- 不写业务逻辑：工厂只插行，不调服务函数、不写审计、不发事件、不写状态历史。要“经服务函数造出来”的演示数据（3 部剧、演示员工）归各自的 M1 包。
- 不加表、不改迁移、不改种子的内容。
- 不加门禁、不动 `ci.yml`：本包的用例随 `pnpm test` 跑。
- 不接 W0-07b 的测试装配、W0-13 的取号、W0-14 的真三件套（基上没有）。
- M1 主路径之外的表（广告、客服工单、退款、发票、通知等）不写工厂：谁先用到谁照同一写法加一个文件。

工厂与硬性规则 5、6 的口径（默认，本任务书定）：工厂绕开服务函数直接插库，是测试数据的准备手段，**只许出现在 `packages/services/src/testing/` 下**；应用层（`apps/api`、`apps/worker`）的用例经 `@liyoxi/services/testing` 用工厂，自己不写插库语句、不引 `@liyoxi/db`。生产代码不引 `testing/`。

## 7. 验收

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 一条命令得到带种子的干净库 | `pnpm test:db:seeded`（要本地的 PostgreSQL 与 `DATABASE_URL`） | 退出码 0；打印库名；库里迁移跑完、种子在、六条断言 0 违规；再跑一遍得到的仍是干净的库（上一遍留下的行不在） |
| 2 | 测试文件里拿到带种子的库 | `pnpm --filter @liyoxi/services exec vitest run src/testing/data/seeded.db.test.ts` | 库里有种子、断言 0 违规；同一轮里种子只播一次（第二个库是从带种子的模板库拷的）；身份是应用角色 `lyx_app` |
| 3 | 每个工厂有连真库的用例 | `pnpm --filter @liyoxi/services exec vitest run src/testing/data/factories.db.test.ts` | 每个工厂不给参数能插入（库的 CHECK、外键、唯一索引都过）；主键是 UUID v7；时间等于注入的时钟；覆盖的字段写进去了；工厂清单与用例清单一一对应（少写一个用例即失败） |
| 4 | 快照比较器 | `pnpm --filter @liyoxi/services exec vitest run src/testing/data/snapshot` | 增、删、改各报得出；忽略的列变了不报；没变时为空 |
| 5 | Provider 支架 | `pnpm --filter @liyoxi/services exec vitest run src/testing/data/provider-harness.db.test.ts` | 十二个替身的调用按先后合成一条；事务里外呼即抛错 |
| 6 | 派生模板库 | `pnpm --filter @liyoxi/db exec vitest run src/testing/derived.test.ts`；跑完一轮后 `pnpm test:db:prune --dry-run` | 两处同时要，只加工一次；测试库从它拷、重置后仍是加工完的样子；一轮结束后本会话不留库（要删 0 个） |

通用门禁照 `CLAUDE.md` 第 8 节；`pnpm test:isolation --scope connected` 仍绿（两个会话的派生模板库互不相干）。

要登记的留桩：无（假三件套是测试专用的缺省，不是留桩；W0-14 合并后换缺省，记在状态文件）。

要同 PR 回写的文档：无。

## 10. 默认（本任务书定）

1. 放在 `packages/services/src/testing/data/`，自带 README；`testing/README.md` 只加一行指过去（两边都在往那份 README 末尾加节，分开放少冲突）。
2. 工厂的形状：`createFactories({ db, clock, seal? })` 返回一个对象，一张表一个方法，`(覆盖的字段?) => Promise<插入的行>`。`db` 收 Prisma 客户端或事务句柄。覆盖字段的类型取 Prisma 的 `…UncheckedCreateInput`（外键写标量列）。
3. 工厂的范围（M1 主路径，按外键顺序，19 张）：`merchant_user`、`entity`、`store`、`entity_member`、`store_member`、`staff`、`file_object`、`billing_account`、`payment_txn`、`billing_order`、`subscription_term`、`point_hold`、`drama`、`drama_episode`、`agreement_version`、`agreement_consent`、`drama_order`、`order_item`、`delivery_ticket`。清单行点名之外多出来的几张，是订购单、订单项的非空外键要的上级。另给两个组合：商家的起步数据、已认证已开通套餐的商家。
4. 工厂只保证这一行与它自动造的上级行过得了库的约束，并在换状态时补上跟着状态走的列；账本的行（批次、分摊、流水、账户上的余额缓存）不造，要账本自洽的数据经服务函数造。
5. `staff`、`subscription_term`、`agreement_version` 的工厂要库里有种子（角色、套餐、协议清单）：工厂配带种子的库用。
6. 带种子的库：种子在一轮测试里只播一次——第一次用到时从迁移模板库拷一份、播种、关掉连接入口，成为“带种子的模板库” `lyx_test_tpl_<会话标识>_seed`；之后每个测试文件的库从它拷。跨进程靠咨询锁排队。一轮结束由 globalSetup 的收尾删掉。播种的时刻取可拨时钟的缺省起点。
7. 命令 `pnpm test:db:seeded`：只建 `lyx_test_` 开头的库（过测试库的守卫），缺省名 `lyx_test_services_<会话标识>_0_seeded`；已存在即删掉重建；不打印连接串。清理用 `pnpm test:db:prune`。
8. 快照比较器按主键认行（可以按表换成别的列）；读的是 `to_jsonb(行)`，所以时间、bytea、数组都是规整后的写法。表名只收小写标识符，且必须在库里存在。
9. Provider 支架缺省把 `assertNotInTransaction` 接在外呼前钩子上（W0-19 的 `createFakeProviders` 缺省空转）。
