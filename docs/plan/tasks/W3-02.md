要落地的接口（8条）：

| operationId | schema/约束 |
| --- | --- |
| `admin.uploadBatch.cancel` | required；只有matching/ready→canceled，无上传中取消 |
| `admin.uploadBatch.commit` | required；仅ready原片批次，重核当前总集数/覆盖，成片BATCH_PURPOSE_MISMATCH |
| `admin.uploadBatch.create` | purpose/targetId/full或partial/files、AI快照；required键还写批次唯一锚点 |
| `admin.uploadBatch.get` | UploadBatchDetail；持有人或实际用途范围，GET无副作用 |
| `admin.uploadBatch.refreshCredentials` | 只本人/none，整批incoming前缀短授权，不存凭据 |
| `admin.uploadBatch.start` | required；matching→uploading，sequence须acceptSequenceSuggestion=true |
| `admin.uploadBatchItem.complete` | 三段式required；复用HEAD/头/CRC校验，失败rejected持久化后返回错误 |
| `admin.uploadBatchItem.update` | episodeNo/skip/replacementFile严格三选一，唯一集号/上下文重检 |

表：upload_batch/upload_batch_item/file_object/file_ref/production_record/drama_episode_master；不新增DDL。
状态：batch matching/uploading/verifying/ready/committed/canceled/expired，item pending/uploaded/checked/rejected/skipped/replaced；正式技术迁移仍完整守卫。
事件：确认file.uploaded/rejected、提交drama.masters_changed；worker体检/生产事件由其所属包接；无新timer/x01/page。
默认expiry建批72小时、活跃顺延至now+72小时且不超过创建7天；整部必须1..expectedCount，partial也不能跳最后有效条目；拒ZIP/空/重名/超限。
匹配冲突全部未匹配；全部不命中且数足才顺序建议，单文件P3/P4也须人工确认；不根据文件数重写totalEpisodes。
原片权限drama.media.manage；成片delivery.episode.register+真实工单范围，由delivery公开authorize返回expectedCount/context，不从media读L3表。
AI used=声明OR剧目事实、common固定；条目登记同TX写production_ctx/留痕。改集号先production360后batch380，重新认定原片/体检，不能套旧结论。
replacement先旧pending→expired、旧item→replaced让唯一键，再建新file/item；skip/replace同TX调用统一复判，ready坏映射提交仍拒绝。
原片commit创建/替换ready master版本、旧版本superseded/引用释放按正式保留期；成片走既有交付create→consumeFinalReleaseBatch，同TX一次消费。
成片UI每2秒轮询，到终态停；8MB块/文件并发3/块并发4、凭据自动续签；刷新/重进从openUploadBatches找回，不把上传100%当已体检ready。

## 5. 不做什么

- 不改内核认领/锁/幂等机制、DDL/索引/metadata/层白名单；不允许uploading/verifying取消。
- 不新增页面、通用上传构件或QC规则，不实现W3-03执行器/W3-04体检，不直写ready假过关。
- 不用成片调用原片commit，不跨员工续签/替换，不凭客户端AI/归属生成终态事实。
- 不跑真实大文件云上传/密钥/部署；不提前清理其他媒体桩或把未actual W1-21桩编造成已回补。
