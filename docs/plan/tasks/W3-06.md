## 1. 目标

要落地的接口（6条）：

| operationId | schema/约束 |
| --- | --- |
| `admin.file.erase` | super_admin+正式stepup/required三段式；10–500字reason与confirm(fileId/category) |
| `admin.file.list` | 正式类别/范围/状态/purgeRunId筛选，AdminPage<AdminFileView>，不签任意读URL |
| `admin.file.restore` | files.restore/required三段式；5–200字reason、deleted未erased且窗口内 |
| `admin.purgeRun.approve` | files.purge.approve/required，confirm(candidateCount/candidateBytes)与行比对 |
| `admin.purgeRun.list` | PurgeRunView分页/筛选/实际数量，GET零写入 |
| `admin.purgeRun.reject` | 同权限/required/5–200字reason，正式x-step-up:skip不得加再验证 |

表：file_object/file_ref/file_purge_run/upload_batch/production_record、audit_log；OCR raw清除由已注册端口，不直读上层。
状态：stored→deleting→deleted、deleted→stored恢复；purge proposed/held/approved/running/done/aborted/rejected，技术守卫不进审批单。
x01：media.sweep每10分钟，清除运行仅每日03:00后首轮；无新页面/timer/事件，恢复无出站事件。
扫描每步独立TX/带原状态条件：pending过期、rejected incoming清理、无live引用到期、batch过期、purge执行、OCR raw/需求提醒公开回调；一步错不挡后续。
候选上限5000，数量/字节/分类阈值取正式参数；list_only都proposed，auto未熔断running，越阈held；同刻只能一个running。
每文件删除前重锁/复核live引用/keepUntil/归属，累计3次guard trip运行aborted，不能批准后直接无条件删候选。
分类钩子在文件TX提交后另TX按自己的锁序处理；ZIP/publishList/derivative补偿按正式I8/I13，未来ZIP未接不能用恒真钩子。
restore窗口secure90天、其余30天，erasedAt非空永不恢复；外部移除marker后TX复核失败要加回marker，原deletedAt留存至成功。
erase stored先deleting禁止新link/签名，TX外删全部历史版本，失败保留deleting同key续作；成功写erasedAt、清originalName与ops审计。
两用例全期间同fileId session advisory mutex、占用/锁连接断开自动释放；PR1只交此机制，PR2消费公开作用域，不以两个TX行锁/Redis短锁代替。

PR1失锁边界：断连事件、定期真实持锁查询及assertHeld观察到失锁后，signal/ALS阻止后续TX与提交；网络半断尚未被观察时，检查与COMMIT之间仍有窗口，不能即时撤销已发外部副作用。PR2须向真实Provider传AbortSignal、复核守卫并补偿，不增加DDL/fencing机制冒充绝对原子性。
注销只释放可释放引用，法定单据/生效协议保留；不物理删除file行/历史审计，不拿用户身份参数绕跨主体授权。

## 5. 不做什么

- 不在乙PR加kernel驻留连接/跨TX锁机制，不改DDL/约束/锁序/metadata/层白名单。
- 不删除live引用/未到保留期/法定证据，不能跳复核/熔断或增加无目标全库CLI。
- 不新增页面/审批/调度机制，ZIP重打/顺延保留期仍归ensureZip接收包。
- 不跑真桶清扫/恢复/彻删、改生命周期/法务设置，fake版本不是真实恢复已验。
