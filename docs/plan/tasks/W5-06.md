## 1. 目标

以当前订单项、账号和使用期事实生成、更新或作废授权书，重复、乱序事件不得复活已取消授权。
这是授权事实机制包；PDF、数字签名、版次查询及人工修订由 W5-07 实现。
按[两片移交](../changes/W5-06-two-phase-handoff.md)执行：PR1 交核心、N16 及完整 N6 函数和真库定点，尚不正式登记 N6；PR2 等 W5-07 完整 actual 后登记并验收完整 N6，两片齐才完成本包。

拥有接口：无（0 API）；不因内部公口新增 HTTP 路由。

| 唯一 x01 | 类别 | 处理边界 |
| --- | --- | --- |
| `docs.onLicenseFacts` | 订阅者 | 事件只提供重新对齐的信号，回读当前事实，不按旧事件载荷恢复旧状态 |

- 唯一事实入口为 `delivery.getLicenseFacts`，由本包定义窄输入输出、真实读取实现和注入桥。
- W5-03/05 交付的订单、工单、许可事实是输入；本包不另造阶段推导、不依赖未合广告实现。
- docs 属 L1，不能查询或导入 L3 的 order/delivery 私有表和实现；经组合根注入纯函数依赖。
- 事实包含订单项与订单编号、主体/门店/剧目、当前阶段、选定账号集合、使用期和交易同意引用。
- 一个账号一封信：粒度为订单项 × 发布账号；新账号建信，移出账号作废，历史信件保留。
- 已取消、已终止、未开工的当前事实不应产生未作废信；已结束按日期派生失效，不翻造状态。
- 自动换版只比较 status、periodStart、periodEnd 三项法律要素；名称笔误的更正留给 W5-07。
- 锁订单项后锁信件/版次，使用现有锁表与稳定顺序，不能添加公共锁级或在账户锁后补锁。
- 建信、法律要素更新、版次快照和 `license_letter.revision_queued` 在同一事务内提交。
- 编号按订单项/平台派生，重建追加序号；不占用另一套 biz_sequence 或复用旧验真码。
- 导出同一 `reconcileLetters` / `ensureLetters`；订阅者、交付守卫与正式纠偏只调用这一个实现。
- 快照读许可、同意与授权方信息同样经窄依赖；不在 docs 中跨层拼接订单、账号、广告查询。
- 事件重放与当前事实无差异时零新增、零改版；唯一约束只是兜底，不替代锁内重新求值。
- docs.N6/N16按真实当前事实和法律要素检查；N6①②经同一收敛公口heal_and_alert，③及PDF哈希、连续版号异常按主文报告，完整函数语义不分片削减。PR1正式登记N16，直接调用完整N6做真库定点；PR2才把完整N6接入正式full，不能靠空事实或恒零结果抹掉违规。
- 交 W5-07 版次快照、指纹、查询出口；交 W5-08 授权就绪公口，真实渲染版判定需再接 W5-07。

本包不独立关闭 M5 桩；`m5-order-aftersales-licenses` 由 W5-07 关闭，广告/授权就绪桩由 W5-08 关闭。

## 5. 不做什么

- 不实现渲染器、证书驱动、下载 HTTP、人工更正/作废入口或广告生命周期。
- 不从历史事件恢复过期快照；不变量自愈只能调同一收敛公口，不用SQL直接写终态或恒真守卫替代事实。
- 不增加重复订阅者/队列，不把已合取消公口复制到 docs，不变更账本退款数额。
- 不确认 Q9、法务正文或真实签名；不使用真实客户资料、密钥、服务器或外部网络。
