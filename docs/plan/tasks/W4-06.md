## 1. 目标

提供真实积分包资源与加购履约，沿 ledger.purchase 入账；服务端资格与购买策略决定是否可购。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `m.pointPack.list` | GET `/m/point-packs` |
| `admin.pointPack.create` | POST `/admin/point-packs` |
| `admin.pointPack.delist` | POST `/admin/point-packs/{pointPackId}/delist` |
| `admin.pointPack.list` | GET `/admin/point-packs` |
| `admin.pointPack.shelve` | POST `/admin/point-packs/{pointPackId}/shelve` |
| `admin.pointPack.summary` | GET `/admin/point-packs/summary` |
| `admin.pointPack.update` | PATCH `/admin/point-packs/{pointPackId}` |

- 现状：积分包资源仍是 meta；ledger.purchase 已有永久 addon 批次与幂等操作，fulfill 对 topup 仍 blocked，购买创建 pointPackId 分支尚未落地。
- 表：point_pack、billing_order、point_lot、ledger_operation、point_ledger_entry；新积分包即上架，原地编辑写审计并增加 lock_version。
- 积分数≥100、价格整数分>0、上架积分数唯一；上下架/更新以 expectedVersion 复核，position 排序与稳定游标按实际契约。
- 商家列表只有上架档、服务端政策许可且老板具 points.topup 能力；套餐未生效/退款处理中/策略隐藏拒绝，不由页面隐藏代替服务守卫。
- 既有付款创建增 pointPackId 分支，服务端锁后重算金额/包版本与 QUOTE_CHANGED；协议 scene=topup 的版本同意记录同 TX 写。
- 付款单内容冻结 packId/points/price，档位后改价或下架不回写旧单；不凭客户端 points 或支付结果直接加积分。
- 已付 topup 由公共 fulfill 调 ledger.purchase：账户420最后锁、单主体 TX；同付款单操作键只一个 addon 批次与流水。
- 到期加购余额 inactive 与套餐恢复后的 resumeAddon 沿既有语义，不设新过期日、不删旧 lot，不修改积分消耗顺序。
- 上架/报价/购买/入账均用真实 DB 公口与注入 Clock；汇总六个月加购按账本/付款事实，不把未支付订单当收入。
- 发已有 billing.points.purchased 与 billing.order_fulfilled，只含编码/数值/引用，无个人信息；本包无新 x01 处理器。
- 协作 W4-05 的 fulfill-upgrade-topup 与 purchase-actions 两桩：本包仅 topup 子项，主责任/其他未办子项保留。

本包唯一 x01 清单：

| 类别 | 登记名与主体 |
| --- | --- |
| 无 | 不登记新处理器或变更旧归属 |

本包无独占回补桩；协作项按本节边界与第7节实证回写，不能提前关闭兄弟包桩。

- 不实现升级、补偿延长、现金退款或永久积分新的消费/过期算法；不改 public ledger 框架。
- 不把积分包价格强设为积分数，不让下架覆盖历史订单快照，不将失败付款计已加购。
- 不关闭 W4-05 尚未完成的协作桩，不新增 x01/页面/DDL/依赖。

- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
