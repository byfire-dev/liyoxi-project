## 1. 目标

`@liyoxi/contract` 从空包变成可用的契约骨架：后面的包只要往里写 Zod 结构与路由，就能得到三份 OpenAPI 与类型。生成物提交入库，`contract:check` 保证它与源码一致。W0-09a、W0-09b、W0-10、W0-13、W0-27a、W0-28 直接等它。

## 2. 依据

“约定”= `docs/api/00-conventions.md`。只读下表所列条目。

| 文件 第 N 节 | 取什么 |
| --- | --- |
| 约定 第 1 节 C1、C2 | 四组前缀 `/api/v1/m`、`/admin`、`/portal`、`/hooks`。根路径探活 `/healthz`、`/readyz`、`/health` 与内网 `/internal/health/*` 不进 OpenAPI、不分配 operationId，只登记（`registryKeyOnly`）。`x-auth` 七个取值：`public`、`optional`、`signed`、`user`、`member`、`staff`、`portal` |
| 约定 第 1 节 C7 | 中间件顺序。本包只用它确认：401、403、426、428、429、400 这些通用码都在幂等行落库之前返回。顺序本身的装配在 W0-22b |
| 约定 第 2 节 C14 | `operationId` = `<m\|admin\|portal\|hooks>.<资源单数驼峰>[.<子资源>].<动作驼峰>`，全仓唯一 |
| 约定 第 4 节 C21–C26 | 成功体 `{ code: 0, message: "ok", data }`，无内容时 `data` 为 `null`。错误体 `{ code, error, message, retryable, requestId, fieldErrors?, details? }`；`fieldErrors` 只随 `VALIDATION_FAILED`。HTTP 只用 200、202、400、401、403、404、409、410、426、428、429、500、503、504，不用 201、204、422。错误码唯一来源在契约，符号、数值、HTTP、默认文案、`retryable` 同源 |
| 约定 第 4 节 C27 | 通用错误码 28 个：符号、HTTP、数值、可重试逐行照抄。`AUTH_REQUIRED`、`SESSION_INVALID` 的“可重试”写“—”。`CONSENT_REQUIRED`、`REMINDED_TODAY` 两个带 `details` |
| 约定 第 5 节 C29、C31–C36、C38 | 标识：小写带连字符的 36 字符 UUID v7 字符串。金额整数分 `…Fen`；积分整数 `…Points`；比例万分比 `…Bp`；`bigint` 出接口为十进制字符串；时刻 ISO 8601，输出 UTC 毫秒三位以 `Z` 结尾，输入不带偏移即拒绝；日期 `YYYY-MM-DD`，月份 `YYYY-MM`；键总是出现，无值写 `null`，空数组写 `[]`；请求体未声明的键剥离、不报错 |
| 约定 第 5 节 C37 | 会增长的响应枚举标 `x-open-enum`，生成的类型是 `已知值 \| (string & {})` |
| 约定 第 6 节 C42–C44 | 游标分页 `cursor`、`limit`（默认 20，上限 50），响应 `{ items, nextCursor, hasMore }`。页码分页 `page`、`pageSize`（默认 20，上限 100），响应 `{ items, page, pageSize, total }`。排序参数 `sort` |
| 约定 第 12 节 C74 | 手写源在 `packages/contract/src`。`scripts/generate.ts` 生成 `merchant.openapi.json`、`admin.openapi.json`、`portal.openapi.json`（OpenAPI 3.1），再用 openapi-typescript 出 `.d.ts`。`hooks` 与探活不出文档。生成物提交入库 |
| 约定 第 12 节 C75 | 路由元数据：`operationId`、`x-auth`（商家端缺省 `member`，后台缺省 `staff`）、`x-capability` 或 `x-permission`（`adminRoute()` 必填；可取 `assert-in-handler`）、`x-clerk-view`（`none` / `same` / `trimmed`）、`x-idempotent`（`required` / `natural` / `none`）、`x-idempotent-by`（`natural` 时必填，字符串数组）、`x-idempotent-reason`（`none` 时必填）、`x-three-phase`、`x-redact-on-replay`、`x-rate-limit`、`x-step-up: skip`。契约自测检查声明齐全 |
| 约定 第 12 节 C87 | 归“约定”的通用结构由本包定义：`DictRef { code, name }`、`CursorPage<T>`、`SentryEnvelope`。其余公共结构归各接口文档，不在本包 |
| D7 第 2.2 节 D6；计划 第 4.2 节 Q4 | contract 不依赖任何工作区包。小程序只引纯常量子路径与类型，不带进 Zod 运行时，靠 `exports` 保证 |
| D7 第 2.4 节 | 生成链路图与生成物文件名；“导出的路由必须进 `allRoutes`”等契约自测沿用参考工程 |
| 计划 第 5.7 节“生成物”行 | 对账方式：重新生成后 `git diff --exit-code`；冲突不手工合并，变基后重新生成 |
| `docs/api/registry-errors.md` 第 1 节 | 28 个通用码的对账基准（由约定 C27 生成） |

## 7. 验收

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 契约自测 | `pnpm --filter @liyoxi/contract test` | 全部通过；用例覆盖第 2–6 条 |
| 2 | 通用错误码对账 | 同上（用例读 `docs/api/registry-errors.md` 第 1 节的表） | 28 行，符号、数值、HTTP、可重试 0 差异；符号与数值各自不重复 |

- 不自行合并。

## 10. 实现要点与顺序

1. 错误码表（纯常量，28 行）与错误体、信封。
2. 通用结构与标识类型：UUID v7 标识、金额、积分、比例、大整数字符串、时刻、日期、月份、两种分页、`DictRef`、`CursorPage<T>`、`SentryEnvelope`。
3. 路由元数据类型与四个构造器（商家端、后台、下载页、回调）；路由登记入口 `allRoutes`。
4. `scripts/generate.ts`：按组拆三份文档，再出类型；输出稳定（键有序、结尾换行），同一输入两次生成字节相同。
5. 契约自测与两个根脚本；最后接 CI 与反例（第 11 节第 6 项）。
