# W2-10 成员邀请、多门店与主体额度生命周期

| 项 | 内容 |
| --- | --- |
| 组 / 里程碑 | G2-B / M2 |
| 规模 / 级别 | M / 乙 |
| 交付边界 | 17 条接口；0 页；2 个 x01 项；回补 2 项桩 |
| 分支建议 | `feat/W2-10-tenant-lifecycle`，从实际 main 开工 |

## 1. 目标

在 W1-03 的单主体草稿/认证与门店基础上，完成店员、邀请、多门店、额度覆盖及主体关闭。
主体关闭和空草稿让位公开为同事务函数供 W2-09 调用；只有一套状态联动，不能各调用方自行改状态。
要落地的接口（本包唯一新增归属）：

| operationId | 结构与核心守卫 |
| --- | --- |
| `m.invitation.accept` | `MembershipResult`；手机号限制、名额、本人已有关系、空草稿让位 |
| `m.invitation.create` | `InvitationCard`；owner 选择店铺与限制手机号 |
| `m.invitation.lookup` | public `InvitationPreview`；匿名最小信息，过期只派生不写库 |
| `m.invitation.markShared` | 邀请分享事实；同键重放无重复写入 |
| `m.invitation.revoke` | pending→revoked；同事务取消 expiry |
| `m.me.membership.leave` | clerk 主动离开；owner 不按此路由退出 |
| `m.member.list` | `MemberItem`、`SeatInfo`、待接受邀请；角色裁剪 |
| `m.member.remove` | clerk 移除、取消所属门店关系与会话授权 |
| `m.member.update` | 显示名/门店范围；不得移除后越权恢复成员 |
| `m.store.archive` | 最后一家有效门店、业务阻断；`StoreBlocker` |
| `m.store.create` | `StoreCard`；先检查门店额度和生命周期 |
| `m.store.delete` | 仅无资质、无业务的草稿门店；软删除而非物理删 |
| `m.store.restore` | by_owner 归档恢复；主体关闭归档不可自行恢复 |
| `admin.entity.close` | 六类阻断、主体/成员/邀请/门店联动 |
| `admin.entity.get` | `EntityCard` / `EntityStoreRow` / `PendingInvitationRow` |
| `admin.entity.member.list` | `MemberRow`；只读，不提供后台成员新增 |
| `admin.entity.quota.update` | 上限覆盖与乐观锁；`EntityQuotaCard` |

表：`entity`、`store`、`entity_member`、`store_member`、`invitation`，会话与相关审批由公开端口联动。
状态机：entity lifecycle、store lifecycle、entity_member status、invitation status；迁移和 initial 历史按既有 flow。
事件按 x01 已登记 `entity.abandoned/closed`、`store.archived/draft_deleted/restored`、成员变化、邀请变化逐行发出。
x01 唯一实装 `tenant.onEntitlementChanged` 与一次性定时器 `invitation.expire`；后者自然键 `invitation.expire:invitation:{id}`。
回补 `m2-order-store-quota.md`：公开 `tenant.assertWithinQuota` 与真实 order 提交调用点，不由 order 另造额度公式。
回补 `m2-profile-overview-members.md`：建档首页 ownerDisplayName、clerkCount、pendingInvitationCount 与 preview 读真实成员/邀请。
成员摘要接既有 profile/merchant-facts 端口或许可只读边界；本包拥有 tenant 取数，W2-11 复用，不重复登记桩归属。

W2-09 等本包 actual 后消费关闭/让位；W2-11/14/15 消费成员与门店公开 DTO，不反向依赖页面。

## 5. 不做什么

不实现 portal 授权 API、主体财务退款/清零、M3 素材写侧；会话吊销走既有公开函数或端口。
不直接向上调用 billing/order/delivery；计数拥有者注册端口，tenant 不查上层内部表。
不因套餐下降自动删成员或停门店；已有用量保留并提示，新增行为由服务端守卫阻断。
不把邀请 lookup 的过期展示当写迁移；不修改已接受/撤回邀请让它重新可接受。
不改门店复合外键、唯一索引、状态 CHECK、全局锁表/layers 和冻结鉴权构件。
不重写 M1 门店上下文或把归档门店对 clerk 开放；保留 owner/by_owner 归档只读口径。

## 6. 允许新增的依赖

无。沿用 L1 tenant→docs 白名单与既有 L0 服务；上层额度/阻断读事实通过纯端口。
如当前缺同事务会话或审批收尾公开出口，提出窄出口方案由拥有者先合，不借内部实现、不新增白名单。
数据库仅使用已接管表与迁移；新公共 schema 保留旧导出，不能改公共角色/权限元数据。

## 8. 需要业主做的事

开工、合并前无。默认门店/成员上限沿已有参数；大客户覆盖经真实权限接口，不靠脚本改库。
真实短信邀请、消息和多账号真机演练仍由 W2-22/W2-30 与业主清单承接，本包替身不称外部已验证。
对名额下降或空草稿让位的产品默认有异议可事后改，不因此停下代码交付。

## 9. 交付与默认

乙类 17 接口一包；如同一关闭机制需独立甲类/结构变更，按 CLAUDE 第 7 节单独提交并记录拆分。
表、接口、timer/subscriber 和两个桩分别回写真实实现证据；状态不把后续页面或通知派发计入完成。
写顺序统一事务→幂等→全局锁→守卫→业务→审计/历史/事件/定时器，计费账户只锁一个主体且最后锁。
空草稿让位按已登记主体 abandoned 联动；不要先锁两个主体账户造成跨主体事务。
clerk 仅选 store_member 分配的有效门店；老板可读 by_owner 归档，entity_closed 不恢复。
成员加入与退出的同意记录通过 docs 公口追加；不可改历史同意，GET 不补签署或归因。
移交 W2-09 同事务关闭/让位、W2-11 成员摘要真实源、W2-14/15 typed 操作和异常结构。
