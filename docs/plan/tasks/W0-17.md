## 1. 目标

- 业务事务能登记、取消、改期定时器；同一语义目标只有一行未取消；周期任务每期一行。
- sla 模块按工作日历算截止时间，并给出时限快照。
- 五个端口有接口与空实现，上层注册后由实现接管。使用方：W0-23、W0-24，M1 起的各域，G2-C、G2-D。

## 5. 不做什么

- 扫描认领、`runTimer()` 执行、失败退避、长任务续租、进程内降级、租约、队列：W0-23。

- 工作日历导入、`calendar.imported`、各域的时限重算订阅者、`calendar.coverage_check`：M2 及各域。
- 五个端口的实现：不变量在 W0-24，告警在 G2-D，埋点在 M7；通知场景解析与提醒查询由各域注册、G2-C 调用。

- 纯提醒（R1–R7）与账务时钟不建定时器行。
- 不改表结构、锁序常量、`infra/ci/layers.json`；不改 W0-07 的事务单元与 W0-15 的 events。
- 不直接读 config 读侧（W0-18 不在依赖里）：策略值与工作时段由调用方传入。

## 10. 实现要点与顺序

1. 先读 W0-07b 已合并的注册接口与 W0-09a 的登记数据，确认“定时器处理器”“周期任务”两类注册项的字段。W0-09a 只登记名称、所属模块、里程碑与“关键类”；节奏、模式、漏跑级别写在各模块的 `register.ts`，本包在装配时对照契约校验。
2. timers：`arm(tx, { kind, subject?, fireAt, key, payload? })`、`cancel(tx, { subject, kinds?, keyPrefix? })`。`kind` 必须在契约登记表里；`subject.type` 取最终表名；同键唯一靠 `uq_timer_dedupe_key_live`。
3. `timer` 行只由已持有主体业务行锁的事务改；`arm`、`cancel` 自己不锁业务行。`timer` 的 `lock_rank = null`，不进锁序表。
4. 主键用 W0-07 的 UUID v7；`fire_at` 由调用方按注入时钟给；`created_at`、`updated_at` 用库时间。
5. 拼键工具只给形状（`{kind}:{subject_type}:{id}[:后缀]`），不替各域拼具体的键。
6. 周期登记：`ensureRecurring(now)` 按 D7 第 7.6 节的算法；只读写数据库，不碰 Redis。循环在 W0-23。
7. sla：读 `work_calendar_day` 组成日历，调 W0-11 的纯函数；全部按 Asia/Shanghai。
8. 五个端口：一端口一文件；签名照依据；空实现只记一条调试日志。
9. `register.ts`：timers 登记“已触发的周期行保留 90 天”的清理项；sla 登记不变量 `sla.N8`。调度在 W0-24，本包只登记并直接调函数测试。
