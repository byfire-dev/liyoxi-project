## 1. 目标

将actual仅promote的执行能力扩为统一media_job调度/队列/远程提交回查/父对象汇合，队列丢失仍由事实表恢复。
落地媒体任务列表/受限人工重试和CI只唤醒回调；接手后删除M1 promote消费者30秒补偿扫描。
处理器按kind注入，体检/审核/理解/ZIP等业务由对应包接，不用空handler将16kind标全完成。

要落地的接口（3条）：

| operationId | schema/约束 |
| --- | --- |
| `admin.mediaJob.list` | system≥v、AdminPage<MediaJobView>，默认failed，状态/父对象/日期成对筛选 |
| `admin.mediaJob.retry` | media.job.retry/required/NoteOptionalBody；仅failed且业务仍需要，重设deadline/attempt/error |
| `hooks.ci.mediaJob.wake` | signed query HMAC(mediaJobId)/natural；不信回调结果，只submitted next_run_at=clock.now |

表：media_job、父媒体聚合、file_object、webhook_event、audit_log；state queued/running/submitting/submitted/succeeded/failed/canceled，不新增状态。
x01：media_job_run循环、media_job队列、hooks.ci.mediaJob.wake回调；无新页面/timer，I10随quick登记。
默认每15秒/最多20行FOR UPDATE SKIP LOCKED，认领短TX→TX外call→父行先锁+state/attempt/lease条件收尾，重复结果一次汇合。
远端userData=`jobId:attemptNo`，先按该事实找回已提交任务再决定重提；回查5秒起上限60秒，回调只能加速不能伪造成功。
回调eventId=`mediaJobId:JobId`，provider=ci，载荷不存；不是submitted/不存在记ignored，不修改running/submitting租约时间。
promote硬超时4分/租约5分/deadline30分；probe3分/4分/30分；同步审核90秒/2分/15分；远端提交2分租约，其余kind时长按D5表。
SIGTERM停止领取，等本机最多45秒再终止/条件退queued，attempt减回一次；被强杀才等租约，不能全库重置租约。
父对象同TX汇合调用纯决策函数，晚结果不覆盖已退役/新generation；10分钟收敛扫描复用同函数，不直写父ready。
retry清attempt/finished/error、nextRunAt=now、deadline=now+kind预算并审计；被废弃/删除业务MEDIA_JOB_NOT_RETRYABLE。
ProduceID默认本任务书定`lyx:{fileId}`（小写UUIDv7），只系统新补标采用；七字段长度规则及上游原标保留，合法取值仍法务外部未验。
任务input/output只白名单事实，不含签名URL/openid/识别敏感值；对象预定键/参数版本进dedupe，provenance留真实生产代次。
已有promote扫描只在统一循环正式覆盖且崩溃/Redis丢失回归通过后删除；不得两套扫描争抢或先删兜底。

## 5. 不做什么

- 不改kernel队列/租约/事务/锁常量、DDL/metadata/层白名单，不新建job_run或业务状态。
- 不用回调报文结果更新 succeeded，不改queued/running/submitting的nextRunAt，不重置非failed任务。
- 不实现W3-04/05业务handler、W3-15 ASR回调、后续ZIP，未接kind明确unsupported不假成功。
- 不拿真实凭据/发云任务/部署，不把fake processed=false当真实体检/转码完成。

## 6. 允许新增的依赖

无。原生HTTP/crypto、现有BullMQ/事务/fast-check足够；新增SDK需另报精确范围，不在本包随手安装。
