## 1. 目标

预发白名单用0.01–1.00元验证支付入账/自动退款，并实现真实资金内网探活；生产绝无自动退款入口。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `hooks.internalHealth.finance.get` | GET `/internal/health/finance` |

- 现状：finance() 只回 null/degraded，路由是 frame；stg.pay.autorefund与shippingInfo 只有登记约定，不能把已登记当已处理。
- 取数表：payment_txn、payment_exception、worker_lease、timer、webhook_event、billing_account、invariant_run/violation、billing_order；读不到/超时仍null+breaches。
- 金额全用整数分1..100，白名单主体且专属预发付款单前缀；pnpm stg:pay-qr通过业务创建/预下单公口，不直接写成功状态。
- 硬保护一：APP_ENV=prod 的任务登记与handler map都没有 stg.pay.autorefund，不能靠运行时 if/flag 代替不存在。
- 硬保护二：任务处理前服务端拒绝>100分，零渠道调用/零业务写；硬保护三：只接本预发前缀单与白名单，不接生产/普通支付单。
- 自动退款只调用 W4-10 公共三段式意图，保持 out_refund_no、权益收回/可退余额与发票守卫，不能另写捷径或抹掉审批事实。
- shippingReport默认关闭，开启才消费 billing_order.paid；现WechatPayProvider无发货口，需官方协议核验的窄兼容方法，事务外调用、幂等与限额保留。
- finance在API进程只读取数，worker不在线仍可报；单指标1.5s超时、缓存沿现5s，失败不得把null变0或依赖worker自己报告。
- 输出仅指标，不泄露单号/主体/openid/证书内容；证书期限取配置公钥模式的商户API证书事实，不读真实密钥。
- 阈值沿h01：未入账10min、心跳3min、timer5min、收件5min、证书30天、推进600s、每日校验/估值26h、受阻24h/72h。
- 只读探活GET无状态迁移/外部动作；自动退款与发货两处理器只追加自己登记，业务事件取已有x01，未知事实fail closed。

本包唯一 x01 清单：

| 类别 | 登记名与主体 |
| --- | --- |
| 订阅者 | `billing.uploadShippingInfo` |
| 周期任务 | `stg.pay.autorefund` |

回补留桩：`docs/plan/stubs/m4-ops-probe-finance.md`；目标涵盖 `GET /internal/health/finance` 只出框架，没有取数。登记键 `hooks.internalHealth.finance.get`。
跨包桩仅在协作包各子项实际完成后整体置完成；本包记录已办子项，未办部分与原责任不得删除。

- 不调用真实云、真实支付或真实员工账号，不用 SQL 直接推进状态，不绕过公口制造已付款/已退款事实。
- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
