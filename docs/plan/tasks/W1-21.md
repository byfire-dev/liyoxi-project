## 5. 不做什么

- 不改各域的服务、接口、页面与它们的测试。脚本在哪一段跑不通，是哪个包的事就回到那个包开 `fix/*` 修，本包不绕、不打补丁。
- 端到端脚本只走主路径一条，不做分支与异常（各包自己的测试管）；不起浏览器（后台 Playwright 主路径在 W1-19）。
- 不放松门禁：待落地基线只降不升；不改 `layers.json`、锁序常量、已有规则。覆盖检查有一时补不上的未引用行，写进一份只减不增的基线并记偏差，不关检查。
- 不做 M2 的事：真机清单第一版（W2-29）、通知、预发。
- 不打 `m1-done` 标签，不推送、不合并。

## 9. 交付与收尾

- 一个工作包一个 PR。提交顺序：端到端脚本 → 演示种子的核对与 `demo:m1` → 留桩检查与覆盖检查 → CI 步骤 → 演示手册、回顾、台账。
- 体量：非测试代码约 500 行（运行器与三个脚本），不落接口与页面，不拆。
- 演示手册写到别人照着能做：前置、每一步点哪里、预期看到什么；写明 `order.start_delay_minutes` 在演示库里由演示种子经服务函数改成 0，手验不用等。不写任何账号的口令（演示账号的初始口令由 `staff:bootstrap` 现场给出）。
- 回顾一页：实际包数与估算的差（含拆 a、b 的）、返工点、复审积压、外部事项进展、风险表要改的、按默认实现的待确认事项汇总表（各 PR 描述里列的默认项编号汇成一张）、退出条件九条各自的证据链接。
- 同 PR 把 `docs/plan/status/W1-21.md` 写成“完成”。
