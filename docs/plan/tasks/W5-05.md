## 1. 目标

交四条样片/订单事实接口与两个订阅者；商家只提compose意见，后台经理整条代录API由W5-08拥有，避免广告修订隐藏依赖环。

本包拥有的完整 operationId（消费者引用不重复计owner）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.order.activity.list` | GET `/admin/orders/{orderId}/activities` |
| `admin.order.quote` | POST `/admin/orders/quote` |
| `admin.sample.markSent` | POST `/admin/samples/{sampleId}/mark-sent` |
| `m.sample.requestChange` | POST `/m/samples/{sampleId}/request-change` |

复用SampleParamSchema、SampleWriteResult/SampleView与现AdminSampleView；补merchant SampleRequestChangeBody（只compose/note/imageFileIds）、markSent body及AdminOrderQuote/活动DTO。商家确认/相册签发已由 [Q9 变更包](../changes/plan-q9-sample-player.md)收敛，本包不重复实现。

- 商家m.sample.requestChange严格按m05：feedbackKind固定compose、note、0–3张imageFileIds；不接feedback_time_ms/feedbackTimeMs、adId或自造versionNo body。
- 版本由sampleId与当前已推送版本的真实关系守卫；旧版本/暂停/无归属/未入库或拦截截图拒绝，不能用旧GET响应强行成功。
- 样片compose变change_requested，记录决定/用户/意见与引用；工单退sample_making，sample_round_no与新环节SLA同事务，不修改广告扣次。
- 后台admin.sample.markSent由原delivery.sample.push权限在真实scope登记已发送，保持当前版本/查看证据与幂等，不把沟通记录冒充商家同意。
- Q9 当前新推送仅 weapp、确认强制勾选；历史四渠道/字段/快照保留，不再按相册/portal/企业微信记录放行新确认。独立 markSent 只作沟通记录。旧 album-only 待确认不能确认；本包后继须与 W5-03/08 明确安全恢复链，当前不声称已有重推/回退接口。
- 播放器由 Q9 先行，本包不重复开发；仍不增加商家时间点UI；后台admin.sample.requestChange整条compose/ad_content与既有可选feedbackTimeMs在08实现，不与本包分裂owner。
- 后台order.quote复用原报价/额度/冻结快照读口，不改金额/积分算法；广告选择旧桩明确仍由08补，不提前闭桩。
- 订单活动只按实际历史/审计返回，GET零写/范围/分页与敏感裁剪；不把查询变成补状态/回填业务入口。
- order.onCalendarImported按当前工作日历重算订购派生；order.onLicenseShortened按当前许可事实处理缩短联动，不使用过期事件快照复活取消行。
- 重复/乱序订阅无新增账/工单或重复时限；R4样片提醒只读查询/场景接W2-17，纯提醒不造定时器。

本包x01：order.onCalendarImported；order.onLicenseShortened；R4沿既有notify.remind_scan的只读领域规则，不另算x01。
留桩：无独占回补桩；W1-20-m5-sample-feedback.md由W5-10实际页面闭桩，本包只提供商家合法反馈与证据公口。
