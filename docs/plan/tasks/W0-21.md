## 1. 目标

一条命令把空库播成“能开工”的样子：8 个角色、63 个通知场景与它们的通道绑定、开关、字典类型与初始项、清单模板、协议清单、订阅槽位、短信模板、价目初始行、估值口径、工作日历、站点配置初始版。之后每次发版紧跟迁移再跑一遍，注册表里新登记的键自动补进库，运营改过的行不动。六条配置类不变量写成 SQL 断言，W0-24 拿去登记。

移交表（`docs/plan/tasks/README.md` 第 5 节）归本包的一行：第 21 行（场景的通道绑定、角色权限点开关由默认授予得出、默认模块等级矩阵、07 第 7 节补登的 2 个开关键）。

“13 分组”“14 分组”等 = `docs/data-model/` 下对应编号的分组文档；D3、D6 是 `docs/appendix/design/` 下的草案；原型在 `design/prototype/admin/src/`。

## 5. 不做什么

- 不写成 Prisma 迁移，不改库结构、授权与 `packages/db`（见第 10 节第 1 项）。
- 不播参数值；不播行业、行政区划、题材等要运营维护或按国标导入的字典项；不播员工、协议正文、受控财务配置、演示数据（各随 W1-01a、W1-03、W1-11b、W1-13）。
- 不建埋点分区：首版迁移已建好当月与未来 3 个月的分区，往后由周期任务 `analytics.partitions` 建。
- 不接不变量框架（W0-24），不登记 `staff.I8`（W1-01b）；只给出断言。
- 不写配置的写侧（字典增改、站点配置发布、日历导入等），不发事件、不写审计：播种没有操作人。
- 不改 `infra/ci/layers.json`、已有的门禁脚本与 CI 步骤；不加 CI 步骤，用例都在 `pnpm test` 里。
- 不改 `docs/data-model/`、`docs/api/` 与 01–05：发现出入记在状态文件“偏差”。

## 9. 交付与收尾

- 一个工作包一个 PR。评审顺序按提交顺序：任务书 → 角色默认配置 → 内核里的种子类型 → 各模块的种子 → 运行器、断言与用例 → 命令行与命令表 → 状态文件。
- PR 描述按 `.github/pull_request_template.md` 填全。
- 同 PR 更新 `docs/plan/status/W0-21.md`。
- 不自行合并。

## 10. 开工前要定的点（默认，本任务书定）

| # | 要定的事 | 默认 |
| --- | --- | --- |
| 1 | 种子是迁移还是命令 | 命令（`pnpm db:seed`），不是 Prisma 迁移。理由：验收要“可重复执行”；注册表会长（新开关、新场景），迁移写一次就定死；测试库由迁移建模板，种子进了迁移，已有用例自己写的行会撞主键。分组文档里的“由迁移播种”读作“紧跟迁移跑播种” |
| 2 | 以什么身份写 | 连接串给的账号，按应用角色 `lyx_app` 的授权就够（用例以它跑）。经 `tx.run` 写，主键由应用生成，时间取注入的时钟 |
| 3 | 已有的行怎么办 | 一律“没有才插”，不改已有的行：运营改过的开关、角色权限、场景开关都留着。只增表与不可改的修订行（等级模板价、计费参数、价目修订）天然如此 |
| 4 | 代码放哪 | 各模块自己的 `seed.ts`（表归谁，种子归谁），从模块入口给出；包级的 `seed.ts` 按固定顺序跑。不新建模块目录，不动 `layers.json` |
| 5 | 角色的默认模块等级矩阵放哪 | 契约的 `authz/role-defaults.ts`（纯常量）：a01 第 3.34 节的“代码默认配置”与种子取同一份。矩阵照原型 `SysRoles`（与 PRD 第 3.3 节一致） |
| 6 | 权限点默认授予怎么进 `actions` | `roles` → `{ on: true, leadOnly }`；`module_viewers`（各模块导出）→ 该模块等级不是 `n` 的角色 `{ on: true, leadOnly: false }`；`super_admin_only`、`all_staff`、`undecided` 不进任何角色；超级管理员的 `actions` 是空对象（它拥有全部）；V1.1 的键不写 |
| 7 | 槽位字段与短信模板变量 | 都播空数组、状态 `unconfigured`：要与微信后台、短信服务商逐字一致，模板选定并报备后随模板编号一起写（计划：M2 的初始化脚本） |
| 8 | `account.verify` 清单没有文档给的条目 | `config.N20` 要 9 套各有启用版本：按账号核验比对表的六项写成六条 |
| 9 | 工作日历播哪几年 | 2026 年按公布的放假安排；2027 年只按“周一至周五工作”铺底，放假安排公布后由后台导入。批次号都是 1 |
| 10 | 六条断言的形态 | 每条一句 SQL，返回违规行（`subject_key`、`detail`），0 行即通过；要对照注册表的把键清单作参数传入。`config.N9` 两半都写 |
