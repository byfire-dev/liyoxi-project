## 1. 目标

单独完成账单下载/解析/匹配/补记机制；同账单重跑不多记资金，缺行与金额差异可证明分类正确。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.reconciliation.list` | GET `/admin/reconciliations` |
| `admin.reconciliation.rerun` | POST `/admin/reconciliations/{reconciliationId}/rerun` |

- 现状：X-04 driver有申请/下载/校验账单摘要和CSV解析，但解析器不强制汇总、不校验行与总额；账单业务/对账资源仍未落地。
- 表：wx_bill_file、wx_bill_line、recon_day、payment_txn、refund_txn、payment_exception；不建M8月结表。
- 事务外申请账单/下载，验证可信来源、返回日期、SHA1摘要/文件字节后解析；URL/账单原文不进事件与普通日志，原件沿media/storage公口留证。
- 整数分/笔数/手续费允许退款负手续费的规则，汇总行必校验；recon_day bigint汇总经DTO字符串，不能Number静默丢精度。
- NO_STATEMENT_EXIST/未配置/超时不是无交易证据；保持wait/失败事实并重试，不建空ok日、不自动消掉platform_only。
- 文件hash/账单日/商户与行号绑定唯一，重复导入更新同事实匹配；is_foreign按appid/mchid与本系统单号格式跳过，不计差异。
- 匹配收款成功需同单号/渠道号/金额；退款非成功只matched_pending并比金额，不更新本库成功；可信成功通过02/10公口补记。
- 缺平台/缺渠道/金额/状态/退款超额按08矩阵开差异；恢复一致时只有允许类型自愈，不能批量resolved伪造财务处理人。
- recon_day技术状态wait/ok/diff/fixed不写flow历史；payment_exception用公共flow，账单行match_state按条件写，不重复发已处理事件。
- 比对可批量只读，但有入账/退款效果按主体分TX；order290→txn300/refund320→exception340→account420，禁止一TX汇总多主体账户。
- bill.download与receipt.daily_digest唯一job本包登记，真实Clock/租约重跑无多次收款/退款；付款差异通知与日摘要走通知公口。
- 独立模型按原件行算期望，不调用待测matcher计算答案；重复导入/乱序callback/query/缺行补到并发用实际DB屏障验证。

## 5. 不做什么

- 不把缺账返回推断为无资金，不用客户端CSV/未核摘要数据补入账，不复制付款/退款终态写法。
- 不混甲类入账并发或退款Saga机制，不做月结/托管款项/V1.1/页面，约600生产行只对账机制。
- 不改provider验签/锁表/DDL/kernel/门禁，不在TX下载或持多个主体账户。
- 不调用真实云、真实支付或真实员工账号，不用 SQL 直接推进状态，不绕过公口制造已付款/已退款事实。
- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
