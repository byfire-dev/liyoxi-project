## 1. 目标

- 事务外必须调外部服务的用例有统一工具：占用、外呼、落结果，中断后可续做，结果只落一次。
- 内容编辑有统一的乐观锁工具。
- 使用方：W1-07（文件确认是多事务三段式），M2 的换绑与短信验证码，M4 的预下单与退款执行。

## 10. 实现要点与顺序

1. 先读 W0-13 的 `tx.run(ctx, fn)` 与幂等上下文。W0-13 的单事务入口读到 `in_progress` 行只返回 409，不产生这种行；占用、抢占、写回由本包加。
2. 三段式由用例声明各段：`claim`（事务一：占用并记业务意图）、`external`（事务外）、`settle`（末个事务：写结果与幂等记录）、可选的 `compensate`。
3. 用例必须写成可续做：`external` 用业务侧稳定的外部幂等号（如商户单号）。工具不替用例生成这个号。
4. 占用写 `state = 'in_progress'`、`locked_until = now + 30 秒`，时钟用注入的。重复请求：`request_hash` 不同 → `IDEMPOTENCY_KEY_REUSED`；未过期 → `IDEMPOTENCY_IN_PROGRESS`；已过期 → 条件更新抢占后续做。
5. `external` 经 W0-07 的“不在事务中”断言执行。故障注入点设在外呼前、外呼中、外呼后三处，用 W0-05b 的工具。
6. “先落库、提交后外调”：本地行先提交；外呼失败时调 `compensate`（删行或标失败），不留占用。
7. 幂等为 `none` 的用例走同一条“事务外调外部、事务内落结果”的路径，但不读写幂等记录。
8. 乐观锁：带版本条件的更新；影响 0 行时回读最新值并抛 `VERSION_CONFLICT`。列名可配。父行锁（`dramaLockVersion`）与逐项修订号（`expectedRev`）只留参数位，不替领域实现。
