## 1. 目标

补工单详情余下表单、已有订单详情售后/授权，以及我的待审批取消类型；0新增API/页/x01。
强制迁移和重新求值两个入口必须接实，不能沿旧只读提示遗漏；不复制流程或退积分算法。

| 既有页面key / route | 本包边界 |
| --- | --- |
| `delivery.ticket_detail` / `/delivery/tickets/$ticketNo` | 指派/改派、暂停、改期、返工补发、SLA、取料、人工制作及强迁/求值 |
| `order.detail` / `/orders/$orderNo` | 当前订单取消试算/申请、售后进度、逐项授权/历史与更正/作废/失败重生成 |
| `approval.mine` / `/approvals` | 仅actual取消kind/domain/operations映射与同页处理/真实业务链接 |

请求/响应从`@liyoxi/contract/types/admin`的operations推导；params/query/body用所属已合schema，不复制DTO。
暂停由取消/资质等实际业务驱动，只展示叠加原因与已有合法处理动作；不虚构手动pause/resume接口。
后台经理代录可选feedbackTimeMs保留并按实际schema提交，不因商家A31限制删字段或改成商家时间点入口。
写前cancel旧查询再读实际GET，scope/权限/actions与DTO版本/回显确认必须一致；未声明字段不造。
中央stepup按metadata重放原key，creator/异人/大额二人规则由服务端；不以单管理员代两人证据。
取消详情准确显示冻结释放/已扣退回/到期去向与未执行，不能写现金退款或端上估算“到账”。
授权更正/作废/重生成仅按实际actions和版次，POST受理不代表PDF就绪；GET核新旧版/失败及可用文件。
所有动作保同步闩、同意图key与未知结果恢复；成功POST后仅实际GET核状态/活动，读失败不重复新提交。
换工单/订单/审批、退出或范围变化取消在途并丢迟到结果；旧确认/上传/签名不得回填新对象。
新表单仅本域Modal正文滚动/间距，保留原样片/成片上传、质检、批次与授权下载主路径。
