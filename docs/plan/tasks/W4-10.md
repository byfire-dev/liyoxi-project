## 1. 目标

单独交退款三段式机制：领域申请/权益收回/渠道交易分层，重复乱序与每段中断都不丢资金事实。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.paymentOrder.refundQuote` | POST `/admin/payment-orders/{paymentOrderId}/refund-quote` |
| `admin.paymentOrder.refundRequest.create` | POST `/admin/payment-orders/{paymentOrderId}/refund-requests` |
| `admin.refundRequest.approve` | POST `/admin/refund-requests/{refundRequestId}/approve` |
| `admin.refundRequest.confirmNotAccepted` | POST `/admin/refund-requests/{refundRequestId}/confirm-not-accepted` |
| `admin.refundRequest.execute` | POST `/admin/refund-requests/{refundRequestId}/execute` |
| `admin.refundRequest.get` | GET `/admin/refund-requests/{refundRequestId}` |
| `admin.refundRequest.list` | GET `/admin/refund-requests` |
| `admin.refundRequest.recordOffline` | POST `/admin/refund-requests/{refundRequestId}/record-offline` |
| `admin.refundRequest.reject` | POST `/admin/refund-requests/{refundRequestId}/reject` |
| `admin.refundRequest.retry` | POST `/admin/refund-requests/{refundRequestId}/retry` |
| `admin.refundRequest.summary` | GET `/admin/refund-requests/summary` |
| `admin.refundRequest.void` | POST `/admin/refund-requests/{refundRequestId}/void` |
| `admin.refundRequest.withdraw` | POST `/admin/refund-requests/{refundRequestId}/withdraw` |
| `hooks.wechatpay.refund.notify` | POST `/hooks/wechatpay/refunds` |

- 现状：现金退款资源仍meta；ledger.refund只是积分退回，不能当现金退款。preview/suspend/resume/revoke套餐退款域公口需新增，不假称已落地。
- 表：refund_request、refund_txn、approval_request、payment_txn、billing_order、subscription_term；发票/差异以本域守卫与窄公口协作。
- refund_request flow状态为pending_approval/pending_execution/executing/done/not_executed；refund_txn渠道状态created/processing/succeeded/closed/abnormal/not_accepted/abandoned，不写伪flow历史。
- 提交冻结服务端规则核算、审批同TX与周期refund_request_id闸门；7天窗口仅按提交时Clock检查，批准复核未使用/余额/差异，升级周期按M98/M111拒绝window/qualification_failed。
- E1：intent/权限/stepup/版本/回显复核，红票及可退余额检查；同TX revokeTerm、记entitlement_revoked_at、建refund_txn(created)、executing后提交。
- 事务外以原 out_refund_no 调微信；E2只落可信结果/幂等记录，不覆盖提前到达的成功；未知/超时保持可查事实，不新建退款号重试。
- retry/confirmNotAccepted沿C51先占用、事务外外调、后TX写结果；未受理须停止重试≥10min且真实queryNotFound，不能把普通网络404/超时当不存在。
- 真实driver已有queryRefund而公共WechatPayProvider暂无；只兼容扩出同语义查询口，保留旧methods/result/beforeCall，不增SDK。
- 渠道任意状态晚到成功都入库；相同成功金额只累加一次，超退真实开refund_over差异；未入账收款退款不改付款单/发票，入账款累计达实付才refunded。
- 失败回pending_execution但权益已回收不恢复闸门、不允许void；未执行驳回/撤回/作废恢复周期/发票/差异，不能丢可用余额或擦除历史。
- approval30/refund_request70 → order290 → payment_txn300 → refund_txn320 → invoice330/exception340 → account420；相关行先发现后按主键升序锁，同TX一个主体。
- 本机制包含rf.poll、submitRefundTxn、可信退款callback与两人CLI放弃abnormal；CLI要显式两员工确认/审计，不能sql改状态或跳过签名。

本包唯一 x01 清单：

| 类别 | 登记名与主体 |
| --- | --- |
| 订阅者 | `billing.submitRefundTxn` |
| 定时器 | `rf.poll`（主体 `refund_txn`） |
| 回调 | `hooks.wechatpay.refund.notify` |
| 命令行 | `refund:abandon-txn`（`refund_abandon_txn`） |

本包无独占回补桩；协作项按本节边界与第7节实证回写，不能提前关闭兄弟包桩。

## 5. 不做什么

- 不混支付入账并发机制、完整对账或页面，甲类约600生产行围绕同一退款Saga；体量不足先调度。
- 不抹除已回收权益/失败渠道事实，不把超时当未受理，不改out_refund_no重试，不无视红票守卫。
- 不做V1.1托管款项/代付/结算，不新增kernel/idempotency/flow/savepoint机制，不把退款拆成异主体TX。
- 不调用真实云、真实支付或真实员工账号，不用 SQL 直接推进状态，不绕过公口制造已付款/已退款事实。
- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
