## 1. 目标

新增小程序积分充值1页并接旧钱包/套餐选择/付款结果的真实微信支付与续费升级加购入口。
页面key `sub/billing/topup/index`；0新增API/x01，回补m4-weapp-wallet-entries与m4-weapp-wechat-payment。
钱包入口桩分工：本包购买/支付入口，流水跳转由W4-15、发票合同跳转由W4-16最终消费；两本未合不能宣称全入口完成。

| 消费operationId（非新增归属） | DTO与行为 |
| --- | --- |
| `m.wallet.get` | Wallet/权益及服务端actions，不自己推进账户或判断到期 |
| `m.purchasePolicy.get` | 当前mode/channels/effective quote策略及协议键，disabled隐藏/阻断 |
| `m.plan.list`、`m.plan.quote` | PlanCard/PlanQuote，续费升级试算真实服务端结果 |
| `m.pointPack.list` | PointPackCard；加购限制、有效期/积分/金额由服务端 |
| `m.paymentOrder.create` | 入库付款单与同意版本；返回真实id后才能调用支付/上传 |
| `m.paymentOrder.wechatPrepay` | PayParams/paymentOrder/replayed；每轮支付新意图，不缓存参数 |
| `m.paymentOrder.sync` | 每单3秒节流，主动查单终态来自后端 |
| `m.paymentOrder.get`、`m.paymentOrder.cancel` | 详情/取消outcome paid/cancelled/cancelling真实回显 |
| `m.paymentOrder.transferProof.create` | 对公结果页原凭证链保留，不先传业务未入库的凭证 |
| `m.agreement.list`、`m.agreementVersion.get` | 当前《会员服务协议》《积分规则》版本，按后台真实同意范围 |

平台requestPayment成功只是渠道客户端回调，到账/履约仍等详情或sync；不得乐观加积分。
C50 prepay重放payParams=null不能当已付：保留付款id，读取详情，仍pending才以新key重新签发。
用户取消/非取消失败区分，付款单保持pending，继续支付新意图key；同点击重入同步锁。
copy/渠道/支付模式按引导/策略/quote，不硬写“iOS不允许”或按单一OS静态开放。
quote版本/协议/ctxRev变动即清无效同意与旧结果；切店/卸载/角色变化阻止旧回调/错误写UI。
支付成功回调按登记pay_success真实请求订阅并上报；H5明确平台空转，不能当微信实付证据。
requestPayment确缺只新增窄平台函数/实现在既有平台模块，不改旧函数形状；先由调度核路径边界。
Q10默认线下签约+后台代建，不接虚拟支付；V2实际结论反向另变更，不提前放宽入口。

## 5. 不做什么

- 不写支付签名、Provider/账本算法、虚拟支付或匿名/portal流程，不直连服务/DB。
- 不改lib/request、共享权限/同意/构件、根依赖/metadata，不能给H5实际requestPayment。
- 不把null payParams/客户端success当已付款，不无限轮询、不上传未入库单凭证。
- 不清除原同意/角色/幂等/迟到守卫，不把旧clerk hidden入口改成购买权限。
- 不真实开微信支付/自动退款/花钱；小额实付必须W4-09和业主授权。
