## 0. 分阶段交付（同编号，调度批准）

按[拆分记录](../changes/W2-28-compat-before-mixed.md)分为独立可用的 a 与 b：a 交 `contract:compat`、退役登记、临时标签用例、两条门禁自测及 verify 只增步骤；b 交真实双版本同库四步冒烟、HTTP 主流程适配、main 工作流和同提交发布阻断。a 不新增混跑脚本或假服务结论，不改 b 的判据与 10 分钟上限。a 验收对应第 7 节 1–4 及自身静态门禁；b 保留第 7 节 5–8 的整包要求。

2026-10-15 调度批准先交 b 的独立 HTTP 桥接前置，再实现四步编排：复用 M1 默认七段主链，增加对应版本 HTTP transport、真实时间等待、受保护同库 attach 与本轮 MinIO/本地微信协议 IO。允许必要 `packages/services/src/testing/` 装配伴随；不改生产业务服务、契约或旧版本源码。前置不是混跑通过，也不提供发布放行。

状态文件仍一份，a 合入后继续“进行中”；W2-29 及全部原下游仍等 b 完成。环境泳道、M2 退出条件、HTTP/页面/x01/留桩归属与包数均不变。

## 1. 目标

- 小程序一旦上传送审，它那一版的契约就受保护：之后任何 PR 改坏了它还在用的接口，合并前被 `pnpm contract:compat` 拦下。后台与下载页对上一个发布版本做同样的检查。
- 每次合并到 main 后自动验一遍“新版本写出的数据，上一个版本读得了、也写得进”：这是回滚安全与“先声明、下一版再写入”唯一的自动化证据。失败阻断发布，不阻断 PR。
- 这两样是 M2 退出条件 ⑤ 的另一半（“`contract:compat` 与新旧版本混跑冒烟进 CI”）。使用方：W2-29（送审上传打的标签靠它保护）、W2-26 的发布预检、之后每一个改契约与改结构的包。

## 5. 不做什么

- 不打任何标签，不动小程序的上传与送审（W2-29）；不改契约的内容与生成物。
- 不做 D7 第 10.6 节第 19 项里的迁移演练（`@ignore` 删列三步、CHECK 约束替换各做一次）：随第一个结构变更包。
- 不做核心接口的 P95 基线（计划 第 5.5 节“M2 起加”一行的每晚任务，D7 第 10.6 节第 16 项）：不在环境五包里，见移交。
- 不为了让检查通过去改别的包的接口；发现 main 上已有的不兼容，停下报告。
- 混跑里不连任何真实外部服务：两个版本都以 `APP_ENV=local` 起，全用替身 Provider。

## 10. 实现要点与默认（本任务书定）

| # | 要定的事 | 默认 |
| --- | --- | --- |
| 1 | 没有 `v*` 标签时混跑拿谁当“上一个版本” | main 上一个提交（合并提交的第一个父提交）。合并即部署之下，它就是预发上正在跑的那一版。建生产、有了 `v*` 标签之后改为最近一个 `v*` 标签，只改这一处 |
| 2 | 上一个版本的镜像从哪来 | 先按 `sha-<12 位提交号>` 从镜像仓库拉；拉不到就用 `git worktree` 检出那个提交现构建。上一个提交还没有 server 镜像的定义时算“没有可比版本” |
| 3 | 还没写 Zod 结构的路由 | 它们不在生成的 OpenAPI 里。旧版没有、新版有：算新增，通过。旧版有、新版没有：算删路径，失败 |
| 4 | 读冒烟遍历什么 | 上一个版本自己的 OpenAPI 里全部不带路径参数的 GET，加上第 ② 步产生的各对象的详情 GET（脚本记下它建过的对象编号）。只看有没有 5xx，不比内容 |
| 5 | 混跑里时间怎么过 | 不拨时钟。库里先灌演示种子（`order.start_delay_minutes` 为 0），脚本里“等 worker 处理完”用轮询加上限（每步 30 秒） |
| 6 | 检出时取标签 | `verify` 的检出步骤改为带标签的浅克隆；标签多到拖慢检出时再改成只取 `weapp-v*` 与最近一个 `v*` |
| 7 | 结论怎么传给发布 | 混跑任务在该提交上留一个名为 `mixed-smoke` 的检查结论；`deploy-stg.yml` 调编排脚本时把它作为预检的输入传进去 |
