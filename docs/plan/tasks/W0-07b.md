## 1. 目标

各模块在自己目录的 `register.ts` 里登记六类东西，组合根自动收集成一份装配结果，api 与 worker 两个进程拿到的是同一份。以后的包（W0-13–17、W0-22–24 与各域）只写自己的 `register.ts`，不改任何共用的清单文件。登记有重名、缺实现，进程启动时就报错，不留到运行时。

“D7”= `docs/appendix/design/d7-platform.md`；“15 分组”= `docs/data-model/15-integration-ops.md`；“x01”= `docs/api/x01-events-jobs.md`。

移交表（`docs/plan/tasks/README.md` 第 5 节）里没有接收方是本包的行。与本包有关的两处，开工时查过：第 4 行（单独的 `gate-change` PR 放开一个装配文件引 `@liyoxi/db`）等本包定组合根的位置，见第 11 节第 2 项；业主清单 `#27-7`（`packages/db` 入口把 `PrismaClient` 类也导出了）留给本包加规则，见第 7 节验收 6。

## 10. 实现要点与顺序

1. `kernel/assembly/types.ts`：六类登记项、`ModuleRegistration`、`defineRegistration`；端口 `definePort`（单实现，可带默认实现）、`defineKeyedPort`（按键多实现，如各类审批执行器）、`implement`。
2. `kernel/assembly/assemble.ts`：`assemble({ entry, appEnv, registrations })`，先按 `envs` 过滤，再查重名与缺实现，问题攒齐了一次抛出（`AssemblyError`）；`collect.ts`：从一组模块入口里取 `registration`。
3. 样例模块夹具两个，用例覆盖验收 1–4。
4. 组合根 `packages/services/src/assembly.ts`：各模块的 `index.ts` 逐个整体引入，哪个给出了 `registration` 就收哪个；`assembleServices`。`providers` 不参加：依赖规则 `providers-via-types` 只许 kernel 引它的入口，它也没有要登记的东西。自测覆盖验收 5。
5. 测试装配 `testing/assembly.ts`：真实模块之外再追加样例登记。
6. lint 规则片段与反例；说明文档；`CLAUDE.md` 第 9 节；状态文件。

## 11. 开工前要定的点（默认，本任务书定）

| # | 要定的事 | 默认 |
| --- | --- | --- |
| 1 | “自动收集”怎么做 | 组合根把各模块的 `index.ts` 整体引入（`import * as`），入口里有 `registration` 就收（`providers` 除外，见第 10 节第 4 步）。模块加 `register.ts` 时只在自己的 `index.ts` 加一行再导出，不动共用文件，并行的包之间不冲突；不用生成物，也不在运行时扫目录（打包后不可靠）。`register.ts` 不直接被组合根引用：依赖规则只许引模块的 `index.ts`，不为此放松规则 |
| 2 | 组合根放哪；移交表第 4 行 | 放 `packages/services/src/assembly.ts`（包级文件，不属于任何一层，可以引全部模块的入口），经 `@liyoxi/services` 的入口给 api 与 worker。客户端工厂按 `packages/db` 入口的注释与 D7 第 2.3 节规则 7，由 services 的 kernel 在装配基础设施时调，应用层不必引 `@liyoxi/db`：移交表第 4 行那个 `gate-change` PR 可以不开，由 W0-22 开工时最后确认 |
| 3 | 两个入口收到的内容是否不同 | 相同。`entry` 只记在装配结果上，不参与过滤：api 也要订阅者表（W0-15 任务书 第 7 节第 7 条），哪些东西只在 worker 里跑由用它的包决定 |
| 4 | `envs` 的取值与缺省 | 取 `loadEnv` 的四个环境（`local`、`test`、`stg`、`prod`）；不写即全部环境；六类都可以写。环境由调用方传入，不读 `process.env` |
| 5 | 重名查什么 | 同一环境里：订阅者名、定时器 kind（处理器与周期任务合在一起）、不变量编号、清理项名、单实现端口的实现、按键端口的键、模块名。环境不相交的两个同名项不算重名（如预发与生产各一个实现） |
| 6 | 缺实现查什么 | 登记项的处理函数不是函数；模块声明的端口没有默认实现、在某个环境里也没有模块实现；实现指向没有模块声明过的端口；`modes` 非空的不变量没有 `run` |
| 7 | 处理函数的签名 | 照草案：订阅者 `handle(tx, event)`；定时器处理器 `handle(tx, timer)` 返回 `fired` 或 `skipped`；周期任务 `run(ctx)`；不变量 `run(tx, scope)` 返回违规列表；清理 `run(tx, ctx)` 返回删除行数。事件、定时器行、上下文的类型只写当前确定的字段，用它们的包只增字段 |
| 8 | 名字的写法 | 订阅者名、kind 用契约 `NAME_FORMATS` 的正则；不变量编号 `<命名空间>.<编号>`。在不在契约的登记里由 W0-15、W0-17 查 |
| 9 | `PrismaClient` 的规则放哪 | lint 的 `no-restricted-syntax`：`packages/db` 之外不得 `new PrismaClient`。与 W0-07 的 `$transaction` 规则是同一条 ESLint 规则，后写的会整条盖掉前面的，所以新片段把两组条目拼在一起 |
