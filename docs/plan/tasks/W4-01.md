## 1. 目标

把 X-04 已验证的自研微信支付薄驱动接入 Provider 装配与真实预下单；不以 fake 成功代替渠道事实。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `m.paymentOrder.wechatPrepay` | POST `/m/payment-orders/{paymentOrderId}/wechat-prepay` |

- 现状：providers/wechat-pay/ 已有签名、验签、解密、查单/关单/退款与账单解析；providers/index.ts 尚未选择该真实驱动，业务预下单仍是 meta。
- 表：billing_order、payment_txn、idempotency_record；复用已冻结字段与索引，不新增付款状态或 DDL。
- 事务 A 锁定主体范围、订单与当前尝试，复核未终态、微信渠道、金额、payer/openid 与退款闸门，创建/复用 out_trade_no 对应 created 交易后提交。
- 事务外调用 Provider；请求金额取服务端快照，不接受浏览器支付结果作为入账事实。外呼前继续经过现 beforeCall 守卫。
- 事务 B 复核同一订单/交易版本，把可信 prepay_id 与有效期写入，created → prepaid；幂等记录随 B 写，渠道响应到达前不得占用账户锁。
- 换付款人前查询已支付时，伴随实现最小可信 recordChannelSuccess→现公共 applyPayment 微信适配→fulfill；这是本接口正确性必需，不能反向等待W4-02或另建paid写法。
- root已准本包最小伴随能力：匹配/不符/重放及保存点证据，保留银行路径；W4-02后续消费实际公口扩回调/兜底/关单，W4-03独占并发甲机制。
- 签名调起 signMiniProgramPay 已在真实driver实现、公共Provider尚未暴露；只做对应typed窄出口与装配，未配/旧fake/unconfigured保持兼容。
- C50：首响应的 payParams 只供本次调起，重放 payParams=null 且 replayed=true；签名参数与原始通知不进日志、审计或异常 detail。
- 严格校验 appid/mchid、整数分、订单号与渠道响应签名；过期/失败不得把 created 写成 prepaid，更不得推断 succeeded。
- 配置全空走未配置；部分配置启动即拒绝且只列字段名。复用 SDK 核验结论与 node:crypto/fetch，不引入新支付 SDK。
- 锁序沿订单 290 → payment_txn 300；需要入账时同一 TX 仅一个计费主体、账户 420 最后锁，复用既有时钟。

## 5. 不做什么

- 不做微信收款回调、退款或对账；换付款人成功查单只调用本包伴随交付的可信入账公口，W4-02 后续消费该实际公口。
- 不改微信 AppID/真实密钥，不部署，不做真实小额付款；上线仍等 E2。
- 不改 request/idempotency/kernel 机制、根依赖、锁表或已冻结渠道字段。
- 不调用真实云、真实支付或真实员工账号，不用 SQL 直接推进状态，不绕过公口制造已付款/已退款事实。
- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
