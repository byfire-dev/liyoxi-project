## 1. 目标

`flow.transition` 对交付工单、审批单、客服工单三张表的迁移能写出 `elapsed_work_min`：在这之前端口没有实现，这三张表一迁移就抛错，M1 的审批与交付用不了。另把 W0-26 的状态色调字典与契约的枚举对上：字典里写了“表.列”的条目，取值都是契约里那一列枚举的取值。

移交表（`docs/plan/tasks/README.md` 第 5 节）第 9 行的 ①、③ 归本包；其余各项仍在 W0-30。

“01 分组”= `docs/data-model/01-kernel-flow.md`；“14 分组”= `docs/data-model/14-config-data.md`；“规范”= `design/design-spec.md`；D3 是 `docs/appendix/design/d3-flow.md`。

## 7. 验收

| # | 验收项 | 命令 | 判据 |

| 1 | 三张表的迁移写得出工作分钟 | `pnpm --filter @liyoxi/services exec vitest run src/flow/work-minutes` | 生产装配里端口有实现。播过工作日历种子的库上，审批单做带停留时长的迁移，`elapsed_work_min` 与手算相等：跨午休（不扣）、跨周末、跨节假日、跨调休上班日各一例；改了工作时段参数后按新的时段算 |
| 2 | 原有用例不坏 | `pnpm --filter @liyoxi/services exec vitest run src/flow/ src/sla/ src/config/ src/assembly.test.ts` | 全过；“端口没有实现时三张表迁移即抛错”一条仍在（用例里显式去掉实现） |
| 3 | 状态字典键与契约枚举同名 | `pnpm status-tone:check` | 字典里每个写了“表.列”的条目：契约里有绑定这一列的枚举，条目的取值都在枚举的取值之内。0 差异，退出码 0；只读文件，不连库 |

## 10. 开工前要定的点（默认，本任务书定）

| # | 要定的事 | 默认 |
| --- | --- | --- |
| 1 | 实现放哪、怎么登记 | 放 `sla`：它已有日历的读取，与 flow、config 同在 L0，同层可互引。在 `sla/register.ts` 里用 `implement(workMinutesPort, …)` 登记，flow 不引 sla |
| 2 | 工作时段怎么读 | 端口的实现是静态登记的，手里只有事务句柄，拿不到进程里那个带缓存的配置服务。在迁移的事务里经句柄读 `param_value`：取迁移时刻生效的 `work.start`、`work.end`，库里没有即代码默认值。不走缓存：算出来的数写进只增表，事后改不了 |
| 3 | 工作时段配错了（起不早于止） | 用代码默认值，不让迁移失败；配错由 config 的自检报 |
| 4 | 日历缺行 | 照纯函数按“周一至周五工作”兜底，不抛错。端口的实现拿不到装配结果，不在这里告警：缺行由不变量 `sla.N8` 与日历覆盖检查报 |
| 5 | 测试装配 | 真实实现进了登记，`createSampleFlow` 缺省就带它；用例传自己的实现即顶掉它，传 `null` 即“没有实现” |
| 6 | 同名检查查什么 | 只查有枚举对应的条目（`column` 非空）：列在契约里绑定了枚举、取值在枚举之内。标了“无枚举对应”的条目不查（移交表第 9 行 ③）。字典没有覆盖到的枚举取值不算差异 |
| 7 | 检查脚本放哪 | `packages/shared/scripts/`：`infra/` 不在工作区里，按包名引不到契约与 shared（照 `machines:check` 的先例）。脚本登记进 `infra/ci/gate-files.json` |
