## 1. 目标

补齐配置写读闭环，保证字典引用、参数预约、开关版本和清单版本可追溯；年度日历修正能重算在途审批决定时限。
给审批框架增加真实 due_at/sla_snapshot、决定时限定时器与超期读侧；新增仅升 lockVersion 的公开入口供后续资质字段修正复用。
本包没有页面，W2-07 接配置四页；审批页由 W2-06 接既有审批接口。现有读侧与审批状态迁移保持兼容。

要落地的接口（13 条）：

| operationId | schema/结果约束 |
| --- | --- |
| `admin.calendarDay.batchImport` | CalendarImportBody；按年内置或 days/source，CalendarImportResult |
| `admin.calendarDay.list` | year/includeAllDays；CalendarYear，未导入 importedAt=null |
| `admin.checklistTemplate.activate` | checklistTemplateId；无请求体，草稿启用，ChecklistTemplateView |
| `admin.checklistTemplate.create` | 新版本请求；ChecklistTemplateView，版本内容按场景校验 |
| `admin.checklistTemplate.discard` | checklistTemplateId；无请求体，仅 draft→retired，ChecklistTemplateView |
| `admin.dictItem.create` | DictItemCreateBody；编码由服务端分配，DictItemView |
| `admin.dictItem.update` | DictItemUpdateBody + lockVersion，编码/类型/上级不可改 |
| `admin.dictType.list` | 类型元数据与可编辑规则，不允许创建新字典类型 |
| `admin.featureFlag.list` | FeatureFlagList；仅超级管理员读取规则 |
| `admin.featureFlag.update` | 既有规则 schema + lockVersion；规则序与缺省分支不丢 |
| `admin.paramValue.list` | group/keys 多值；ParamList 含 current/pending/source/lastSaved |
| `admin.paramValue.replace` | 整批 items/expectedRev/effectiveAt；一项冲突整批回滚 |
| `admin.paramValue.withdraw` | paramValueId/reason；未生效且距生效至少 10 分钟，ParamItem |

既有 dictItem.list、checklistTemplate.list、approval.list/summary/get 仅增量补真实字段，不重复计 M2；route method/path/metadata、参数默认与枚举冻结不动。
表：dict_type、dict_item、param_value、feature_flag、checklist_template、work_calendar_day、approval_request、timer/outbox/audit；不新增表/列或修改草稿。
状态机：复用 approval_request.status 的提交/决定/撤回守卫，时限在同 TX 记录/取消；checklist_template.status 配置生命周期按新建→draft、draft→active/retired、旧 active→retired，不写 status_transition，不擅增业务状态机。
事件：calendar.imported、approval.sla_breached；x01 本包仅 approval.onCalendarImported、sla.breach（approval_request）、calendar.coverage_check。
字典新增锁 dict_type 行发编码；停用在同 TX 检查真实引用，拒绝 block_if_referenced；实际 profile/content 引用及并发新引用不能漏算，历史名称仍可读。
参数复用 shared/src/params/defs.ts，按键排序取咨询锁，比对所有 expectedRev；预约不会被立即值隐式取消，撤销按正式时间边界。写后提交才 bump 对应 config.cache 版本，跨进程与待生效时刻遵循既有缓存上限。
日历逐年铺底、逐日比较：相同导入不升批次不发事件；只有 kind 变化才取新 calendarVersion，note/source 的审计按 a01。自定义 days 日期不重、adjusted_workday 只能周末，source 必填。
默认：页面仅用内置年导入；缺年份明确 VALIDATION_FAILED。coverage_check 从业务 clock 的北京时间判断 12 月 1 日起下一年覆盖，只告警不抓取、不自动伪造官方日历。
审批 submit 用当时参数快照与工作日历写 due_at/sla_snapshot；calendar 订阅仅重算未完成、工作日制且窗口交集的对象，保留原策略参数并更新日历版本，重设 timer、写差异审计。
决定/撤回取消决定 timer；已决/过期/重复事件守卫无副作用。I3 区分 decision/execution 去重后缀，I5 超期列表用实际快照时限；未来执行类由注册端口返回真实事实，不恒真放行。
默认：继续使用 actual FOR UPDATE 锁审批，外键插入等待属于现有串行化；本乙包不新增 FOR NO KEY UPDATE 或修改 flow 按表选锁的机制。只升版本入口持同一锁、核对 pending/版本，不能制造迁移/决定记录。

## 5. 不做什么

- 不改 params defs 的默认值/范围来迎合写侧，不增任意参数/字典类型，不将 system 枚举变成自由配置。
- 不做 W2-07 页面、W2-03 员工联系时限，不实现 W4 执行类领域单据或通知发送；各 x01 主体按唯一归属接入。
- 不改 kernel/flow 锁强度、锁序、layers.json、SLA 算法、表结构、草稿、冻结 metadata 或既有 gate。
- 不抓取/解析国务院网页、上传文件或自动导入；内置年是版本数据，不在业务事务中做外部 IO。
- 不以待办状态或零引用桩消除 I3/I5；有尚未实际 producer 的来源时明确登记覆盖范围并移交。
