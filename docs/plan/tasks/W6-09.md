## 1. 目标

交付作品巡检、下架核查两页，并把账号健康、商家下架确认和巡检记录接回四个既有页。
拥有接口：无；0新增x01。新页2、旧页4，评审页面总数6；不把弹层拆成新页。

| 页面key / route | 唯一边界 |
| --- | --- |
| publish.patrol / /publish/patrol | 新页；队列、详情、证据与巡检动作 |
| publish.offline / /publish/offline | 新页；下架审核工作台、批量核查与升级 |
| /publish/accounts | 旧页；账号真实列表/汇总及异常标记 |
| sub/publish/accounts/index | 旧页；服务端允许下的账号解绑 |
| sub/publish/tasks/index | 旧页；下架任务、确认及发布清单复制 |
| sub/order/launch-record/index | 旧页；真实巡检历史与现行上线记录 |

| 消费operationId（不重复拥有API） | 实际用途 |
| --- | --- |
| admin.patrolTask.list/summary/get/create | 实际队列、范围、详情及创建结果 |
| admin.patrolTask.markNormal/markAbnormal/recover/remind | 结果/恢复/催办，按当前DTO/actions |
| admin.channelAccount.list/summary/markAbnormal；m.channelAccount.unbind | 跨端账号健康及解绑后的实际关联影响 |
| admin.takedownTask.list/summary/get/check/batchCheck | 下架队列及逐项、批量核查结果 |
| admin.takedownTask.markOnline/sendBreachNotice/escalate | 仍在线、违约通知与升级动作 |
| m.takedownTask.list/summary/confirm | 商家下架待办与确认；不把自声明等同后台核查 |
| m.orderItem.publishList.get；既有上线记录GET | 发布清单复制与巡检记录，消费实际已合读侧 |

后台summary与列表采用相同scope/query，不能按当前页条数拼页签计数。
批量核查按契约上限/逐项结果展示；部分失败保留原原因，不全表乐观改成功。
商家确认、后台核查、仍在线与升级分别显示；发送受理不冒充平台实际下架或通知到达。
周期巡检/下架任务由后端生成，页面刷新不能制造任务、重排到期或复活取消任务。
异常账号、关联内容、处理记录从服务端读；解绑不可在前端绕开仍有关联的守卫。
weapp列表合并保持既有分页/恢复协议，当前门店或账号改变时废弃旧响应。
发布清单复制在tasks页由本包唯一接入；W6-11仅负责downloads页，不并改同一旧页。
上线记录巡检块展示历史与当前事实，不把未巡检显示为正常；旧链接核验结果保留。
本包独占W1-20-m6-publish-future留桩；不关闭后端usage/ZIP/清单桩。
