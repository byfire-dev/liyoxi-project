## 1. 目标

交四个制作人工入口和取料/下载三接口，复用已合M3处理器与文件事实，补master_checkout而不是再造流水线。

本包拥有的完整 operationId（消费者引用不重复计owner）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.deliveryTicket.material.downloadUrls` | POST `/admin/delivery-tickets/{deliveryTicketId}/materials/download-urls` |
| `admin.deliveryTicket.material.list` | GET `/admin/delivery-tickets/{deliveryTicketId}/materials` |
| `admin.orderItem.download.list` | GET `/admin/order-items/{orderItemId}/downloads` |
| `admin.productionRecord.list` | GET `/admin/production-records` |
| `admin.productionRecord.normalize` | POST `/admin/production-records/{productionRecordId}/normalize` |
| `admin.productionRecord.recheck` | POST `/admin/production-records/{productionRecordId}/recheck` |
| `admin.productionRecord.restamp` | POST `/admin/production-records/{productionRecordId}/restamp` |

按a05补ProductionRecordView、ProductionJobAccepted、NormalizeBody/RestampBody/RecheckBody、MaterialList/DownloadBody/DownloadResult与DownloadRecord DTO；保正确联合体和短链接脱敏/有效期，复用原File/Production结构。

- productionRecordId就是文件ID；事实查询至少fileIds/orderItemId/adId之一，按真实父对象scope裁剪，不返回media_info.raw。
- normalize/restamp/recheck权限分别沿production.*，只触发既有M3 jobs/driver，required key与原media_job去重都保留。
- 规格化/补标产生新文件与来源链，复制实际声明/所用版本，不能篡改原已入库对象或直接把pipeline_state写成ready。
- 产物体检/AI回读成功后仍须原剪辑师登记新成片/广告版本并重新QC，不做V1.1自动采纳/自动登记。
- 制作素材清单只读，不签发；materials/downloadUrls按实际master/ad_version/store_asset/profile_media联合体选择。
- 取原片必须当前就绪版本、1–50集；广告版本/素材须是本单实际集合，已移出档案但订单保留引用按主文允许，不放宽归属。
- 原片下载写master_checkout复合唯一键及真实版本/次数；每份访问审计，30分钟短签名地址不缓存进幂等结果。
- 签名与文件下载门槛沿当前本人任务/范围和内容安全状态；无权限/跨门店/拦截/失效对象拒绝并不泄露URL。
- 成片包、download_grant及access日志三来源排障记录可读，GET零写，旧授权/过期地址不充当前可下载事实。
- 04等03 actual串行交接materials/order-items契约所属子集；不改媒体租约/轮询/预算、锁序或M6 ZIP机制。

本包x01：无新x01；调用原M3媒体任务执行器与media.production.checked，不自造production.derived消费者。
留桩：无本包独占桩；制作人工/取料是08§6.8明定后续范围，不能以旧流水线已绿宣称本七API完成。
