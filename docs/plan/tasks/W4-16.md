## 1. 目标

交小程序发票/合同2页，并完成已签协议付款单bizTitle取数桩；0新API/x01。

| 页面key | 结构与主要行为 |
| --- | --- |
| `sub/billing/invoices/index` | InvoiceRequestCard/InvoiceContext，可开票付款单选择、申请、记录/文件 |
| `sub/billing/contracts/index` | SignedAgreementItem/SignedAgreementItemForClerk，所同意版本与PDF |

| 消费operationId（非新增归属） | 行为 |
| --- | --- |
| `m.invoiceRequest.list`、`m.invoiceRequest.summary` | 记录/页签计数/抬头与状态，服务端真值 |
| `m.invoiceRequest.create` | 同意/付款单选择、企业邮箱与开票字段；同意图key与真实提交结果 |
| `m.invoiceRequest.downloadUrls` | 每次现签PDF/附件，C18/C50和文件错误受控 |
| `m.paymentOrder.list`、`m.paymentOrder.summary` | eligible未申请单据与可开票计数，不端上计合计估税 |
| `m.agreementConsent.list`、`m.agreementConsent.summary` | 实际已签版本、本人/主体范围与计数 |
| `m.agreementVersion.get` | 同意过的实际版本内容/PDF，不拿当前新版冒充旧同意 |
| `m.agreement.list` | 真实待同意/当前版本信息，复用W2-12正文公口 |

已签列表是m.agreementConsent.list；summary为clerk none，店员不得请求此计数，用户级协议按trimmed列表显示。
合同页授权书区域留M5，M4仅协议/已签PDF；不空展示假授权书或伪签章。
回补m4-docs-signed-agreement-biz-title：docs/signed.ts目前bizTitle=null，须经窄只读端口批量取billing.describePaymentOrders。
docs在L1不得import L2 billing/查billing_order；root/runtime绑定真实billing公开getter，无N+1/空实现冒充。
此必要跨域读口作为独立小companion先合后消费，或经调度明确本包最小装配边界；不直接改billing算法。
老板可见本主体已签（含前任owner），clerk只本人用户协议且无bizType/bizNo/bizTitle；字段禁用遵C57。
开票/重放返回敏感字段按actual裁剪，邮箱/PII不进埋点、URL不落持久缓存。
同意版本/页面锁/上下文/卸载/迟到结果保留，写后真实GET更新；失败不假显示“已开票”。

## 5. 不做什么

- 不计算发票税额/可开票金额/协议版本，状态/actions与正文纯消费。
- 不代签同意、虚构邮件送达/PDF签章，不绕clerk/owner范围或打开别主体文件。
- 不重写公共request/Uploader/平台/构件、支付模式，0新依赖/HTTP/cron。
- 不让L1 docs读取上层订单，不能把null标题硬编“购买套餐”声称回补。
- 不显示M5授权书业务、不上传真实发票/读取客户邮箱或凭据。
