## 1. 目标

超级管理员可保存既有角色的授权配置，员工可修改本人密码、重绑 TOTP 与绑定企业微信；后台可查询脱敏审计，并通过专用 POST 查看获准字段明文。
使用已经落地的授权、数据范围与再验证机制；本包只实现用例和持久化，不重新设计权限模型。
PII 查询必须先在独立事务提交 access 审计，再解密返回；审计失败即拒绝，查询响应与日志都不能泄漏其他字段。

要落地的接口（10 条）：

| operationId | schema/结果约束 |
| --- | --- |
| `admin.auditLog.get` | 路径 auditLogId；AuditLogDetail，差异与 meta 全部按规范脱敏 |
| `admin.auditLog.list` | 过滤/日期/分页；AuditLogItem 列表，scope 在服务端裁剪 |
| `admin.auth.bindWecom` | BindWecomSelfBody，按 flags 二选一手填 userid/扫码 code |
| `admin.auth.changePassword` | 当前/新密码；本人改密，当前会话保留、其他会话吊销 |
| `admin.auth.me.confirmTotp` | 6 位 code；新恢复码首次可见，重放 recoveryCodes=null |
| `admin.auth.me.enrollTotp` | 无请求体；15 分钟待确认密钥，no-store，未确认前旧密钥仍有效 |
| `admin.piiReveal.create` | PiiRevealBody；白名单 subjectType/field，PiiRevealResult 含 auditLogId |
| `admin.role.defaults.get` | roleKey；代码注册表的默认 RoleConfig，不写库 |
| `admin.role.get` | roleKey；RoleDetail 含真实 lockVersion、成员与可编辑配置 |
| `admin.role.replace` | RoleConfig + lockVersion；完整替换、审计 diff，超级管理员角色拒绝修改 |

表：staff_role、staff、staff_session、audit_log；字段查看按 a01 第 3.41 节完整表/字段清单，不增加自由 SQL/table/column 参数。
状态机、出站事件、定时器、新页面：均无。角色配置、安全自助与明文访问不是状态迁移；不新增 x01 归属。
角色 replace 复用 13 模块 n/v/o/e、角色适用 actions/leadOnly、own/group/all 的现有校验；o 仅 delivery/publish。保存与审计同 TX，提交后失效角色缓存，跨进程读取按既有 5 秒口径。
审计 list 的 ops 要 system≥v、access 只超级管理员；get 按该行 stream 判定，越权详情 404。PII 字段逐项走 assertPermission、对应 scope 与注册表要求的 assertStepUp；范围外统一 404，非法组合 400；保留 admin.pii_reveal 与 global 限流。
默认：先在事务外完成权限/scope 校验，独立调用 audit.record 提交 access，再读取解密结果；不在已有业务 TX 内偷偷重开事务，也不新增 kernel 脱离事务机制。
访问审计记录用途、目标、员工/会话、客户端和 note，不记录 value；返回 Cache-Control:no-store，不写幂等记录、缓存、指标标签或错误日志。
默认：各字段由所属模块注册只读定位/密文/scope 事实，security 不反向 import 域模块或 SQL 查询上层表；同层只经 kernel 端口。完整字段清单都按正式 schema 校验，未来业务没有记录或合法 scope 事实时受控 404，不以 fake producer、恒真 scope 或恒零表代替。
本人改密与确认 TOTP 同 TX 吊销其他会话，当前会话保留；confirm 替换密钥、旧恢复码作废，stepup_at 更新，不复用超级管理员替人重置接口。
默认企业微信手填不能声称平台已核验；扫码分支通过既有 provider 三段式处理，事务外换 userid，未配置/超时不落绑定事实。

## 5. 不做什么

- 不改 authz 判定、权限默认矩阵、模块级别、数据范围算法、字段裁剪、再验证窗口、中间件顺序或限流配额；发现机制问题另开甲类修复。
- 不做 W2-03 员工禁用/池/管理员代重置，不写 W2-06/08 页面，不实现客服/财务的业务 producer。
- 不做审计导出接口/队列；它不在本包 10 条归属，交 W2-31 拆 G7-A 时明确接收。
- 不开放任意字段、GET 明文、脱敏结果以外的日志详情；不手改 golden、contract generated 或冻结 metadata。
- 不改 layers.json、已有 gate 规则、表结构或加密协议；新增 golden 登记的 diff 若被判放松即停止，不能豁免。
