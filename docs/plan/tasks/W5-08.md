## 1. 目标

老板能提交、查看、确认和修改本门店广告，实际积分冻结/扣减与版本确认可追溯。
同时接通订购选广告与 identity/profile/delivery 的广告事实，回补恒空、恒真输入。

拥有接口（12条；原权限、能力、店员裁剪、幂等与里程碑不变）：

| operationId | 方法与实际路径 | 请求 → 响应结构 |
| --- | --- | --- |
| `m.ad.list` | GET `/m/ads` | AdListQuery → AdCardPage |
| `m.ad.quote` | POST `/m/ads/quote` | AdQuoteBody → AdQuote |
| `m.ad.create` | POST `/m/ads` | AdCreateBody → AdState |
| `m.ad.get` | GET `/m/ads/{adId}` | 当前门店adId → AdDetail |
| `m.ad.confirm` | POST `/m/ads/{adId}/confirm` | AdConfirmBody → AdState |
| `m.ad.requestChange` | POST `/m/ads/{adId}/request-change` | AdRequestChangeBody → AdRevisionResult |
| `m.ad.submit` | POST `/m/ads/{adId}/submit` | AdSubmitBody → AdState |
| `m.ad.downloadUrls` | POST `/m/ads/{adId}/download-urls` | AdDownloadUrlsBody → DownloadUrl |
| `m.playable.get` | GET `/m/playables/{playableId}` | playableId及资产授权 → 复用Playable/PlayableSource |
| `admin.ad.cancelQuote` | POST `/admin/ads/{adId}/cancel-quote` | AdCancelQuoteBody → CancelQuote |
| `admin.ad.cancelRequest.create` | POST `/admin/ads/{adId}/cancel-requests` | AdCancelRequestCreateBody → CancelRequestDetail |
| `admin.sample.requestChange` | POST `/admin/samples/{sampleId}/request-change` | AdminSampleRequestChangeBody → AdminSampleView |

| 唯一 x01 | 责任 |
| --- | --- |
| `ad.returned_stale`（主体ad） | 到点仍待补充才发原事件/客服待办，不自动执行取消或退积分 |

- ad 保留7态与独立 GG 单号，按真实 flow 迁移；提交时记交易同意、计价/SLA快照和积分冻结。
- quote 只试算零写；提交重新核政策/金额/门店闸门，价格过期不沿用客户端输入扣账。
- 资质未通过保持待指派，不提前 capture；真正指派/扣减由 W5-09 消费本包窄公口完成。
- 免费修改次数按创建快照；超次修改采用原账本公口，版本/扣减/事件同事务，不自写积分余额。
- 后台样片代录整个API由本包单写：compose调W5-05样片公口；ad_content只限免费次数，超次拒绝不代老板付费。
- 保留AdminSampleRequestChangeBody的versionNo、feedbackKind、条件adId、note、既有feedbackTimeMs与截图，不给商家新增ad_content或时间点输入。
- 广告内容分支锁广告→订单→项→工单→样片，真实重开ad并计免费轮次；浮动绑定其他工单的活样片superseded，暂停中恢复后重算，已钉版不被污染。
- 同key同body返回原结果，同key异body拒绝；退款/取消锁内重核，不因过期报价重复冻结或扣减。
- 老板 ad.request/ad.confirm 与当前门店为准，店员、异主体、停用门店沿契约拒绝；不借视图裁剪代替授权。
- 只有已推送版本可见、可确认；preview_channels 取推送快照，查看证据须对应版本，不能靠GET伪造已查看。
- 小程序播放关闭后的保存/勾选兜底沿既有证据规则；m.playable.get 按资产类型授权，广告权限不能放开样片或预告片。
- 可选广告为已有确认版、未取消且无在途取消；修改中的已确认广告按浮动引用参与，样片确认时钉版。
- 订购 quote/create 校验广告门店、类型、广告位与剧目许可；引用/计数在实际写事务中一致，不查询恒空副本。
- 登记 ad merchant facts 给 identity/profile 的原 keyed reader，低层消费者只拿端口结果，不反向引用 ad。
- delivery 的广告就绪消费实际确认版本；授权就绪消费 W5-06 对齐和 W5-07 实际 ready 版，不以有pending信件代替。
- 后台广告取消两入口复用 W5-01/02/03 的唯一试算/审批/执行链，保留现 ad.cancel 公口，不另造退积分执行器。
- 对外 URL 沿真实存储/可播放资产签发、访问留痕与 no-store；未ready/归属不符时零签发。

本包唯一关闭四桩（均在docs/plan/stubs/）：`m5-identity-overview-ad.md`、`m5-profile-overview-ads.md`、`m5-order-ads.md`、`m5-delivery-ad-license-ready.md`。
本组当前含meta-only路由；按上述API文档补strict输入输出，复用已有Playable，不能只改挂载清单算落地。
广告新页及checkout展示属于页面包，本包0新页；不替 `m5-weapp-order-ads` 写页面完成。

## 5. 不做什么

- 不实现后台广告指派/推送/人工查看凭证接口、不注册广告SLA处理器；这些由 W5-09 单写。
- 不实现新页面、M6 portal会话/ZIP、平台发布，不把老板广告权限用作公共视频播放授权。
- 不复制取消执行/现金退款、不直接写成功积分/流水/确认事实，不降媒体ready与真实查看证据守卫。
- 不把本机假签名/替身/未配置通道当作法务、数字证书或真实平台审核验收。
