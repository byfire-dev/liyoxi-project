## 1. 目标

- 超级管理员能在后台新增员工、看员工列表与详情、看角色列表；新建的员工凭激活码走 W1-01a 的激活四步登录。
- 上层有一个定了签名的分配入口 `staff.pickNext(tx, pool, scopeKey)`：M1 按最小实现给人，M2 换成按城市轮询，调用方不用改。
- 上层取员工摘要有一个只读函数（按 id 批量取 `StaffBrief` 的展示列），各域的列表与详情不用各写一遍。
- 使用方：W1-02（员工列表页）、W1-08 与 W1-16a（选人下拉）、W1-17（开工时指派）、各后台接口包（员工摘要）。

本包落地的接口（4 条）：`admin.staff.list`、`admin.staff.get`、`admin.staff.create`、`admin.role.list`。表：`staff`、`staff_activation`、`staff_role`、`staff_group`、`assignment_pool_member`（只读）。状态机：`staff` 的“新增（立即启用）”“新增（暂不启用）”两行。事件：`staff.created`。不变量：`staff.I8`。

M1 的口径（哪一段做、哪一段不做）：

| 项 | M1 做到哪 |
| --- | --- |
| 新增员工 | 全做：立即启用（`active`、待激活、生成激活码）与暂不启用（`pending`）；分组缺省进该角色的默认组；角色未开放（`available_from = v1.1` 且开关关着）只能暂不启用；`inviteWecom` 只把状态置为 `invited` |
| 激活码怎么给 | 不发短信。`activationDelivery` 传什么都按 `manual` 办：响应里带一次 8 位明文，幂等记录里置空，重放回 `null` 与 `replayed: true`。登记留桩，M2 回补 |
| 员工列表 | 完整列表（`system ≥ v`）与选人模式（带 `pool` 或 `recommendPool`，按 a01 第 3.12 节的池读权判）；筛选、分页、排序照文档。`actions` 恒为空数组：十个动作的接口都在 M2 |
| 在办量与推荐 | `withLoad = true` 时 `openWorkCount` 给 0、`openWorkBySource` 给空数组（在办来源由 G2-A 起各域登记）；`isRecommended` 标在最小实现会选中的那一位。并入分配池的留桩 |
| 员工详情 | 全做；`wecom.qrUrl` 恒为 `null`（上传二维码在 M2） |
| 角色 | 只有列表：8 行与启用中的成员。详情、默认配置、保存在 M2 |
| 分配端口 | `staff.pickNext(tx, pool, scopeKey)`：取该池里启用的成员中工号最小的一位，对他的员工行按锁序加共享锁并再核一次“启用中”；不看城市、不看当班、不读写游标。池里没人返回 `null`。池成员在 M1 只来自演示种子（W1-01a）。调用方必须在锁任何业务行之前调它，与正式实现同一约束 |

## 5. 不做什么

- 编辑、启用、禁用、移交、重置密码、重置第二因子、重新生成激活码、解除锁定、企业微信绑定、设置分配池、当班、员工计数、分组列表、分配池成员与游标、会话管理：都在 M2（G2-A）。
- 角色详情、默认配置、保存：G2-A。
- 轮询游标、按城市分配、改派记录：G2-A。本包不写 `assignment_cursor`、`assignment_history`。
- `staff` 的其余不变量（`staff.I1`–`I7`、`I9`、`I10`）：G2-A。其中 `staff.I2`（至少一名启用的超级管理员）在没引导过首位管理员的库上必然违规，不能在 M1 登记。
- 不改鉴权链、中间件与 `authz`；不加迁移；不改 `infra/ci/layers.json`、锁序常量。
