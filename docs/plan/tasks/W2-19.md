## 1. 目标

实现唯一消息页，商家可按分类看消息、单条/全部标已读并进入已有业务页；首页/我的入口展示真实未读数。
老板、店员、无门店上下文只看到后端允许的收件内容，切店/切用户不会带出旧消息或角标。
使用W2-18已有订阅封装/接线，在用户点击时发起授权并上报真实平台结果，不创建独立通知设置页。

## 4. 允许改动的目录

| 路径 | 可以做什么 |
| --- | --- |
| `apps/weapp/src/sub/service/messages/`（新增） | 唯一页、api/model/styles/测试与原生导航配置 |
| `apps/weapp/src/pages/{home,mine}/` | 仅消息入口/未读角标增量，不重写商城/账户 |
| `apps/weapp/src/stores/` | 仅消息上下文缓存/失效私有文件（新增），复用既有contextRev |
| `apps/weapp/src/pages.ts` | 仅本页implemented/workPackage，app.config从既有清单生成 |
| `apps/weapp/shots/message-{fixtures,scenes}.ts`（新增）及既有场景聚合 | 仅新增本页场景/固定数据，保留所有旧场景/外发守卫 |
| `docs/plan/pages.md`、本包状态、weapp README | 页面生成、样图与真机清单；无服务端生产改动 |

页面：`sub/service/messages/index`，分包sub/service，画板Messages；保留正式URL/里程碑，登记为W2-19、implemented=true。
接口：只消费m.message.list/summary/read/batchRead、m.notifySetting.list及W2-18订阅结果；不增加接口、schema或能力点。
表/状态机/事件/timer/x01/桩：无。本包只UI与请求，不能写DB或自造未读真相。
list默认all/limit20，tab按正式枚举，cursor不透明；触底累加按messageId去重，下拉刷新替换，不把hasMore=false当请求失败。
无X-Store-Id只看账号消息，有店走中央request当前上下文；contextRev变化废弃过期响应、清旧cursor/详情/未读，不手选可越权门店ID。
从后端summary/me聚合更新角标，单条/全读成功后重读或按响应更新，再校准summary；失败不永久减未读，不把列表长度当未读总数。
点击消息先按真实read接口处理，再按服务端目标与已落地路由进入；不可访问/已删除显示正式状态，不猜测未来客服/广告URL。
老板降为店员后ownerOnly不可见，店员不显示积分/金额字段；即便旧缓存存在也要清理，前端不能重造文案扩大接收范围。
通知设置作为本页已有操作区/弹层，不新增独立页；显示on/off/rejected/banned/unavailable，模板缺配不画授权成功。
订阅必须用户点击回调同步调用已有subscribe封装，point/slot取bootstrap；accept/reject/ban/filter原样上报，不把H5替身当微信真机授权。
全读按正式required幂等键，重试保留键；单读自然幂等按契约；401/403/429统一反馈，无批量后台无限重试。
默认system公告类V1.1不出页签；保留all/order/delivery/launch/plan_points/review/store/service，未来页签由后续包接。

## 5. 不做什么

- 不做独立通知设置/消息详情/公告页，不增加其他导航登记，不改后台消息面板。
- 不重写subscribe/track/request/context机制、共用组件/主题；缺构件另包提升。
- 不改services/API/contract、真实provider/模板配置，不能用客户端缓存代替成员权限。
- 不用H5截图声称小程序渲染/真机订阅已验，不发送真实通知或操作外部账号。
