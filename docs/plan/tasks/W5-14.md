## 1. 目标

交广告制作任务单页工作台，含队列/详情面板、指派、版本登记推送、查看证据与修改/取消入口。
0新增API/x01；详情/上传/取消弹层留本页，不另造后台广告详情路由。

| 页面key / route | 本包边界 |
| --- | --- |
| `delivery.ad_tasks` / `/delivery/ad-tasks` | 唯一新页，原queue-workbench骨架、同scope队列/summary与详情面板 |

| 消费operationId（不重复拥有API） | 页面行为 |
| --- | --- |
| `admin.ad.list`、`admin.ad.summary`、`admin.ad.get` | 实际页签/紧急排序/范围与需求、积分、关联工单、修改历史 |
| `admin.ad.assign` | 当前真实员工候选、在办量与指派结果，不写死“推荐”或固定0 |
| `admin.ad.return` | 当前动作下退回补充，原因必填、真实状态GET |
| `admin.ad.adVersion.create` | 上传已入库可用文件、段落/广告属性，登记实际新版本 |
| `admin.adVersion.push`、`admin.adVersion.markSent` | 推送版本与已有企业微信发送事实分别登记，不伪造送达 |
| `admin.ad.requestChange`、`admin.ad.remind` | 代录免费范围内修改、限频催办，超次不绕商家确认 |
| `admin.ad.cancelQuote`、`admin.ad.cancelRequest.create` | 服务端实际逐项退积分预览/申请，后续审批执行沿W5-13已有页 |
| `admin.staff.list`、`admin.staff.openWork.get` | W5-09接实的typed广告在办来源；候选/停用/范围准确 |
| `admin.file.create`、`admin.file.complete`、`admin.file.get` | 沿现有合法上传/入库状态，未就绪或拦截不登记版本 |

请求/响应从`@liyoxi/contract/types/admin`的operations推导，params/query/body依所属actual schema，不复制DTO。
积分冻结/扣减、免费次数、等待原因、预计完成与关联订单影响均由实际GET，不在UI重算。
候选来源与在办由W5-09接既有staff框架，不能造独立picker/恒零列表或改移交算法。
同意图原key贯穿超时/中央stepup重放；busy同步闩防双击，未知结果先读GET再决定恢复。
写前真实GET核当前adId/版本/权限/actions与当前scope，DTO未声明的lockVersion等字段不得造。
换广告、换范围、关面板/退出均废弃旧确认与上传意图，迟到文件/GET不能绑定另一广告。
同文件完成/体检/入库按实际返回，失败可恢复但不伪造ready；登记后GET核版本/状态/历史。
推送和“已发送”分开；下载地址现签，不在错误、埋点、截图日志暴露签名或员工凭据。
取消申请与真正执行退积分分开，链接只指向实际已合的取消审批处理面板。

## 5. 不做什么

- 不新增广告详情页、取消页、客户资料或在办管理页，不将弹层计新页。
- 不改广告计费/免费次数/时限/账本，不能前端判断“已退积分”代替执行GET。
- 不扩大素材/文件权限，不让未入库/别广告/别scope文件通过，不能复用过期签名。
- 不绕中央stepup、版本/creator/当前动作守卫，不为截图放宽超时或原断言。
- 不接真实企业微信、云或生产素材，不把登记“已发送”冒称外部送达已验。
