## 1. 目标

交小程序素材库、上传、详情、上传中心4页；0新API/x01，回补2项前端桩。
页面只消费W3-14/15实际typed DTO和actions；理解进度/计数/采用状态不由端上计算成业务真值。

| 页面key / route | 结构与交互 |
| --- | --- |
| `sub/asset/lib/index` | StoreAssetCard/Summary，类型/状态/标签/本人筛选、游标分页 |
| `sub/asset/upload/index` | type/fileIds/textBody/tags/note/demand；真实分类登记/上传完成后create |
| `sub/asset/detail/index` | StoreAssetDetail，全文/文件/标签/使用记录、反馈与补交肖像授权 |
| `sub/asset/uploader/index` | 大文件上传任务、进度/失败/取消/续传，保留实际上传上下文 |

页面消费operationId如下；仅消费者，不重新拥有接口/服务schema。

| operationId | 用途 |
| --- | --- |
| `m.assetDemand.list` | 需求列表与上传时关联 |
| `m.storeAsset.list` | 稳定列表与参考选择筛选 |
| `m.storeAsset.summary` | 类型/整理中/本人采用数，首页clerk摘要 |
| `m.storeAsset.get` | 详情、当前可读文件与洞察 |
| `m.storeAsset.create` | 真实文件stored后登记素材，同意图幂等key |
| `m.storeAsset.feedback.create` | 标签错误反馈，不直接改机器/人工标签 |
| `m.storeAsset.portraitAuth.create` | 补授权材料；不得把补交显示为已确认 |
| `m.file.create`、`m.file.complete` | 实际分类/签名上传链；不先写素材再伪造文件 |

回补m3-weapp-clerk-assets：首页需求/我上传/采用摘要接真实API，只改本域入口区域。
回补m3-weapp-order-reference-assets：确认订购参考区域按真实isSelectableAsReference选IDs，详情真实回显。
采用与参考不同：need_portrait_auth可参考，未确认前不可采用；UI不创造额外业务放行。
W3-14负责后端reference端口，页面不修改order quote/create计价和下单锁序。
同页详情签名每次重新取；expired/read失败走明确重取/错误，不缓存永久URL。
切店/ctxRev、角色变化、卸载、迟到成功/错误全部丢弃旧结果；同步busy锁与同意图key保留。
上传任务需绑定本轮主体/门店/文件；切店或删除失败任务不得把旧文件交给新店。
微信文件/相册/隐私依已有平台私有入口；H5只能近似，不声称真续传/真机授权。

## 5. 不做什么

- 不改lib/request、公共构件/既有平台wrapper、冻结metadata、购买/计价规则。
- 不实现后台复核、识别算法、视频压缩服务、匿名/portal、ZIP或采用记账。
- 不把promoting当stored，不上传后直接跳过分类/complete，不绕内容block/肖像守卫。
- 不写色值/前端推算权限、采用数/整理状态，不删旧clerk/异步/截图断言。
- 不将H5平台空转或假metadata写成生产识别、真机续传已验。
