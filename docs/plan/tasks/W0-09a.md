## 1. 目标

把“系统自己动”的名字与全库枚举收进 `@liyoxi/contract`，成为代码侧唯一来源。内核各件（W0-07 的操作人枚举，W0-15 事件，W0-17 定时器，W0-18 配置）只等本包。每个 x01 条目带归属里程碑，里程碑退出时据此核对“该落地的都落地了”。

“x01”= `docs/api/x01-events-jobs.md`；“NN 分组”= `docs/data-model/` 下的分组文档。

## 9. 交付与收尾

- 一个工作包一个 PR；超过可评审体量（计划 第 5.3 节“粒度”行）即拆成 a、b 两个可独立合并的 PR，并记一条计划变更。默认拆法：a = x01 名称登记、里程碑与 `x01-map.md`；b = 枚举、开关键与参数键。
- PR 描述按 `.github/pull_request_template.md` 填全。
- 同 PR 更新 `docs/plan/status/W0-09a.md`。
- 先交付可读的中间成果：先出 `x01-map.md` 与操作人枚举。遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。合并后改任何条目的归属，要在 `docs/plan/changes/` 记一条（计划 第 5.7 节）。

## 10. 实现要点与顺序

1. 操作人三个枚举与 15 个共用枚举先做，W0-07 最先要用。
2. x01 名称登记：由 `frag/x01-events-jobs.json` 与 x01 第 4.4–4.6 节一次生成初稿，之后契约为准。每项带所属模块；订阅者与定时器带“关键类”；事件带前缀、聚合、状态（发出 / 不发 / 预留）。
3. 按计划 第 8.4 节逐项写 `milestone`。定时器按“kind × 主体”一行一个归属。预留的 `reports.onMonthClosed` 归 M7。
4. 生成 `docs/plan/x01-map.md`；写 `registry:check`。
5. 全库枚举：从已迁移的库读出全部取值集合形态的 CHECK，按 `catalogue.json` 的表 → 模块对应分文件声明，绑定“表.列”；取值相同且语义相同的列共用一个枚举。写 `enums:check`。
6. 对账有差异时：x01 的正文与 `frag` 不一致，以正文为准改 `frag`；分组文档 第 3 节与库不一致，以库为准改分组文档。改完跑 `python3 tools/api-check/check.py` 与 `python3 tools/schema-check/check.py`。库本身有错，停下报告，不在本包改库。
7. 开关登记与参数键清单；接 CI 与反例。
