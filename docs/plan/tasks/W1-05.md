## 1. 目标

- 小程序能走通“打开 → 游客 → 登录 → 我的 → 切换门店 → 退出”：三个路由、两个弹层，外加冷启动与几个恢复动作的接线。
- 文案约束有一道自动检查：登录相关文案出现“微信”，PR 过不了。

## 5. 不做什么

- 登录的真实形态（手机号组件、实时验证、额度不足的上报）与自建短信登录：M2（G2-B）。
- 设置、账号与安全、消息、成员、邀请与加入、门店管理与新增门店：M2。首页、商城、选剧单：W1-18。建档首页与“开始建档”触发的建主体：W1-09。
- 不改通用组件（硬性规则 27：要改走单独的构件 PR）、请求层与 NutUI 的入口。
- 订阅结果、埋点、错误上报的服务端调用不接（G2-C 等）：`track` 照调，现在空转。
- 文案扫描第一版只收“微信”一条规则，范围是登录相关的页面与登录页会显示的错误默认文案（别处的“已登录的微信”“企业微信”不归这条管）；“热播”“热度”“为你推荐”等由用到的页面包加行，后台与下载页以后再扫。
- 后端不动：接口有缺陷另开 `fix/*`。
