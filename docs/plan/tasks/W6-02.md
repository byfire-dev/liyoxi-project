补齐可编辑发布清单和上线日历/逾期读侧，确保后台、小程序与电脑端读取同一当前发布文本；撤销核验沿真实审批及履约状态收尾。

机制与移交：

- 发布清单补逐集内容、版本守卫、表格导入与整份替换；验证集数/序号、字段限制和失败时零部分写入。
- 推包前读当前编辑稿，推包后按原规则同步生效 release.publish_list_text；GET 不创建清单或文件。
- 上线日历、任务列表及summary使用相同过滤、数据范围和日期口径；完整展示分批回填、部分上线与逾期原因。
- 撤销核验通过必须撤销对应上线事实、收尾关联审批/巡检并重算交付；复用已合publish/delivery原语，不改审批执行框架。
- 接入 notify 的 R2 上线提醒与 R6 员工逾期提醒真实查询；保持工作日/次日、收件人与节点去重，不留给M7。
- portal发布清单处理器必须在W6-05实际鉴权后挂载，严格按会话门店过滤；复制读取不写下载记录。
- 回补delivery.I16与预填桩；三端字段一致，不能把M1只读预填当完整可编辑清单。
- 既有admin.deliveryRelease.get与后台工单详情只窄补所需投影，既有API归属不变；页面由08/11交付。
