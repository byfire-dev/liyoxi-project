## 1. 目标

交付上线日历、逾期跟踪两页；在既有工单详情接完整发布清单、预打包与方案全账号改选。
拥有接口：无；0新增x01。新页2、旧页2，评审页面总数4，不能将旧页增量漏出工作量。

| 页面key / route | 唯一边界 |
| --- | --- |
| publish.calendar / /publish/calendar | 新页；按实际月历数据展示上线安排及跳转 |
| publish.overdue / /publish/overdue | 新页；实际任务list/summary，范围、状态与逾期事实一致 |
| /delivery/tickets/$ticketNo | 旧页；清单导入/替换、预打包、方案改选门店全部可用发布账号 |
| /publish/verify | 旧页；撤销已核验上线记录，重读真实核验/任务状态 |

| 消费operationId（不重复拥有API） | 实际用途 |
| --- | --- |
| admin.launchCalendar.get；admin.launchTask.list/summary | 日历与逾期筛选，不从分页结果推总量 |
| admin.deliveryTicket.publishList.get/import/replace | 清单元数据、逐集行、校验问题与替换后的正式版本 |
| admin.channelAccount.list | 按实际门店取全部账号，拒绝跨店/停用/不适用平台的候选 |
| admin.deliveryRelease.pack | 显式打包及失败后重试，不让状态轮询隐式重建 |
| admin.launchSubmission.revoke | 当前角色/版本/原因守卫下撤销核验，结果以GET为准 |
| admin.deliveryPlan.get / admin.deliveryPlan.draft.replace / admin.deliveryPlan.push | 沿W5-13已合typed读/草稿替换/推送操作，按当前schema核对；不另造update接口 |

清单导入与编辑沿服务端逐集校验；保留空值、标题/话题/简介及AI标签，不拼假完整状态。
账号改选由服务端候选决定；原订单账号列表不再作为唯一来源，不改变后端归属或账号审核规则。
计划日期用Asia/Shanghai日期值，月界与节假日展示消费实际日历，不在浏览器改使用期。
写动作复用中央step-up、同意图幂等键与同步提交闩；冲突后重读并要求重新确认。
只消费后端声明的actions/版本字段；没有lockVersion的DTO不能擅加。
换任务/门店、关详情后废弃旧查询及导入意图；迟到结果不能覆盖另一个工单。
ZIP building/failed/ready分别展示；原包与补发包区分，不拿过期签名作持久状态。
本包唯一回补m6-admin-plan-channel-selection；清单/ZIP的后端桩由W6-02/07关闭，不能双认。
共享ticket-detail既有取消/暂停/补发/授权入口保留；本包不接管其业务owner。
