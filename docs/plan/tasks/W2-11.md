## 1. 目标

扩展已经落地的档案、资质审核与指派：补 change/new_store 轮次、终局驳回、联络短信、后台事实与跟进。
初次资质审核的既有 update/submit/approve/reject 接口仅增量，不重复统计新增接口或重写 M1 守卫。
要落地的接口（本包唯一新增归属）：

| operationId | 结构与业务边界 |

| `m.qualificationDoc.downloadUrls` | 本人主体/门店文件现签；资格、fileId 与引用复核 |

状态链：实体 verification 与门店 qualification，按初次、新店、变更原链迁移；资料草稿阶段按已接管模型派生。
事件：x01 既有 `store.qualification.*`、`store.qualification_change.*`、指派/跟进事件，系统重复信用代码驳回用真实 system actor。
x01 本包唯一实装 `profile.onQualificationApproved` 与 `profile.onTenantLifecycle`；重复/乱序处理按当前轮次与历史事实守卫。
回补 `m2-profile-admin-facts.md`、`m2-profile-qualification-rounds.md`，不得把 M3 OCR 或 M5 广告/取消执行计入完成。
W2-10 拥有成员摘要桩的回补；本包消费其真实成员源，保留 ad/assets/support 的所属里程碑留桩。

## 5. 不做什么

不提前 OCR、素材理解/重处理、M5 广告和售后授权，不伪造识别 confidence 或素材在办量。
不把后台代改档案作为绕过资质轮次的通道；已认证主体的变更保留前一合法值，失败不得覆盖。
不放宽自审、override、再验证、业务 scope、lockVersion 与字段回显；具体规则沿现有 a03 元数据。
不修改 nullable 字段为假 0/空串，不借客户端 file/account/store ID 读取外主体内容。
不改 31 模块、同层白名单、DDL/USCC 索引、全局锁序和冻结审批/裁剪构件。
不删除旧 clerk/权限/并发断言，不让不变量过滤真实重复主体或存量资质档案。

## 6. 允许新增的依赖

无 npm 依赖。profile→approval/tenant/media/identity 仅用既有公开出口；profile→staff 不新增同步白名单。

`Promise<void|number>` 旧同步端口兼容保留；只对真实拥有者返回的计数宣称已同步，rollback 包含分配计数。

作者本地中文提交、五节正文交调度；sole 独立复审与 CI 收口，不追加第二正式轮。
