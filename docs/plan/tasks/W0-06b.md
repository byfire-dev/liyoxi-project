## 1. 目标

表结构被代码接管之后不再漂移：每个 PR 在空库跑完全部迁移，再与入库的结构快照对账；分区、迁移写法、分组文档、已冻结的草稿各有一道检查。之后的结构变更包照着这些门禁改迁移、快照与分组文档。

产出：结构快照与五个检查脚本；改造后的 schema-check；草稿冻结守卫；六个 `db:*` 命令；CI 步骤与反例。路径见第 4 节。

## 9. 交付与收尾

- 一个工作包一个 PR；超过可评审体量（计划 第 5.3 节“粒度”行）即拆 a、b，并记一条计划变更。拆法：a 是快照、约束比对、分区断言；b 是迁移规范、schema-check 改造、冻结守卫。
- PR 描述按 `.github/pull_request_template.md` 填全。同 PR 更新 `docs/plan/status/W0-06b.md`。
- 先交付可读的中间成果（先出快照文件）；遇到阻塞即停，把原因写进状态文件并报告。不自行合并。

## 10. 实现要点与顺序

1. 先读 W0-06a 的 ADR。它与本任务书有出入时，以 ADR 为准，在 PR 描述“偏差”里写明。
2. 快照：经 `psql` 读系统目录，写成六节，稳定排序。规范化只做一件事：去掉分区子表及其触发器。
3. `db:snapshot:check`：建临时库 → `migrate deploy` → 重新生成 → 与入库的比 → 删库。约束比对、分区断言用同一个库。
4. 迁移规范：D7 第 8.3 节第 5 条的四类语句与两种自动放行。首版迁移里的 `RENAME`、`DROP TABLE` 已带标记（W0-05）。
5. schema-check 改造：默认流程改为连迁移后的库比字段表；旧流程留在 `--from-draft`。改 README。
6. 冻结守卫：登记哈希，比对。
7. 逐道门禁加反例；接 CI；在分类规则里登记：快照随新迁移一起变算“只增”，单独变算“放松”。回写文档。
