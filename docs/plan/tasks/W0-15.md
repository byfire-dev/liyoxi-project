## 1. 目标

- 业务事务里能发出站事件：校验载荷、填信封、按去重键去重。
- 事件按已登记的订阅者展开成投递行。
- 使用方：W0-16（状态迁移发事件）、W0-23（中继循环调本包的展开函数，消费时按名取订阅者）、W0-30；M1 起各域。

| # | 规定 | 出处 |
| --- | --- | --- |
| 1 | `emit` 的第一个参数是事务句柄；事件与业务写在同一事务 | 01 第 5、7.1 节 |
| 2 | 信封列由 `emit` 统一填：事件类型、聚合类型与 id、主体、门店、操作人三列、`actor_role`、`client_platform`、`client_version`、`request_id`、`occurred_at`、`dedupe_key`。载荷里不重复 | x01 第 2.3 节 |
| 3 | `id` 是应用生成的 UUID v7；`occurred_at` 取注入的时钟；`created_at` 用库默认值 | 01 分组 第 2.3 节 |
| 4 | 定时器、订阅者、回调、周期任务触发的事件：`actor_type = system`，`actor_id` 与 `client` 为空 | x01 第 2.3 节 |
| 5 | 事件类型：小写点分 2–3 段，全长不超过 64，必须在契约的事件目录里且状态是“发出”。聚合类型取最终表名，必须在契约登记表里；可与聚合 id 同为空 | x01 第 2.1 节；01 分组 第 2.3 节 |
| 6 | 载荷是 `{ v: 数字, … }`，按事件类型的 schema 校验；只放 id、业务日期、关键数字与枚举；聚合行的 id 在载荷里再写一遍 | x01 第 2.3 节 P1–P3 |
| 7 | 载荷不得出现：明文手机号、openid、证照号、银行账号、姓名、地址、验证码、令牌、对象存储的键与签名地址、自由文本 | x01 第 2.3 节 P5 |
| 8 | 去重键：`INSERT … ON CONFLICT (dedupe_key) DO NOTHING`。没插入就是该事实已发过：跳过、不报错，业务事务照常提交。不填时为空 | x01 第 2.3 节；01 分组 第 2.3 节 |
| 9 | `tmr:{定时器去重键}` 只用于一次执行只发一条事件的处理器；可能发多条的不套 | x01 第 2.3 节 |
| 10 | 订阅者名匹配 `^[A-Za-z][A-Za-z0-9_.]{0,63}$`，写法 `<模块>.on<事实>`；不含冒号与连字符 | x01 第 2.5 节；01 分组 第 2.4 节 |
| 11 | 展开：取 `published_at IS NULL` 的事件，`ORDER BY seq LIMIT 200 FOR UPDATE SKIP LOCKED`；每个订阅者 `INSERT … ON CONFLICT DO NOTHING` 一行 `pending`；再把 `published_at` 从空写一次。纯数据库事务，不碰 Redis；这里的时间用数据库时间 | 01 分组 第 2、2.3、2.4 节；D3 第 20.2 节 |
| 12 | `outbox_event` 只许插入与写一次 `published_at`；其余列不可改，行不可删 | 01 分组 第 2.3 节 |
| 13 | 兼容：新事件、新订阅者先登记，下一版才写出；订阅者改名等于新订阅者 | x01 第 6 节 V4、V7 |
| 14 | `events.I8`：没有超过 5 分钟未展开的事件；没有超过 15 分钟仍待处理且不在退避中的投递行。P2、`full`、不自愈 | 01 分组 第 2.3、2.4 节 |

## 10. 实现要点与顺序

1. 先读 W0-07b 已合并的“订阅者”注册接口与 W0-09a 的事件目录、订阅者、聚合类型登记；名字以合并后的代码为准。
2. 契约：`calendar.imported` 的载荷 schema（01 分组 第 4 节已定）；按事件类型取 schema 的入口。
3. `emit(tx, …)`：校验事件类型、聚合类型、载荷 → 从身份上下文填信封 → 带去重的插入；返回是否真的写入。原生 SQL 只写在本模块的仓储文件里。
4. 订阅者：用 W0-07b 定的注册接口；本包补对照契约的校验与“按事件类型取订阅者”的查询。
5. 展开分两层：收事务句柄的服务函数；自己开事务的用例入口（供 W0-23 的中继循环调用）。展开函数归本包，W0-23 只调用、不重写。
6. `events.I8` 的两段查询与聚合类型自检；在 `register.ts` 登记不变量项。调度在 W0-24，本包只登记并直接调函数测试。
7. 测试连真库；并发测试用多条独立连接。
