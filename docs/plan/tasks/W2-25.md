## 1. 目标

- 交出把那台阿里云服务器变成预发所需的全部脚本与配置：节点初始化、桶配置、六个容器的 Compose、宿主机 nginx 的三个站点、systemd 单元、密钥文件的清单与齐备检查、第四个镜像、构建并推送镜像与“合并即部署”的流水线。
- 这些东西先在本机照原样演练通过（`pnpm stg:rehearse`），PR 合并不等服务器。真正上服务器的每一步由业主执行，或业主在场逐步确认后由调度会话执行（ADR-041 第 4.10 节）；本包的会话不登录服务器、不接触任何密钥的值。
- 使用方：W2-26（发布编排接着本包的节点步骤往下做）、W2-27、W2-29；G3-A、G4-A 的预发联调。

## 5. 不做什么

- 不登录服务器，不读、不要、不转手任何密钥、口令、证书与它们所在的路径；不读参考工程留在服务器上的任何东西。脚本里出现的只有密钥文件的名字。
- 不改宿主机 nginx 已有的站点（公司官网、`api.timavia.com`），不删参考工程遗留的容器、卷与导出文件；初始化脚本遇到它们只报告，不处置。
- 不做完整的发布编排、回滚、持续探测、上传体验版（W2-26）；不做日志统计、错误上报、告警接通（W2-27）。
- 不建云日志、凭据管理、远程命令通道、负载均衡（随生产）；不做生产的任何东西。
- 不改 `apps/`、`packages/` 的业务与装配代码。`loadEnv` 缺的键由用到它的代码包补，本包只给值。
- 不把“合并即部署”默认打开：流水线受仓库变量 `STG_DEPLOY_ENABLED` 控制，缺省不跑，由业主同意一次后打开。

## 7. 验收

都在本机与 CI 上验，不需要服务器。服务器上的验证写在第 8 节。

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 本机演练 | `pnpm stg:rehearse` | 照 `node.yml` 起六个容器（密钥文件用演练值现造在临时目录，端口换成不撞共享实例的），依次跑节点步骤 `pull`（本地镜像时跳过）、`check-env`、`migrate`、`up`、`status`、`verify-db`，再跑 W1-22 的冒烟，全过；跑完删掉容器、卷与临时目录 |
| 2 | 容器的形态 | 同上（演练里读 `docker inspect`） | 六个容器的内存上限等于 ADR-041 第 4.2 节的表（mediatool 256MB、内存加交换合计 1GB）；只有 gateway 发布端口且只绑回环 8080；库与 Redis 不发布端口；网络是固定网段；重启策略 `no`；日志驱动 `json-file` 带轮转；`docker inspect` 的输出里搜不到任何演练密钥的值；api 只挂得到自己的那几项密钥，mediatool 一项都没有 |
| 3 | 库 | 演练里的 `verify-db` | 库名 `liyoxi`；`btree_gist`、`pg_trgm` 已装；`pnpm db:verify-grants --database liyoxi` 的同一份核对通过（登录账号是成员、两个角色不可登录）；应用连库用的是应用登录账号，不是属主 |
| 4 | Redis | 演练里读 `CONFIG GET` | `maxmemory-policy` 是 `noeviction`；AOF 开着；`maxmemory` 64MB |
| 5 | 密钥齐备检查 | `bash infra/deploy/check-secrets.sh --dir <临时目录>`（用例在 `infra/deploy/test/`） | 少一个文件、权限不是 0400、文件为空，各自非 0 退出并只报文件名；输出里没有文件内容 |
| 6 | 节点初始化脚本 | `pnpm test`（`infra` 项目，真 bash 加桩命令） | `node-init.sh --dry-run` 只打印不执行；重复执行不出错；发现 80、443 之外的端口冲突、发现参考工程的进程在跑，各自停下并说明；生成的 `authorized_keys` 一行带限定命令、无终端、无转发 |
| 7 | 宿主机 nginx 模板 | 演练里用 `nginx:stable-alpine` 容器对渲染后的三个站点跑 `nginx -t` | 通过；模板里没有 `add_header` 安全头；`client_max_body_size` 不小于 2MB；`proxy_set_header Host $host`；`X-Forwarded-For` 是覆盖写 |
| 8 | 桶配置 | `pnpm stg:buckets -- --check --offline`（桩掉云命令行） | 对夹具里的“现状”能报出差异；不带 `--apply` 不改任何东西；`buckets.json` 里四个预发桶的版本控制与生命周期与 D5 第 3.1、3.5 节一致，`secure` 桶的 `ci/` 前缀 7 天删除 |
| 9 | 四个镜像与流水线 | `images.yml` 在 PR 上的运行（不推送）；`pnpm test` 里的工作流清单用例 | 四个镜像都能构建；server 镜像的 `pg_dump` 主版本断言在；`deploy-stg.yml` 在 `STG_DEPLOY_ENABLED` 不为 `true` 时整段跳过；两份工作流都没有把密文打印出来的步骤 |
| 10 | 已有门禁 | `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test && node infra/ci/classify-gate-changes.mjs --base origin/main` | 退出码 0；门禁改动只有只增类 |

要登记的留桩：无。没到位的外部条件记外部验证台账，不记留桩。

要同 PR 回写的文档：`CLAUDE.md` 第 9 节；`infra/ci/README.md` 第 1 节；运行手册与平台配置核对表的对应行；四份外部验证文件。

## 8. 需要业主做的事

下表每一步都是“业主执行，或业主在场逐步确认后由调度会话执行”。步骤、每步的回退办法与判据由本包写在 `infra/bootstrap/README.md`，这里只列要点。

| 时点 | 业主操作 | 判据 |
| --- | --- | --- |
| 开工前 | 无 | — |
| 合并前 | 无 | — |
| 合并后，上服务器之前 | 定镜像仓库用哪家并建好（建议 6）；定补 3（AppSecret 与上传密钥要不要重置）、补 4（谁登录）；加三条预发域名的 DNS；生成发布用的密钥对，私钥与镜像仓库凭证录入 CI 密文；开 `lyx-stg-secure` 桶（没开不挡，见第 10 节第 5 项） | `infra/bootstrap/checklist.md` 逐项勾完 |
| 首次起环境 | 核对参考工程没有复活、8080 空闲 → `node-init.sh --dry-run` 看一遍再去掉参数执行 → 把各项密钥写进密钥文件（只有业主做） → `db-init.sh` → 手动触发一次 `images.yml` 推镜像 → 节点步骤从 `pull` 到 `verify-db` 逐步跑 → 签证书、装三个站点文件，`nginx -t` 通过后重载（会波及公司官网，先确认） | 三个预发域名的 `/healthz` 从公网回 200；`docker inspect` 里搜不到密钥；整机重启后六个容器按顺序自己起来（D7 第 10.6 节第 17 项） |
| 首次起环境之后 | 从公网带一个随机请求编号请求一次，在 gateway 与 api 的访问日志里查这一条 | 记下的客户端 IP 是请求方的公网 IP，不是网桥地址；实测的网段写进模板与 `TRUSTED_PROXY_CIDRS`（V6 的预发部分） |
| 启用合并即部署 | 把仓库变量 `STG_DEPLOY_ENABLED` 设为 `true`（同意一次） | 下一次合并后预发的版本号变了，冒烟通过 |

## 9. 交付与收尾

- 体量约 900 行脚本与配置，超过一个 PR 好审的量，按两步交，不改编号：a = `node.yml`、`stg.env`、节点步骤、密钥检查、systemd、nginx 模板、演练（验收 1–7）；b = 桶配置、`weapp-uploader` 镜像、两份工作流（验收 8、9）。a 合并后 W2-26 即可开工。
- 同 PR 把 `docs/plan/status/W2-25.md` 写成“完成”；“没有验的”一栏如实写：服务器上的各步都还没有做。不推送、不开 PR、不合并。
