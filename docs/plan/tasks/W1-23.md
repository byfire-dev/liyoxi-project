## 9. 交付与收尾

- 体量：约 64 份任务书，W0-31 写 32 份用了七个会话并行。本包按两步交，不改编号：
  - a：拆包表（三个里程碑一次定完）、计划回写、全部状态文件、M2 的 25 份任务书、环境包的核对。合并后 M2 与 G2-0 即可开工。
  - b：M3 的 19 份与 M4 的 20 份任务书。它们只等 G2-0 两包，赶在那两包合并前交出即可。
- 先落拆包表再写任务书：表是第一个提交，调度会话据它把任务书按组派给几个会话并行写；各会话只写自己那几份，最后由一个会话统一提交。
- 同 PR 把 `docs/plan/status/W1-23.md` 写成“完成”，“偏差”里列对计划做的修正；不推送、不开 PR、不合并。

## 10. 拆包的做法与默认（本任务书定）

| # | 事 | 做法 |
| --- | --- | --- |
| 1 | 编号 | `W2-NN`、`W3-NN`、`W4-NN`，两位数字，拆出或新增的用 a、b 后缀。不要用带字母的段（如 `W2-D1`）：`infra/ci/status-summary.mjs` 只认 `W<数字>-<数字>[a-z]`。M2 里 W2-25–W2-29 已占用（环境包，个位数对应计划 G2-D 行的 ⑤–⑨）。建议：G2-0 用 W2-01、02；G2-A 用 03–08；G2-B 用 09–16；G2-C 用 17–19；G2-D 的 ①–④ 用 21–24；M2 合流 W2-30；交 G7-A 的拆包 PR W2-31；包数对不上时空号或加后缀，不挪已有编号 |
