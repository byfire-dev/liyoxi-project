## 1. 目标

在既有商家详情/资质复核增加素材页签与人工复核，0新增API/页/x01/桩。
计划G3-C“后台复核页”是既有页面增量，不能静默添一条新菜单或改变M3 11页总数。
当前M1资质review与M2 W2-15商家详情入口以actual已合文件为准，素材view另置本域私有子目录。

| 消费operationId | 页面行为 / 结构 |
| --- | --- |
| `admin.storeAsset.list` | StoreAssetCard，待整理/已采用/类型筛选与稳定分页 |
| `admin.storeAsset.summary` | 角标/页签数量来自服务端 |
| `admin.storeAsset.get` | StoreAssetDetail，识别全文/多文件/历史使用记录与现签 |
| `admin.storeAsset.create` | 代传stored文件后登记素材；staff上传快照 |
| `admin.storeAsset.review` | lockVersion、标签/用途/时效/可用性，版本冲突重新读后再编辑 |
| `admin.storeAsset.reprocess` | 重新识别由后端actions决定，保留旧洞察 |
| `admin.storeAsset.delete` | 原因确认与soft delete，不直接清对象 |
| `admin.storeAsset.portraitAuth.create` | 代传分类portrait_auth材料 |
| `admin.storeAsset.confirmPortraitAuth` | 材料齐全才确认；补交后状态不自动变ready |
| `admin.assetDemand.list` | 门店需求、已收到数与真实状态 |
| `admin.assetDemand.create` | 发起拍摄需求、完成日期和通知对象 |
| `admin.assetDemand.cancel`、`admin.assetDemand.complete` | 按版本/actions撤销或完成，失败不乐观假更新 |

所有列表/详情遵循own/all范围；不能前端隐藏按钮代替服务授权，不带外店ID拼接签名请求。
机器内容/人脸提示与人工用途/时效/可用性分开展示，后端没结果时显示明确未识别/人工整理。
补拍/肖像提醒依实际事件/状态，不声称实时消息已送达；识别失败可复核，不把机器推断当授权。
人工编辑基于所见lockVersion，双击同步锁、同意图幂等key、确认锁内结果后回读。
分页/筛选/换商家/切页/卸载/权限变化均使旧请求失效，旧finally不能清新锁。
现签文件到期或失效只重取实际详情；不本地拼storageURL，任意文件名/备注按普通文本渲染。
材料上传先分类登记→上传→complete/stored，再提业务；失败只清本轮临时记录，不删共享对象。

## 5. 不做什么

- 不改共享Table、Uploader、Form/Query框架、权限矩阵规则、服务/路由schema或冻结metadata。
- 不新增后台“素材复核”独立菜单/页面，不修改资质默认审核/拒绝/放行算法。
- 不自动采用、代老板同意肖像授权，不静态填计数/识别/通知状态。
- 不删旧loading/迟到响应/权限断言，不forceclick、不靠加timeout把竞态变绿。
- 不直连DB/storage，不用fake传签名充作真实API返回，不碰真实材料或密钥。
