## 1. 目标

两端页面开工前，把“取色、取字号、取图标、取状态色、写时间与脱敏”这几件事各收成一处来源：样式变量与后台主题由 `design/tokens.json` 生成；图标成一套有名字的图标集；状态与颜色的对应是一份常量；页面里写色值会被检查拦下。W0-27a、W0-28 直接等它。

“规范”= `design/design-spec.md`。设计变量与图标放 `packages/shared`，走子路径导出，不新增包（计划 第 5.1 节）。

## 2. 依据

| 文件 第 N 节 | 取什么 |
| --- | --- |
| `design/tokens.json`；`design/README.md` | 样式变量的唯一来源，现有 185 个，分 `shared`、`merchant`、`admin` 三段。两端的样式变量与主题由它生成；组件级规格仍看规范 |
| 规范 第 0 节 | 优先级：平台约束与业务确认 ＞ 规范 ＞ 原型源码 ＞ 截图。颜色、字号、尺寸按规范取值，不照抄源码里的零散数值 |
| 规范 第 1 节 | 颜色变量名与 tokens.json 一致。`#C4501B` 只作填充与图标色，不作文字色；橙色文字用 `#A63F12`。五种状态色加后台紫色，各有文字色与浅底。第 1.6 节列的颜色不进变量，写在各自组件里 |
| 规范 第 2、3 节 | 字体栈三种；两端字号表；字重；数字加 `tabular-nums`。间距阶梯十档；两端圆角档位；描边；后台五种阴影 |
| 规范 第 4.1 节 | 小程序 `designWidth` 设 375，原型的 px 数值原样写进样式文件，不乘换算系数。状态色用类名修饰符 `--success`、`--info`、`--warning`、`--danger`、`--neutral`，与样式变量同名 |
| 规范 第 5.4 节的全局主题表 | Ant Design 全局主题逐项取值。`colorTextBase` 与 `colorText` 都要设；全局字号 14，不设成 13；衬线字体不进主题，另设一个样式变量。组件级要点不在本包 |
| 规范 第 6 节（含第 13 节的裁决） | 6.2 的状态取色表是规范性的：按业务对象、状态、端取色，同一状态两端可以不同色；★ 的 9 处已裁决；表里没有的状态按 6.1 的方法判断，超时与逾期一律红。6.3 的叫法：两端对同一状态的叫法可以不同 |
| 规范 第 7 节 | 时间默认 `MM-DD HH:mm`；跨年或存档用 `YYYY-MM-DD HH:mm`；有效期只写日期；句中的日期数字两侧留空格；区间用“至”；当日截止写 24:00；当天写“今天 HH:mm”，一分钟内写“刚刚”；时长 `mm:ss` 两位分钟。脱敏七种：手机号、姓名、统一社会信用代码、邮箱、座机、银行账号、许可证编号 |
| 规范 第 9 节；`design/analysis/patterns.md` 第 6 节 | 图标约 100 个，都是原型源码里的内联 SVG：画布 24 × 24，不填充，圆头圆角，颜色跟随文字色；线宽照原型原样保留（多数 1.8；返回、关闭、小箭头与后台 16px 及以下为 2；小尺寸对勾 2.4）。抽成有名字的图标集，两端共用。不换用 NutUI 或 Ant Design 自带图标。第 9.2 节的封面规格属组件，本包只出其中的圆角变量 |
| D4 第 9.3 节 | 脱敏纯函数放 shared，前后端共用规则，由后端执行。另有一种：IP 隐去第三段 |
| D7 第 2.5 节；第 4.2 节 | 样式变量前缀 `$lyx-*`，mixin 前缀 `lyx-*`。小程序图标用 CSS mask，不用图标字体 |
| 02 第 5.4 节；D7 第 2.2 节 D1、D6 | shared 不依赖 React，不 import `node:*`；小程序只引纯子路径 |
| 计划 第 5.7 节“生成物”行；第 10.1 节“页面”行 | 生成物对账：重新生成后 `git diff --exit-code`。页面不写色值与状态色 |

## 5. 不做什么

- 不写任何组件：小程序的 `Icon`、状态标签、封面占位、mixin 在 W0-27a、W0-27b；后台的 `StatusTag`、图标 React 组件、Ant Design 组件级覆盖在 W0-28。
- 不做原生标签栏的位图、品牌字图片（W0-27a）；不做衬线字体的自托管与分片（W0-28）。
- 不做金额、积分、增减号的格式化（W0-11）；不写库里的脱敏列（W0-14）。
- 不接“状态字典键与契约枚举同名”的检查（W0-30）。
- 不改 `design/` 下的任何文件。发现 tokens.json 与规范不一致：停下报告，写进状态文件“偏差”。
- 不改 `apps/`、`packages/contract`、根 lint 配置里已有的规则、`infra/ci/layers.json`。
- 生成物之外的源文件里不写色值：字典只写色调名，不写十六进制。

## 9. 交付与收尾

- 一个工作包一个 PR；超过可评审体量（计划 第 5.3 节“粒度”行）即拆成 a、b 两个可独立合并的 PR，并记一条计划变更。默认拆法：a = 变量、主题、图标与两项检查；b = 状态色调字典、格式化与脱敏。
- PR 描述按 `.github/pull_request_template.md` 填全；借用清单写“源路径@f1361e3 → 目标路径”。
- 同 PR 更新 `docs/plan/status/W0-26.md`。
- 先交付可读的中间成果：先出生成的变量与预览页。遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。W0-11 并行改同一个 `package.json` 的 `exports`：各只加自己的行，后合并的一方变基。

## 10. 实现要点与顺序

1. 生成脚本：tokens.json → 两端 scss 变量、TS 常量、Ant Design 主题对象。输出稳定、带“生成物，勿手改”的文件头。
2. 图标：从 `design/prototype/merchant/src/` 与 `admin/src/` 的内联 SVG 抽取，去重、命名，存成图标源；胶囊示意、标志、图表不收。再由图标源生成图标数据与小程序用的 mask 样式。
3. 状态色调字典：照规范 第 6.2 节逐行录入。键用数据模型的“表.列”与取值（各分组文档 第 3 节），色调用 `success`、`info`、`warning`、`danger`、`neutral`、`purple`。
4. 脱敏函数；时长格式化；时间类格式化最后做（第 11 节第 1 项）。
5. “页面不写色值”的检查脚本与白名单；预览页；接 CI 与反例（第 11 节第 2 项）。
