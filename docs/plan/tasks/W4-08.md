## 1. 目标

积分调整与补偿延长由不同员工审批后同事务入账；估值和账户流水来自真实 append-only 账本。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `m.pointLedgerEntry.list` | GET `/m/point-ledger-entries` |
| `admin.pointAccount.adjustmentQuote` | POST `/admin/point-accounts/{pointAccountId}/adjustment-quote` |
| `admin.pointAccount.get` | GET `/admin/point-accounts/{pointAccountId}` |

| `admin.pointAccount.summary` | GET `/admin/point-accounts/summary` |
| `admin.pointAdjustmentRequest.approve` | POST `/admin/point-adjustment-requests/{pointAdjustmentRequestId}/approve` |
| `admin.pointAdjustmentRequest.create` | POST `/admin/point-adjustment-requests` |
| `admin.pointAdjustmentRequest.get` | GET `/admin/point-adjustment-requests/{pointAdjustmentRequestId}` |
| `admin.pointAdjustmentRequest.reject` | POST `/admin/point-adjustment-requests/{pointAdjustmentRequestId}/reject` |
| `admin.pointAdjustmentRequest.withdraw` | POST `/admin/point-adjustment-requests/{pointAdjustmentRequestId}/withdraw` |
| `admin.subscriptionTerm.extensionQuote` | POST `/admin/subscription-terms/{subscriptionTermId}/extension-quote` |

| `admin.termExtensionRequest.get` | GET `/admin/term-extension-requests/{termExtensionRequestId}` |
| `admin.termExtensionRequest.reject` | POST `/admin/term-extension-requests/{termExtensionRequestId}/reject` |
| `admin.termExtensionRequest.withdraw` | POST `/admin/term-extension-requests/{termExtensionRequestId}/withdraw` |

- 现状：ledger.adjust 已有受当前生效套餐约束的操作；调整/延长资源、applyAdjustment/applyExtension/unexpire 公口仍需 billing 域实现。
- 表：point_adjustment_request、term_extension_request、approval_request、subscription_term、ledger_operation、point_ledger_entry、billing_entity_daily、point_entry_valuation。
- 两领域单无自身status/执行步：审批单 approved ⇔ applied_at与ledger_operation齐全，同 TX 完成；失败整体回滚仍待审。
- kind=points_adjust/subscription_extend，dedupe_key按主体；提交只冻服务端摘要，不动积分；自己批准、版本/round失效、disabled申请代撤均按公共审批框架。
- 积分方向与数量按服务端schema；platform_refund 只增加、必须关联真实冻结单并走既有积分退回公口，不把 ledger.refund 当现金退款。
- 普通增加/减少用 ledger.adjust，发起可用快照仅展示，批准重新检查余额/套餐生效/退款闸门；原因说明不得进事件自由文本。
- 延长1–90天，批准作用到此刻实际周期；未到期顺延，到期且未续费可 revive/unexpire 冲回清零，续接后作用新周期并记录 appliedSubscriptionTermId。
- 需补原周期清零积分且实际延长新周期时另建关联积分调整单，term_extension_request_id真实关联；不可悄悄二次入账或绕二人审批。
- extend:{审批单号}/adjust:{审批单号}/unexpire 对应已有ledger_operation语义；清零冲回写expired→available及派生估值，历史lot/流水不删改。
- 审批30先锁，业务行按冻结次序，账户420最后；单 TX 一个主体，不在账户锁后新锁审批或业务单。
- 流水 GET 只查/格式化，不隐式 advance 写库；估值按既有 valuation_policy版本派生，日快照由账户时钟生成，不建月结表。
