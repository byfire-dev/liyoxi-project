## 1. 目标

实现营业执照同步OCR与档案识别/字段比对；0新增API/页，唯一x01为 `profile.onFileModerated`。
回补m3-profile-qualification-recognition，不扩行业许可证或银行回单识别；Q8按只营业执照的既定默认。
现有OcrProvider有recognizeBusinessLicense({imageUrl})，未配置实现可用；真实driver目前缺，必须明示新增。
现有profile/documents.ts手填/加密/校验、W2-11多轮/版本/审批继续作为唯一档案写口。
消费既有 `m.qualificationDoc.create`、`m.qualificationDoc.update`、`m.storeProfile.qualification.get`、`m.storeProfile.qualification.submit`；后台沿 `admin.qualificationDoc.update`、`admin.qualificationSubmission.get`/`admin.qualificationSubmission.approve`。
响应复用 `QualificationDocRecognizedSchema`、`QualificationDocSchema`、`QualificationViewSchema`及后台 `QualificationSubmissionDetailSchema` 内既有checkSummary；不新建HTTP资源或平行DTO。

| 交付物 | 结构与事实 |
| --- | --- |
| 同步OCR适配 | m.qualificationDoc.create只读预检后TX外识别，6秒超时；stored kyc_license与分支执照按真实范围，结果不造默认 |
| ocr_result | file/store请求归属、字段加密和结果引用，原识别值保留，不公开明文整包 |
| recognized/submitted | 按m03§2.6真实识别/手填对照；无识别事实仍null/unavailable |
| checkSummary | 名称/USCC/期限/类型交叉核验；checksRanAt来自注入时钟，不假完成 |
| reviewer更正 | 既有lockVersion和更正权限，保存前后值/说明，保留原识别证据 |
| profile.onFileModerated | file.moderated拦截档案图片后重算完整度；重复/旧轮/已移除文件不污染当前轮，不用它启动OCR |

识别和签名在事务外；锁内重核原file、主体/门店、所属轮、文件未移除与当前审核事实。
识别值不能自动批准资质；unknown实体类型不算矛盾，异常允许授权更正或放行并留痕。
只按同一file_id/映射doc_type/permit_type复用最新ok结果，不跨文件指纹冒用原图/字段；员工own/all范围沿现有profile taskScope。
识别前拒绝not_stored/blocked/category_mismatch/scope_mismatch；不额外要求moderation=pass。
按m03§3.12复用(file_id,映射doc_type,permit_type)最新ok结果；分支执照映射business_license，每店每日20次/开关关闭/未配均手填。
识别技术结果在独立短TX写ocr_result；后续挂草稿TX失败不删除结果，同key重试复用且不重复计数。
本同步营业执照路径不造pending→收尾事件；media.ocr.completed异步回单分支由W4-04接，原事件/任务框架保留。
已提交或归档历史保留真实识别引用，不覆盖旧轮；审核/状态迁移仍用profile原flow。
上传/保存幂等重放recognized/submitted按C50为空，原图签名C18 no-store/现签不入幂等。
未配置/失败仍允许手填与人工审核，警示“未识别”，不能把假默认license当生产结果。

## 5. 不做什么

- 不新HTTP资源/前端页、行业许可证/银行回单识别、自动审批或无权限纠正。
- 不改加密/keyring、信用代码唯一约束、冻结DDL/锁序/分层，USCC竞争保留原savepoint口径。
- 不在事务内OCR/签名，不从文件复制错误storeId，不信客户端recognized或subjectType。
- 不覆写历史轮/旧识别结果，不删旧手填与权限断言，不放宽文件classification守卫。
- 不用假证照样本证明真实准确率，不真实启后付费、上传客户证照或读取凭据。

## 6. 允许新增的依赖
