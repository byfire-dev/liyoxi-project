## 1. 目标

交后台收款/退款/调整/发票/对账/财务配置8登记项，并在已有“我的待审批”补财务类型。
0新增API/x01；m4-billing-finance-config-ui桩由W4-13后端和本包页面共同闭环，不重复拥有后端接口。

| 页面key / route | 结构与行为 |
| --- | --- |
| `finance.payments` / `/finance/payments` | PaymentTransactionRow、收款KPI、差异/退款入口 |
| `finance.refunds` / `/finance/refunds` | RefundRequest列表/详情、审批/执行/重试/确认未受理/作废 |
| `finance.credit_adjust` / `/finance/credit-adjust` | 积分调整/延长申请详情、不同人审批，真实估值与天快照 |
| `finance.invoices` / `/finance/invoices` | InvoiceRequest队列、开具/驳回/邮件重发 |
| `finance.reconcile` / `/finance/reconcile` | 月对账/差异/重跑，任务结果真实状态 |
| `finance.offline_refund`（弹层） | 线下退款真实流水/凭证/版本，计1无独立route |
| `finance.red_invoice`（弹层） | 回填红字票与文件，计1无独立route |
| `finance.settings` / `/finance/settings` | 受控配置提议/比对/另一人批准/驳回/撤回，按登记定inMenu |

所有金额/积分/估值/可退款量、审批人与creator限制由服务端，不能按钮隐藏替代权限。
真实quote/lockVersion/stepup同步保护，双击同意图key；写后详情GET/current上下文失效旧结果。
different reviewer与大额二人规则按actual事实；不能登录一个finance账号声称完成两人验证。
退款发起/执行/处理中/受阻/渠道未受理区分，超额和serialNormalized冲突按真实details展示。
0/null金额、版本生效时间、收款账户脱敏不混淆，不打印签名/银行明文/邮箱进错误或截图日志。
财务配置已批准仍有24h生效口径，提议者不能自审，错scope/disabled/stepup按后端拒绝。
已有approval.mine只补实际已合财务类型，不增第9新页；未实现M5取消类型继续隐藏。

## 5. 不做什么

- 不写退款/账本/对账算法、Provider或受控配置服务/schema，不改冻结层/锁序/DDL。
- 不用虚构status/固定金额/假serial压掉真实冲突，不删旧同意/表格/角色/迟到守卫。
- 不跳过stepup/creator两人闸门，不在前端自动退款/重试无界、不代替后台渠道回查。
- 不显示M5未实现审批，不新增“财务审批”独立页，不修改公共Table/Upload/原图签发。
- 不接真实银行/支付/邮件或上传客户发票；fixture假值不声称正式财务配置。
