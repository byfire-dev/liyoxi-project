## 1. 目标

`@liyoxi/shared` 有一套不读库、不依赖运行环境的纯函数：全仓唯一的取整与计价、周期日期、工作日、应用时区、金额与积分格式化。它给出项目最早的账务证据（PRD 2.9 七例）。W0-12、W0-17 与 M1 的账本包直接等它。

“NN 分组”= `docs/data-model/` 下的分组文档；D1、D3 = `docs/appendix/design/d1-ledger.md`、`d3-flow.md`。主文档与草案不一致时以主文档为准。

## 2. 依据

| 文件 第 N 节 | 取什么 |
| --- | --- |
| 01 第 6.3 节；04 ADR-007 | 金额整数分、积分整数、比例万分比。全仓只有一个取整函数，四舍五入。计价是 shared 的纯函数，三端共用 |
| 03 第 2.3 节 | 锚定日规则：锚定日 = 开通当天是几号；边界(k) = 起始月往后数 k 个月，取 min(锚定日, 该月最后一天)；N 个月的周期 = [边界(0), 边界(N))；第 i 个月发放日 = 边界(i)。每个边界都从起始月直接算，不累加。四行示例；闰年 2 月的边界为 02-29 |
| 03 第 2.5 节 | 计价 `S = round(P × R × (1 + T))`，旗舰版或未选用顶级模型时 T = 0。广告每条 = round(单价 × 折扣)。PRD 2.9 七例的算式与结果（PRD 不在仓库里，以这张表为准） |
| 03 第 2.6 节 | 扣减顺序：先取当前周期的套餐批次（按到期时间升序），再取加购批次（按入账时间升序）。七例的第 5 例用它 |
| 03 第 2.7 节 | 升级补差：剩余天数 = 本计费月最后一天 − 今天，当天不计，上限 30；折算 = 差额 × 剩余天数 ÷ 30；已预付的后续整月补全额差价。七例的第 7 例用它 |
| D1 第 3.1、3.2 节 | 业务时区固定北京时间，UTC+8，无夏令时。周期左闭右开；“到期日 24:00”= 次日 00:00。锚定日另三行示例（07-04 起 3 个月；08-30 起 1 个月；02-28、锚定日 31 续接） |
| D1 第 3.3 节 | 唯一的取整函数是整数运算的四舍五入（HALF_UP）。订剧、广告、升级补发积分、升级补交金额、取消扣除额都用它。价值分摊不用它，用向下取整加尾差 |
| D1 第 5.1、5.6 节 | 三个报价函数的输入与整数算式；逐部计算、逐部取整，合计 = 各部之和；展示分解从 S 反推：`round(P×R) − P` 与 `S − round(P×R)`。七例的输入值 |
| 07 分组 第 2.11 节 | 月度发放计划的成本：周期实付 ÷ 月数向下取整，尾差放最后一个月。七例的第 6 例用它 |
| 01 分组 第 2.7 节；14 分组 第 4.2 节 | 日历四种日类型：`weekday`、`weekend`、`holiday`、`adjusted_workday`。工作时段默认 09:00–18:00，不扣午休。超出已有日历范围按“周一至周五工作”兜底。时限策略 `{ amount, unit }`，`unit` 五种：`work_minutes`、`work_days`、`natural_hours`、`natural_days`、`same_day_cutoff`（`amount` 是截止时刻距零点的分钟数，18:00 = 1080） |
| D3 第 22.2 节 | 工作日历的六个纯函数与口径。两条原型示例：`09-30 08:15` 加 1 个工作日 = `10-08 08:15`；`09-29 11:40` 加 1 个工作日 = 次日 `11:40` |
| 规范 第 7 节“金额”“积分”“增减”三行；第 14 节第 8 项 | “¥”开头、不留空格、千分位。商家端整数不带小数，非整数两位。后台交易、对账、结算金额固定两位；标价与门槛整数不带小数。积分千分位，数字与“积分”之间留一个空格。获得用全角“＋”，扣减用“−”（U+2212）；百分比用半角“+”与“−” |
| 约定 第 5 节 C31、C35 | 后台输入“元”转“分”按字符串拆分，不用浮点乘 100。“哪一天”是 `YYYY-MM-DD`，按北京时间 |
| D7 第 10.2 节 P2、P3、P4、P7、P9 | 必带的性质测试；工具 fast-check；PR 上每个性质 200 轮 |
| D7 第 2.2 节 D1、D6；02 第 5.4 节；计划 第 4.2 节 Q4 | shared 不 import `node:*`、`react`；不依赖 contract 以外的工作区包，对 contract 只引纯常量子路径。小程序只引 shared 的纯子路径 |

## 9. 交付与收尾

- 一个工作包一个 PR；超过可评审体量（计划 第 5.3 节“粒度”行）即拆成 a、b 两个可独立合并的 PR，并记一条计划变更。
- PR 描述按 `.github/pull_request_template.md` 填全；借用清单写“源路径@f1361e3 → 目标路径”。
- 同 PR 更新 `docs/plan/status/W0-11.md`。
- 先交付可读的中间成果：先出取整、计价与七例。遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。W0-26 并行改同一个 `package.json` 的 `exports`：各只加自己的行，后合并的一方变基。

## 10. 实现要点与顺序
