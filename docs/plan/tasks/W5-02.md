## 1. 目标

交付九个取消申请/查询/决定接口及非终局驳回跟进，所有退积分执行只调用已合W5-01。

本包拥有的完整 operationId（消费者引用不重复计owner）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.cancelRequest.approve` | POST `/admin/cancel-requests/{cancelRequestId}/approve` |
| `admin.cancelRequest.get` | GET `/admin/cancel-requests/{cancelRequestId}` |
| `admin.cancelRequest.list` | GET `/admin/cancel-requests` |
| `admin.cancelRequest.reject` | POST `/admin/cancel-requests/{cancelRequestId}/reject` |
| `admin.cancelRequest.summary` | GET `/admin/cancel-requests/summary` |
| `admin.cancelRequest.void` | POST `/admin/cancel-requests/{cancelRequestId}/void` |
| `admin.cancelRequest.withdraw` | POST `/admin/cancel-requests/{cancelRequestId}/withdraw` |
| `admin.order.cancelQuote` | POST `/admin/orders/{orderId}/cancel-quote` |
| `admin.order.cancelRequest.create` | POST `/admin/orders/{orderId}/cancel-requests` |

现有CancelQuote/OrderCancelQuoteBody及CancelApprove/Reject/Withdraw/VoidBody复用；复用01的CancelRequestDetail；按a05补OrderCancelRequestCreateBody、CancelRequestCard/Summary和筛选query，不造执行中的字段。

- OrderCancelQuoteBodySchema/CancelQuoteSchema沿已有纯核算与只读去向；手动扣除只在needsManualDeduct的行必填并有依据。
- 发起在父锁内重算expect.totalRefundPoints，变化返回CANCEL_QUOTE_CHANGED；每单唯一在途申请、同key重放同ID。
- 只允许merchant_request/store_closed/platform_fault人工原因；qualification_final只能系统路径，不能让客户端伪造。
- 申请、明细、approval与cancel_review暂停在同TX；审批只到pending_execution，未执行不退积分，审批/执行时限沿原approval框架。
- 免审批开关只在全部release且预览全额原批次时系统决定并调用01同TX自动执行；不造另一套release路径。
- 批准用CancelApproveBodySchema与真实lockVersion，stage_rule_amount_checked/confirm一致，自批拒绝；驳回沿x-step-up:skip，不私自加再验证。
- 撤回本人/停用发起人代撤、对象失效代撤与作废的当前状态/原权限/说明守卫；恢复只移除本来源暂停，不清其他原因。
- 列表/summary/get同一scope过滤，order或finance查看及发起人可见；GET零写，现金退款保持独立列表不合并API。
- order.rejected_stale按当前资质轮次七自然日守卫，只形成客服待办；新一轮/已恢复/已开工时skipped，不提前整店取消。
- 终局qualification_cancel沿现有整店只读试算和01执行；approval/取消指针/订单/广告事实一致，批准前不提前终止或吞失败。

本包x01：定时器order.rejected_stale × drama_order；sla.breach审批主体已在M2，不新增重复归属。
留桩：唯一回补m5-order-qualification-reject-followup.md；公开只读试算不生成申请，终局与非终局分支均有实证。
