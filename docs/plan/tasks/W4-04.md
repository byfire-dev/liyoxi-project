## 1. 目标

在线下代建、凭证识别和大额复核中复用既有对公入账；回补 OCR/SLA 与二人复核，不放开旧财务守卫。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.paymentOrder.create` | POST `/admin/payment-orders` |
| `admin.paymentOrder.transferProof.create` | POST `/admin/payment-orders/{paymentOrderId}/transfer-proofs` |
| `admin.transferProof.approveReview` | POST `/admin/transfer-proofs/{transferProofId}/approve-review` |
| `admin.transferProof.rejectReview` | POST `/admin/transfer-proofs/{transferProofId}/reject-review` |

- 现状：W1-11b 已有凭证上传/确认/驳回、due_at/sla_snapshot 与同流水并发锁；阈值触发时明确拒绝，OCR unavailable/checks=[]。
- 表：billing_order、transfer_proof、payment_txn、approval_request；OCR/media_job 与工作日历只经所属域公口消费。
- 代建须合同号、目标主体/门店可见且 controls.admin_create_order 生效；服务端金额/版本/购买策略守卫与后台开单人快照必存。
- 凭证 pending/accepted/rejected/superseded 为处理进度，不写 status_transition；付款主状态沿既有 flow，子状态只审计。
- 大额首次确认只暂存 first_confirm，提交 kind=transfer_confirm、dedupe_key=transfer_confirm:{proofId}，子状态 confirm_review，不提前建收款交易。
- 复核人与发起/开单人员的不同人守卫、权限、再次身份验证、expectedVersion、清单 round/version/回显均服务端复核；通过后才同 TX 记收款并 applyPayment。
- 复核退回恢复 proof_submitted；复核期间拒绝重传/取消。普通驳回到 pending_payment/proof_rejected，不借审批框架改变业务终态。
- OCR 事件按 fileId/job/主体/当前 pending 凭证绑定，迟到或被 superseded 结果零业务回写；四项比对仅辅助，不能自动确认到账。
- 上传、替换与处理真实登记/重设/取消 sla.breach；CalendarImported 重算期限并保留计算快照，缺日历按 SLA 公共 fallback 并告警。
- 唯一 billing.onCalendarImported 入口本包登记；预留 invoice_request 分支端口给 W4-13，后者不重复登记订阅者。
- 锁序 approval30（复核时）→ order290 → 既有银行流水 advisory → txn300 → proof310 → account420；同 TX 一个主体，到账流水规范化/唯一规则保持。

| 类别 | 登记名与主体 |

| 订阅者 | `billing.onCalendarImported` |
| 订阅者 | `billing.onOcrCompleted` |

回补留桩：`docs/plan/stubs/m4-billing-proof-ocr-sla.md`；目标涵盖 transfer_proof 的 OCR、check_result、sla.breach。
回补留桩：`docs/plan/stubs/m4-billing-second-review.md`；目标涵盖 admin.transferProof.approveReview/rejectReview 与 transfer_confirm。

## 10. 本轮必要范围伴随（2026-10-16）

调度已批准：后台专属开单/共用凭证写段放 `payment/transfer-admin.ts`，四条契约共用 DTO 放 `a07-billing-finance/transfer-review.schemas.ts`；旧 `purchase-write.ts` 只薄调用，保留 W4-06 加购与 W4-05 商家报价段。`apply.ts` / `machines.ts` 仅接正式 `billing_order.approve_review` 迁移和真实审批/凭证关系守卫，不新增入账者。凭证详情复用 approval 公口投影真实第一确认/复核动作。新四口在唯一幂等业务 TX 前作独立只读权限/范围预检，重放也执行；首次写锁后复核，没有事务外外呼或 C51 可续做阶段，不标 `x-three-phase`。

回单 OCR 的缺失由独立 media/Provider 所属前置补齐；只消费实际合流后的 typed 公口，不拿营业执照识别冒回单，不借兄弟未合源码。SLA 仍为唯一 `sla.breach` 按 transfer_proof 分流，原审批/其它主体分支保持。

通知必要伴随仅 `notify/registry.ts` 的 `transfer.sla_breached → s.finance_overdue`、`dispatch.ts` 的既有 finance 受众与当前到期复核、`billing/notify-facts.ts` 的本域真实截止投影；复用现有场景与读口，不新增框架或 invoice 分支。

复核轮次正式勘误：approveReview/rejectReview 均必填本面板 `review.approvalId`；仅审批 lockVersion（新轮常为 0）不能绑定所见的第一确认。锁内核当前 proof 指针与审批 kind/subject/round，approve 再核审批版本；拒绝新轮被旧面板处理，不以凭证版本代替审批版本。
