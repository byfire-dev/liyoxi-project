## 1. 目标

交脱敏日志、受限新代次重发与SMS回执，原M2发送claim/预算/unknown/receipt边界不重建。
必要新token轮换验签先同编号甲机制PR actual，乙消费再接三接口；机制不夹投递业务。
sent仍仅服务商受理；回执只追加事实，未知结果不当送达或开补发。

本包要落地的接口（完整operationId）：

- `admin.notificationDelivery.list`
- `admin.notificationDelivery.resend`
- `hooks.sms.statusReport.receive`

本包页面：

- 无。

本包x01：

- `hooks.sms.statusReport.receive`

准确输入与边界：

- list支持scene/channel/status/reason/origin/purpose、isDirect、notificationId、接收人/归属和bizType+bizId。
- 日期按北京时间，默认近7天/跨度≤92天；页码分页、sort=-createdAt/-dueAt。
- resend路径notificationDeliveryId；body.reason非空白1–100；权限notify.resend。
- 只failed/skipped外部非直发最新代且无更新成功投递、场景开关可用；拒绝原因沿既有NOTIFY_RESEND_NOT_ALLOWED。
- 新行manual/pending、resendNo=max+1、attemptNo=0，用现行唯一键，不重置旧行。
- POST /hooks/sms/status-reports?token=：≥32随机字节token常量时间比较，轮换可新旧两把，访问日志脱敏。
- body非空数组，读sid/report_status/errmsg/user_receive_time映射SmsStatusPayload并丢弃手机号；eventId=rawBody.sha256。

输出与公口所有权：

- notify拥有read/resend/receipt写侧，security拥有内联收件/验签装配；公开notify.resend可供未来发票消费。
- receipt只改receipt_status/receipt_reported_at，不改delivery.status/预算/补发；未知sid跳过受控记录。
- inline收件与逐项回写同TX；至少一匹配processed，全未知ignored，失败整体回滚500。
- 重发由原scan/deliver重验业务/开关/配额；自动SMS fallback每通知至多一条沿M2唯一键。
- 审计notify.delivery.resend对象新行，meta.sourceNotificationDeliveryId指原行，不额外发outbox。

关键风险：

- 同旧行重发3轮×3–5并发，新代次唯一/同键只一行，不重复下发。

- unknown_outcome与直发含验证码/test不可重发，不据receipt再次外呼。
- 日志仅脱敏，手机号/openid/原Provider错误内容不直接下发；PII沿原公口。
- 发送业务前置用真实公口/隔离工厂，不能SQL造sent或绕收费保护。
- 受影响服务/API或页面typecheck；涉及契约用官方生成/文档对账，原黄金只增。
- 真实HTTP/生产handler、提交后state/history/audit/events为证据，不用注册字符串充数。
