## 1. 目标

- `apps/admin` 有外壳、菜单、路由、请求客户端与三种页面骨架；之后的后台页面包只填“查询、列定义、详情内容、动作”。
- `apps/portal` 能构建，是一个空壳。
- 菜单登记表与页面清单就位，页面归属可由 CI 统计。使用方：W0-29、W1-02、G2-0 的构件包、全部后台页面包、M6 的下载页。

## 9. 交付与收尾

- 一个工作包一个 PR。L 包按“工程与主题 → 菜单与路由 → 请求客户端 → 外壳 → 三种骨架与两个构件 → 下载页空壳 → 冒烟与页面清单”组织提交，PR 描述给出阅读顺序。超过可评审体量即拆 a（工程、菜单、外壳、下载页空壳）、b（三种骨架与构件），并记一条计划变更。
- PR 描述按 `.github/pull_request_template.md` 填全，附截图链接。
- 同 PR 更新 `docs/plan/status/W0-28.md`。
- 先交付可读的中间成果；遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。

## 10. 实现要点与顺序

1. 两个 Vite 应用起步。antd 全局主题用 W0-26 的生成物；全局字号 14，表格、输入框等按规范 第 5.4 节用组件级变量下调到 13。
2. `src/lib/menu.ts`：`{ key, title, path, module, release, badgeKey?, milestone, implemented, screen }`，由 routemap 的 `screens` 与 D7 第 5.2 节整理；它是菜单、面包屑、守卫的唯一来源。
3. 文件路由；每个路由的守卫按模块等级判断，不满足去 403 占位页。
4. 外壳：侧栏、面包屑（最多三级）、用户区、全局提示；菜单按权限与 `release` 过滤；详情页保持父列表的菜单项选中。
5. 请求客户端：类型取自 `@liyoxi/contract/types/admin`；一个中间件统一加请求头；按符号名统一处置错误，会弹框或跳转的恢复动作单飞。
6. 筛选表格：筛选、页码、排序、页签进 URL；服务端分页；翻页保留上一页数据。
7. 审核工作台：左队列右详情；当前页签、选中项、搜索词进 URL；清单没勾完主按钮禁用；处理完自动选中下一条；冲突时提示并跳下一条。
8. 详情页：页头、状态、页签、侧栏卡片。确认构件与上传构件按规范 第 5.3 节。
9. 样例路由、单测、冒烟、下载页空壳、页面清单、CI 接入；写 D7 第 10 项的结论。
