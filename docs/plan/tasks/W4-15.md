## 1. 目标

交小程序积分流水1页 `sub/billing/ledger/index`，接已有钱包只读入口；0新增API/x01。
唯一业务数据源为W4-08 `m.pointLedgerEntry.list`，不自行推算余额、价值、过期或冻结金额。

| 消费operationId | 结构 / 页面行为 |
| --- | --- |
| `m.pointLedgerEntry.list` | LedgerEntryRow、nextCursor/hasMore；type、日期范围及真实过滤 |
| `m.wallet.get` | 旧钱包余额/服务端动作，仅导航接线，GET不advance |

LedgerEntryRow字段逐项来自actual generated merchant；schema缺项由W4-08补，不页面定义新DTO。
积分为整数、金额为整数分格式化；valueFen/null语义保留，0与null不混为“暂无”。
按服务端稳定游标分页，第一页刷新使旧分页失效；去重只用返回唯一id，不改真实排序。
过滤条件变化清旧游标/列表，空/加载/失败均明示，重复点击同步锁并能恢复。
日期按公共北京时间dateKey和真实字段，不从UTC字符串截取月份造边界。
列表行标题/单号/数量/余额按owner/clerk真实投影，店员不请求或展示禁用积分/金额键。
无权响应不绕过，跨店/归档行为消费actual capability；不能由钱包可见推断流水可读。
ctxRev/身份/门店变化、卸载使旧成功/错误失效；旧finally不能释放新请求锁。
GET不记录业务同意/写审计伪动作；页面埋点按登记必要字段，不发余额/手机号明文。

| 页面状态 | 必须可观察结果 |
| --- | --- |
| 初始/第一页 | header与过滤加载，无旧门店数据闪现 |
| 刷新 | 原分页结果不会覆盖新页，cursor来自新响应 |
| 后续页 | hasMore=false停，错误可重试且不重复行 |
| 空结果 | 区分当前过滤无结果与读取失败 |
| 日期边界 | 北京日跨UTC/月末、清筛选回默认 |
| 角色受限 | 实际403/裁剪依契约，禁用键0次 |
| 失效上下文 | 新店继续操作不被旧请求/错误/锁污染 |

## 5. 不做什么

- 不创建账本操作、退款/调整/冻结、不读services/db，不端上算余额/估值。
- 不把末页hasMore误当请求失败，不合并旧过滤cursor，不靠延迟/timeout解决竞态。
- 不写色值/硬编码引导copy，不删旧ctxRev/卸载/店员守卫。
- 不改支付或发票页面、下载签名、上传/平台函数；0新依赖/接口/timer。
- 不声称H5是真机日期/微信体验，也不获取真实商家账目。
