## 1. 目标

api 进程能起来：读环境变量、建数据库与 Redis 连接、装配服务、按契约挂路由、对外应答探活。各域的接口包往后只写“一条契约路由配一个薄壳处理器”，请求编号、日志、校验、错误体、幂等都由骨架给；路由声明了而没挂上对应中间件，进程起不来。

移交表（`docs/plan/tasks/README.md` 第 5 节）归本包的：

| 行 | 事项 | 本包怎么办 |
| --- | --- | --- |
| 1 | 启动时调四个自检（security、审计 `target_type`、聚合类型、`machine` 与 `state_field`） | 给出启动自检的挂点（一张清单，逐项跑、问题一次报全）。四个自检函数开工时都不在 main 上，不接；到了的各加一行，W0-23 或 W0-30 兜底 |
| 2 | 客户端工厂的连接参数在装配时传；真实构建脚本接替占位 | api 主池照 D7 第 8.3 节的表传；`build` 换成真实的打包（见第 10 节第 11 项） |
| 3 | 测试装配导出“已挂载的 operationId 清单”；`/health` 读 worker 租约 | 清单写到 `apps/api/dist/mounted-operations.json`；`/health` 读 `worker_lease` |
| 4 | 放开一个装配文件引 `@liyoxi/db` 的 `gate-change` PR | 不开：数据库客户端在 `packages/services` 一侧建，api 不引 `@liyoxi/db`（W0-07b 偏差 3 的最后确认） |
| W0-10 状态文件“往后移交” | 已挂载清单的路径与格式；接口层测试的位置；两条内网探活的留桩写法；基线降到 610 | 照做 |

“约定”= `docs/api/00-conventions.md`；“h01”= `docs/api/h01-hooks.md`；D7 = `docs/appendix/design/d7-platform.md`。

## 5. 不做什么

- 不定中间件的装配顺序，不做限流（W0-22b）。本包自己的几件按约定 C7 的相对先后挂上，`apps/api/src/routing/pipeline.ts` 留给 W0-22b 接手成唯一的定义。
- 不做鉴权链、成员关系、协议同意、再验证、版本门槛、开关拦截、店员视图裁剪、回调验签（M1 的各包）。“声明即挂载”的规则表里先写上 `x-auth`、能力点与权限点、`x-rate-limit` 对应的中间件名：它们没到之前，声明了这些的路由挂不上去。
- 不写任何业务接口；契约里带结构的路由现在是 0 条。
- 不接 Provider 的装配（见第 10 节第 3 项）；不做队列（W0-23）、事件循环看门狗、`api-drain` 的等待时长（发布编排，G2-D）。
- 不加环境变量，不改 `.env.example`（见第 10 节第 4 项）。
- 不改 `infra/ci/layers.json`、已有的检查脚本、反例与 CI 步骤；不改契约的路由元数据。

## 7. 验收

都在 `pnpm test` 里，不加 CI 步骤。连库的用例走测试支架。

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 接口层测试通过 | `pnpm exec vitest run --project api` | 请求编号（合法的沿用、不合法的重发、错误响应也带）；访问日志里 `token`、`code`、`sig` 等查询参数被遮住；Host 与分组不配即 404；入参不合结构回 400 `VALIDATION_FAILED` 带 `fieldErrors`；业务错误按契约的表出状态码与错误体，未预期的错误回 500 `INTERNAL` 且不带内部信息；四组各挂得上一条样例路由 |
| 2 | 幂等上下文 | 同上 | `required` 缺键 400；同键重放不再执行处理器、回 `Idempotent-Replayed: true`；同键不同内容 409；处理器没把上下文交给 `tx.run` 时报错（防漏用） |
| 3 | 漏挂中间件启动失败 | 同上 | 路由声明了 `x-auth`（非 `public`）、能力点或权限点、`x-rate-limit`、幂等方式而装配里没有对应的中间件：建应用即抛错，点名路由与缺的中间件；不是契约构造器产出的路由、重复挂载同样抛错 |
| 4 | 探活 | 同上 | `/healthz` 200；`/readyz` 启动中与排空中 503、就绪 200；`/health` 没有租约行时 503 且 `worker = down`，租约新鲜、探针新鲜时 200；两条内网探活回 503、各项为 `null` 且都在 `breaches` 里；五条都带 `Cache-Control: no-store`、不套信封 |
| 5 | 构建产物可启动 | 同上（`test/build.test.ts`） | 构建出 `apps/api/dist/server.js` 与 `check-env.js`，产物引到的第三方包都已声明；起它，`/healthz`、`/readyz` 回 200；收到 SIGTERM 后以 0 退出；库连不上时启动失败、退出码 1 |
| 6 | 已挂载清单与基线 | `pnpm test && node infra/ci/landed.mjs --check` | `apps/api/dist/mounted-operations.json` 里是根路径 3 条探活的登记键；待落地 610，不高于基线 |
| 7 | 运行时装配 | `pnpm --filter @liyoxi/services exec vitest run src/runtime.db.test.ts src/ops/` | 连接上的三个会话超时是 D7 表里的值；启动自检有一项不过即失败并列出全部问题；健康检查各项的口径 |
| 8 | 不带坏已有门禁 | 全套（lint、格式、类型、依赖方向、测试、`gates:selftest`）；`node infra/ci/classify-gate-changes.mjs --base origin/main` | 退出码 0；门禁改动只有“只增” |

## 10. 开工前要定的点（默认，本任务书定）

| # | 要定的事 | 默认 |
| --- | --- | --- |
| 1 | 基础设施的装配放哪 | `packages/services/src/runtime.ts`（包级文件，与组合根 `assembly.ts` 并排），经 `@liyoxi/services` 的入口给 api 与 worker。没有照 D7 第 2.3 节规则 7 放进 `kernel/context.ts`：kernel 的入口被全部模块引用，放进去每个用例都要加载数据库客户端；它还要引 config，会成环 |
| 2 | 连接池 | 只建 api 主池（10 个连接，语句 8 秒、等锁 3 秒、事务内空闲 15 秒）。读侧池等第一个用它的包（报表）再建 |
| 3 | Provider 的装配 | 本包不接。驱动的入口只许 kernel 引，而接进 kernel 的入口会让全部模块加载对象存储的 SDK；落点留给 W0-20（它要把外呼前钩子接到事务标记上） |
| 4 | 监听端口、镜像标签、域名 | 不加环境变量。端口走命令行参数 `--port`（缺省 3000）；镜像标签在构建时写进产物（构建环境的 `LYX_BUILD`，没给即 `dev`）；Host 判断只看域名的第一段（`api`、`admin`、`portal`），不比完整域名 |
| 5 | Host 判断的口径 | `api.` 只放行 `/m`、`/hooks` 与根路径探活；`admin.` 只放行 `/admin`；`portal.` 只放行 `/portal`；`/internal/*` 只在不是这三种域名时放行。第一段不是这三个的（节点内网地址、`localhost`）：`local`、`test` 下全放行，`stg`、`prod` 下只放行探活与 `/internal/*` |
| 6 | 探活挂在哪 | 根路径，路径取契约里“只登记”的 5 条；不走幂等与校验，不进访问日志的 info 级（`/healthz`、`/readyz` 记 debug） |

| 8 | 处理器怎么登记 | `defineHandler(契约路由, 处理函数)`，各域一个文件，汇在 `apps/api/src/routes/index.ts`（一域加一行）。处理函数经 `c.var` 拿请求编号、身份上下文、幂等上下文、运行时 |
