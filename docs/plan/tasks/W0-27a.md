## 7. 验收

测试命令写作 `pnpm exec vitest run <文件>`；仓库登记的测试入口不同名时（看 `CLAUDE.md` 第 9 节），用登记的入口加同一文件过滤。`pnpm weapp:build`、`pnpm weapp:shots`、`check-mp-size.mjs`、页面清单脚本与下列测试文件都由本包提供。

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 构建 | `pnpm weapp:build` | 以 0 退出；`apps/weapp/dist/app.json` 含四个标签页、`__usePrivacyCheck__: true`、`lazyCodeLoading`、`networkTimeout`（30 / 300 / 600 秒） |
| 2 | 体积门禁 | `node infra/ci/check-mp-size.mjs apps/weapp/dist` | 主包 ≤1,500KB 且各分包 ≤800KB 时通过，并打印各包体积；对两个超限夹具（主包超、某分包超）各非 0 退出；两个反例进 `gates:selftest` |
| 3 | 请求层 | `pnpm exec vitest run apps/weapp/src/lib/request.test.ts` | 请求头齐全；5 个并发请求同时得 `AUTH_REQUIRED` 只触发一次静默登录，各重放一次且沿用原 `X-Request-Id` 与幂等键；没带令牌的 401 不清会话；带幂等键的写请求网络失败至多重试 2 次，不带的不重试，GET 重试 1 次；`BUSY`、`IDEMPOTENCY_IN_PROGRESS` 按 D7 第 4.4 节重试；同时在途的业务请求 ≤6 |

| 5 | 隐私封装 | `… apps/weapp/src/lib/privacy.test.ts` | 未授权时先走授权再调隐私接口；用户拒绝时返回可识别的结果，没有未捕获异常 |

## 9. 交付与收尾

- 一个工作包一个 PR。L 包按“工程与构建 → 页面清单与标签页 → 请求层 → 四个封装 → 门禁与截图”组织提交，PR 描述给出阅读顺序。超过可评审体量即拆 a（工程、门禁、截图、页面清单）、b（请求层与四个封装），并记一条计划变更。
- PR 描述按 `.github/pull_request_template.md` 填全，含借用清单与截图产物链接。
- 同 PR 更新 `docs/plan/status/W0-27a.md`。
- 先交付可读的中间成果；遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。

## 10. 实现要点与顺序

1. Taro 工程起步并构建通过（借参考工程的配置）。尺寸写在 `.scss` 文件里，原型的 px 原样写。
2. `src/pages.ts`：49 个路由一行一条（路由、分包、画板、里程碑、工作包、已实现）。`app.config.ts` 由它生成，只输出已实现的页。
3. 原生标签栏四项：首页、短剧商城、选剧单、我的；图标位图由 W0-26 的图标源导出。`NavBar` 自绘导航读胶囊位置避让，左侧留 8px 以上。
4. 体积门禁与两个反例。
5. stores：`session`、`context`、`bootstrap`；引导数据缺省取保守默认。本地存储键带 `lyx.` 前缀。
6. 请求层；静默登录与各恢复动作经注入的函数接入；类型取自 `@liyoxi/contract/types/merchant`。
7. 四个封装；上报库验证并写结论。
8. 截图命令；页面清单生成；CI 接入。`project.config.json` 由脚本生成，仓库里只放模板。
