## 1. 目标

回补续费、升级、降级与购买报价分支，让过期清零/补偿锚定/R1 提醒由账本实际事实驱动。

要落地的接口（只有下表属于本包）：

| operationId | 方法与实际路径 |
| --- | --- |
| `admin.subscriptionTerm.get` | GET `/admin/subscription-terms/{subscriptionTermId}` |
| `admin.subscriptionTerm.list` | GET `/admin/subscription-terms` |
| `admin.subscriptionTerm.remind` | POST `/admin/subscription-terms/{subscriptionTermId}/remind` |
| `admin.subscriptionTerm.summary` | GET `/admin/subscription-terms/summary` |

- 现状：plan 类型开通/续期的公共 fulfill 已有；upgrade/topup 明确 blocked，创建与报价非 subscribe 拒绝，R1 只读提醒端口尚空。
- 表：subscription_term、subscription_event、grant_schedule、point_lot、billing_account、billing_entity_daily、ledger_operation、plan_revision。
- 周期只走 scheduled/active/ended/refunded/cancelled；07没有 flow 业务状态机，周期/发放计划在账户锁内推进，只写 subscription_event/账本历史，不写 status_transition。
- 账户时钟来自 ledger.lockAccount，支付成功时间不是发放起点；时钟、补偿与止日均按真实日期算法，不按固定30天造月。
- 在现 fulfill(tx,{billingOrderId,ctx}) 增 upgrade 分支：当期权益换版本、整数积分补发、其后发放计划改写，保持账本操作/结果重放唯一。
- 续费/降级按当前权益、已排期周期与服务端政策报价；延长后续费锚定日前一真实周期止日，不能产生重叠、漏月或旧 dates snapshot 覆盖。
- 现 public ledger 已有 advance/grant/purchase/resumeAddon，但升级/延长/回收所需域函数不齐；只在 billing 域新增窄公口，沿既有操作幂等与账户锁，不改 kernel。
- 既有计划报价与付款创建接口增量回补非 subscribe 分支，operationId 仍归 M1；topup 部分交 W4-06，不并入本包自己的接口清单。
- 月发放按整数分配、余数落最后月；advance 先发放/推进再清零，冻结与可用守卫依既有序列，已用积分不从历史账删掉。
- 日 sweep 分页按主体推进，单 TX 一个主体，账户420最后锁；失败隔离/游标恢复不漏主体，13个月快照按虚拟时钟与手算模型验。
- R1 由 listTermsDueForReminder 真查询到期/清零节点，交 W2-17 通知规则；通知发送不在账户 TX，不新增虚构 renewal_reminder_due 事件。
- 依赖 W4-08/W4-10 的延长与退款会消费本域期限事实，但本包不执行审批/现金退款；冻结消费、退款暂停与不可购买提示由服务端返回。

## 5. 不做什么

- 不实现 topup 履约、积分审批、套餐延长审批或现金退款三段式；兄弟包分别消费公口。
- 不改资源定价/模板价算法、不新增月结表/托管款项/V1.1内容，不跨主体拼一 TX。
- 不改公共 clock/锁/账本操作框架，不因 sweep 失败跳过真实主体或把提醒已投递当已送达。
- 不调用真实云、真实支付或真实员工账号，不用 SQL 直接推进状态，不绕过公口制造已付款/已退款事实。
- 不删旧测试、提高等待/重试、放松门禁或把 fake/mock 成功写成线上联调完成。
