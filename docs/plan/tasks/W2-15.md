| 项 | 内容 |

## 1. 目标

交后台商家列表、按真实 storeId 的商家详情、渠道码登记三页；保留 M1 资质审核页与账号/审批权限框架。
列表/详情虽已有登记，actual M1 只落地资质审核等相关入口；本包据实际主干实装，不把占位登记算已完成页面。

| page key | 地址 / 主要交互 |
| --- | --- |
| `merchant.list` | `/merchants`；筛选、稳定分页、summary、实际门店跳转 |
| `merchant.detail` | `/merchants/$storeId`；档案/资质多轮、负责人/跟进、主体成员、账号变更与活动事实 |
| `merchant.referral_codes` | `/merchants/referral-codes`；创建/停用/启用/筛选与来源说明 |

list/get 保留已有 `admin.store.list/get` 公共 DTO；消费 W2-11 的 summary/activity/profile/qualification/followUp/指派接口。
主体/成员/覆盖/关闭消费 W2-10：`admin.entity.get/member.list/quota.update/close`，按服务器 actions 展示。
账号变更与禁用/启用/下线、渠道码消费 W2-09；申请/决定分开权限，不能在详情页默认全部员工可审批。
结构直接取 `StoreRow/StoreHeader/StoreListQuery/StoreListSummary/AdminStoreProfile/AdminStoreQualificationView`。
跟进/指派取 `FollowUpItem/AssignmentContactView/ManagerTransferResult`；主体取 `EntityCard/MemberRow/EntityQuotaCard`。
账号请求取 `AccountChangeRequestCard/Detail`；渠道码 `ReferralCodeRow`；PII 默认脱敏，不能自行读取文件 ID 解密。
详情私有弹层可录代改/跟进/账号请求，仍在一项详情页；新增独立资质审核页不属于本包。
`qualification.review` 的已有审批行为保持冻结，本包只用实际 submissionId 只读导航，原自审/override/回显/版本 guards 不搬到前端。
表/状态机/事件/定时器：本包全部 0；服务端决定、指派和 quota 不由页面计算或写数据库。

- 本包 README/status、截图与 official pages 生成；不是 server 契约或业务改造包。

## 5. 不做什么

不改公共 QueryTable/CompareTable/RejectDialog/date-range/PII 构件，不新增布局主题/硬编码色值。
不把后台相邻资质页重新实现，不抢 W2-06 我的审批/安全菜单，不做 V1.1 渠道合作与佣金管理。
不直接查 DB/import services，不假设无 scope 的 read Meta 代表全局可见；不本地拼跨主体字段。
不在 frontend 绕过 step-up、creator、自审、lockVersion、回显或 ACCOUNT/ENTITY_CLOSE_BLOCKED。
不把空金额/空 manager/未知来源变 0 或假姓名，不硬编码“最后订单”排序代替服务端 full filters。
不修改生成契约、权限矩阵、旧黄金/门禁和预算；backend缺口先交拥有者单独补实际公口。

## 9. 交付与默认

丙类三页一 PR，详情内弹层不拆成暗页；若实际独立资源页超过三项先记五行变更由调度定。

merchant.list/detail 当前里程碑 M2 保留，既有 M1 StoreRow/Get 和 qualification.review 不移归属。
服务端 actions 决定是否可编辑/审批/转移/关闭，读页可见不等于可写；拒绝后仍保留当前详情以重取事实。

最终交具体浏览器截图、键盘记录、live 结果与精确新页数；不把演示 fixture 当生产事实端口。
