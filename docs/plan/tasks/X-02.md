## 1. 目标

证明 `mediatool` 隔离容器在本地可行：体检、抽封面、AI 标识写入并回读三个操作可用；无网络、无密钥、只读根等约束全部成立；耗时可接受。交出可复用的镜像定义（W1-22 直接复用，G3-A 以它为起点）与 V11 本地部分的结论。产物不丢（计划 第 7.4 节）。

必须沿用的约定（D5 第 6.6 节）：

| 项 | 约定 |
| --- | --- |
| 镜像 | 钉死版本的 ffmpeg / ffprobe + 约两百行的 Node 服务；基础镜像 `node:24-slim` 固定摘要 |
| 网络与凭据 | `network_mode: none`；不注入任何密钥环境变量，不挂密钥文件，没有数据库连接 |
| 文件系统 | 根只读；`/tmp` 为 64MB 内存盘；只挂一个与调用端共享的目录 `/work` |
| 进程限制 | 非 root；`cap_drop: ALL`；`no-new-privileges`；`pids_limit: 128`；内存 1GB、CPU 1 核；并发 2 |
| 调用方式 | `/work/.sock/mediatool.sock` 上的 HTTP + JSON；请求只带 `/work` 下的相对路径与参数；容器自己不取任何远端内容 |
| ffmpeg 参数 | 一律 `-nostdin -protocol_whitelist file`；按登记的扩展名强制解复用器（mp4 / mov / m4a → `mov`）；`mov` 加 `-enable_drefs 0 -use_absolute_path 0`；`-probesize`、`-analyzeduration` 设上限；每次调用 30–90 秒硬超时，超时杀进程组 |
| 输出 | 写回 `/work/{jobId}/`。调用端把输出当不可信数据：JSON 用 Zod 校验且 ≤4MB；封面须是合法 JPEG 且 ≤1MB；加标产物大小在输入 ±1MB 内 |
| 三个操作 | `probe`（媒体信息 + 顶层 box 顺序 + AIGC 标签）；`poster`（抽第 1 秒一帧）；`stampAigc`（`-map 0 -c copy -metadata AIGC=<JSON> -movflags +faststart+use_metadata_tags` 后回读；不带 `use_metadata_tags` 会被静默丢掉） |
| AIGC JSON | 七个字段：`Label`、`ContentProducer`、`ProduceID`、`ReservedCode1`、`ContentPropagator`、`PropagateID`、`ReservedCode2` |
| 耗时线 | 200MB 文件“体检 + 封面” ≤10 秒（D5 第 16 节 P9；本地不含下载） |

## 5. 不做什么

- 不把样片或生成的测试片提交进仓库。不建 `spikes/` 目录：本包的产物都要保留。

## 7. 验收

命令由本包提供。`mediatool:verify` = 构建镜像 → 起 `compose.verify.yml` → 在调用端容器里跑 `verify/` 的用例 → 收尾。

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 镜像可构建 | `docker build -t liyoxi/mediatool:verify infra/docker/mediatool` | 退出码 0；镜像里 `ffmpeg -version` 与钉死的版本一致 |
| 2 | 写后读回一致（计划的验收原文） | `pnpm mediatool:verify` | `stampAigc` 之后 `probe` 读回的 AIGC 与写入的 JSON 逐字段相等；各流的编码、时长、帧数不变；产物大小在输入 ±1MB 内；`moov` 在 `mdat` 之前 |
| 3 | 回读检查有效（反例） | 同上 | 去掉 `use_metadata_tags` 的加标产物读不回 AIGC，用例断言“读不回” |
| 4 | 体检与封面 | 同上 | `probe` 对测试片给出正确的容器、编码、显示尺寸（带旋转元数据的一条按旋转后算）、时长、音轨数、`moov` 位置；`poster` 输出合法 JPEG 且 ≤1MB |
| 5 | 容器约束成立 | 同上（用例名含 `sandbox`）加 `docker inspect` | 容器内没有除回环以外的网卡，访问外部地址失败；写根文件系统失败；运行用户非 0；环境变量里没有密钥类的键；`NetworkMode=none`、`ReadonlyRootfs=true`、`CapDrop=[ALL]`、`no-new-privileges`、`PidsLimit=128`、内存上限 1GB |
| 6 | 恶意输入不出界 | 同上（用例名含 `hostile`） | 内容是播放列表的“.mp4”按 `mov` 强制解复用后失败，不读它引用的任何地址或文件；带外部引用的 mov 不被跟随；跑不完的输入在硬超时内被杀且没有残留进程；带 `..` 或绝对路径的请求被拒 |
| 7 | 调用端不信任输出 | `pnpm exec vitest run packages/services/src/providers/mediatool` | 对一个假的套接字服务：超过 4MB 的 JSON、结构不符的 JSON、不是 JPEG 或超过 1MB 的封面、大小超出 ±1MB 的加标产物，各被拒；容器不可达时给出可识别的“不可用”结果，不抛未捕获异常 |
| 8 | 耗时 | `pnpm mediatool:bench` | 约 200MB 的测试片“体检 + 封面”合计 ≤10 秒；`stampAigc` 的耗时写进报告（没有硬线） |
| 9 | 在 CI 上可重复 | 新增任务的 CI 运行 | 第 1–7 条在 CI 上为绿，链接进 PR |
| 10 | 结论入 ADR | `ls docs/adr/draft-X-02-*.md`；`git diff --stat origin/main -- docs/plan/external-verification docs/08-development-plan.md` | ADR 存在；差异里有台账 v11 与计划。ADR 写明：通过或不通过、ffmpeg 版本与安装方式、各项耗时、套接字在两个容器之间是否可用、遗留问题。台账 v11 与计划 第 8.6 节 V11 行已同步 |

## 10. 实现要点与顺序

1. 读 W0-19 合并的 providers 目录，确认体检方法位在哪、有没有 `MediaToolProvider`（第 11 节第 1 项）。
2. `Dockerfile`：固定摘要的基础镜像 → 装钉死版本的 ffmpeg → 建非 root 用户 → 入口是容器内服务。
3. 容器内服务：监听套接字；三个操作；并发 2 的排队；子进程带硬超时并杀进程组；路径只接受 `/work` 下的相对路径；应答是 JSON。
4. `compose.verify.yml`：`mediatool` 套上第 2 节全部约束；`caller`（同一个基础镜像，不装任何依赖）与它共享一个卷，在里面跑 `verify/` 的用例。
5. 测试片用镜像里的 ffmpeg 现场生成，不入库：竖屏 1080×1920 的 H.264 + AAC 一条；带旋转元数据的一条；`moov` 在后的一条；已带 AIGC 的一条；约 200MB 的一条；伪装成 mp4 的播放列表与带外部引用的 mov 各一条。
6. `verify/` 的用例（第 7 节第 2–6 条）与耗时脚本；加 CI 任务。先交这一段。
7. 调用端：套接字上的调用；用 Zod 校验应答；校验封面与大小；用例（第 7 节第 7 条）。
8. 写 ADR，更新台账与计划 第 8.6 节，写 `README.md`（镜像怎么复用、Compose 片段、已知限制）。
