表结构由代码接管：`packages/db` 有 schema、一个建全 166 张表与全部手写约束的首版迁移、客户端工厂。合并后结构以迁移为准（06 第 8 节），之后所有连库的包从这里起步。

产出：迁入的 schema；首版迁移；Prisma 配置与客户端工厂；系统目录比对脚本；托管库验证脚本（V5 扩展用）；`db:*` 五个命令；CI 里新增的三步与一个反例。路径见第 4 节。

## 5. 不做什么

## 10. 实现要点与顺序

1. 起环境，确认是 17，跑验收 1。不过就按“偏差”处理，先别往下做。
2. 配依赖与 `prisma.config.ts`（连接串只取环境变量 `DATABASE_URL`，缺了就报错）。迁入 schema：只改文件头注释与 `generator` 的输出目录。
3. 出迁移：`prisma migrate diff --from-empty --to-schema … --script` 的输出，接上 `constraints/00`–`15`（文件名顺序）。语义一字不改，只许加注释。分区改造里的 `RENAME` 与 `DROP TABLE analytics_event_plain` 各带一行 `-- lyx:allow <理由>`：检查脚本在 W0-06b，这里先带上，免得合并后再改迁移文件。拼接用脚本做并留在仓库，可重跑核对。
4. 空库 `migrate deploy`。写比对脚本，跑到 0 差异、计数对上；再跑一遍确认可重复。
5. 写工厂与测试。工厂的参数：连接串、连接数上限、三个会话超时。取值由 W0-22、W0-23 装配时传，本包不写死。
6. 接 CI 三步与反例；补 `CLAUDE.md`；写托管库验证脚本：连接串只取环境变量，不打印。
