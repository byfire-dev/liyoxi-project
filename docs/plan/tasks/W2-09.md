## 1. 目标

完成个人账号安全生命周期、人工账号变更审批与渠道码登记；保留 W1-04 已实现的登录、会话和字段裁剪。
账号注销与人工主体关闭共用 W2-10 的主体关闭函数，同一事务完成联动，不复制第二套关闭逻辑。
要落地的接口（本包唯一新增归属）：

| operationId | 请求 / 响应结构或业务边界 |
| --- | --- |
| `m.me.changePhone` | `oldSmsCode`、`newPhoneCode`；返回 `MeUser`，保留当前会话 |
| `m.me.deletion.create` | `hasConfirmed=true`；`DeletionResult` / 六类 `blockers` |
| `m.me.update` | 本人称呼；`MeUser`，文本安全检查在事务外 |
| `m.me.userNotice.acknowledge` | 本人 `userNoticeId`；`UserNoticeAckResult` |
| `m.me.wechatIdentity.delete` | 本人身份；`WechatIdentityRemoveResult` |
| `m.me.wechatIdentity.list` | 游标分页；`WechatIdentityItem`，不返回 openid |
| `m.smsCode.create` | 仅 `purpose=phone_change`；`SmsCodeResult` |
| `admin.accountChangeRequest.approve` | 换绑、老板更换、老板复核；同事务决定并生效 |
| `admin.accountChangeRequest.create` | `AccountChangeRequestDetail`；同时建审批单与材料引用 |
| `admin.accountChangeRequest.get` | `AccountChangeRequestDetail`；手机号和核实材料脱敏 |

| `admin.merchantUser.disable` | 禁用并吊销会话；`MerchantUserStatusView` |
| `admin.merchantUser.enable` | 启用账号；不恢复旧会话 |
| `admin.merchantUser.forceLogout` | 吊销会话；不改变账号状态 |
| `admin.referralCode.create` | `ReferralCodeRow`；唯一渠道码与登记人员 |
| `admin.referralCode.disable` | 停用登记；既有首次归因不被改写 |
| `admin.referralCode.enable` | 恢复登记；守卫与版本遵循 a03 |
| `admin.referralCode.list` | `ReferralCodeRow`；查询、筛选与分页 |

表：`merchant_user`、`wechat_identity`、`user_session`、`merchant_user_notice`、`sms_verification`、`account_change_request`、`referral_code`；审批记录、文件引用通过既有服务写。
状态：账号 active/disabled/deleted 与账号变更对应审批状态均走已登记 flow；初始历史、审计和事件使用同一事务。
事件按 x01 既有登记发出 `merchant_user.wechat_bound/deleted`、账号安全及审批事件；不得夹带手机号明文、openid、材料 URL。
x01 本包唯一新增实装：`identity.onWechatBound`，重复事件只生成一次 `new_wechat_bound` 提示，排除新绑定身份的通知由 W2-17 处理。
回补 `m2-identity-dormant-branches.md`：休眠店员移出后继续绑定、休眠老板的空草稿让位后继续绑定；保留原五条放行条件。
会话过期清理接到既有 ops 清理登记处，不发明新 cron 名；30 天闲置、90 天绝对期限、同身份会话上限保持原口径。
注销/空账号清理完整覆盖微信额度、验证码、提示、wecom_contact 与审批敏感暂存；identity.I24 等已约定检查按实际登记补齐，不过滤旧不变量。

## 5. 不做什么

不改登录已通过的放行分支、不替换会话令牌协议、不统一重写权限或 middleware pipeline。
不落地 portal 两小时授权、M7 企业微信独立回填驱动、真实短信/微信网络驱动、M3 媒体清理；保留登录已有 unionid 联系关系回填。
不跨层查询财务/订单/交付内部表，不把注销时的事件通知当同步成功证明。
不删除审计、交易、同意记录；注销只清约定个人字段，历史经办人显示已注销用户。
不改 DDL/CHECK、锁表、layers 白名单、公共冻结构件；公共 keyring 新用途须单独核实，不能业务包悄悄新增。
不放松旧 clerk/权限黄金、测试断言、门禁；如账号安全机制实际需要甲类改动，单独 PR 后消费。

后续 W2-13 消费个人设置 API，W2-15 消费人工账号变更与渠道码；接口 schema 先 actual 才写页面。
