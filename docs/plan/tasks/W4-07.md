## 1. 目标

完成套餐/价目修订与积分价模板、计费参数变更集；生效规则和公告同事务，旧账快照不随配置漂移。

- 现状：套餐/参数管理仍有 meta；套餐报价已有 M1 纯计算公口，现种子与按时间读修订可复用，不能另写价格算法。
- 表：plan、plan_revision、price_tier_revision、billing_param；公告只经 config.notices 公口。drama_price_revision 单剧修订属 W3-10，不接管。
- plan 编辑只名称等可变列；新价目是 INSERT 修订，未来有效行只允许官方撤销字段，不 UPDATE/DELETE 历史价格。
- 四档模板100–20000且 S≥A≥B≥C、只有变化档 INSERT，同保存 batchId/时刻；V1.0 模板保存即生效，不加模板定时生效任务。
- 参数按键Zod校验且同请求不重键；值未变不插行；每键至多一待生效行，复用既有事务级咨询锁，不造新 kernel 锁机制。
- 需公告的键同日且≥今天+noticeDays，未传取最早日；先 notices.announce 再插修订、同 TX；enabledCycles 不为空且覆盖上架版本当前/待生效价格。
- 有 tiers 校验 billing.price.edit，有 params 校验 billing.param.edit，两类同存需两权限；部分无权整体零写。
- 参数按 effective_at<=账本时刻读，不登记新切换job；未来撤销联动公告且 preserve历史。已冻结/扣减积分仍取旧 pricing_snapshot。
- 模板变化只影响 template 模式，按实际 content 批量事实端口取受影响剧后发已登记 pricing.drama_price_changed；不直接改 content 表、不重复单剧变价处理器。
- x01 的 cause 以已冻结目录为准；a07 注记中的 tier_template 与 x01 若仍不一致，先报告窄跨文档结论，不能自造枚举或另登记事件名。
- 受控 bank_account/purchase_policy/controls 归 W4-13，不写入 billing_param，不以默认参数覆盖真实财务版本。
