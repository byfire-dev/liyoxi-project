## 1. 目标

各模块已经在自己的 `register.ts` 里登记了不变量与清理项，但没有人去跑。本包在 `packages/services/src/ops/` 交这套机制：

1. **调度**：三个周期任务 `invariant.full`（每日 03:30）、`invariant.quick`（每 10 分钟）、`ops.retention`（每小时），登记在 ops 的 `register.ts`，由任务进程（W0-23）跑。
2. **运行与落库**：一次运行一行 `invariant_run`；违规写 `invariant_violation`，同一检查项对同一对象未解决时只有一行（再次发现只更新最近发现时间）。
3. **三种自愈策略**：`none`、`heal_and_alert`（记自愈时间，仍未解决）、`heal_only`（自愈即自动关闭）。
4. **上报端口**：`invariants.report` 的实现（kernel 定义，ops 实现），写同一张表、同一套去重与自愈口径。
5. **清理**：`ops.retention` 逐项执行各模块登记的清理项，单项单轮限量，结果写在定时器行上。
6. **把已有的检查接进来**（移交表第 5、25 行与各状态文件交给本包的）：`events.I8`、`flow.I12`、`sla.N8`、timers 的 90 天清理已登记，只需被调度；本包补登记：幂等行的过期清理（kernel）、`audit.I2`、`audit.I3`（audit）、config 的五条 SQL 断言 `config.N9`、`N16`、`N17`、`N19`、`N20` 与参数自检 `config.N8`（config）、`staff.I8`（staff）。

后台“系统健康”页的手工触发、处理结论，以及告警规则“不变量校验失败”不在本包（见第 5 节）；本包给出它们要调的用例函数 `runInvariants`。

| # | 验收项 | 命令 | 判据 |
| --- | --- | --- | --- |
| 1 | 空库加种子 full 0 违规 | `pnpm --filter @liyoxi/services exec vitest run src/ops/invariants/`（要本地的 PostgreSQL 与 `DATABASE_URL`） | 带种子的库上用真实装配跑一次 full：运行行 `succeeded`、`violations_found = 0`，执行的检查项里有 config 的六条与 `staff.I8`、`sla.N8`、`events.I8`、`flow.I12`、`audit.I2`、`audit.I3` |
| 2 | 人为造一条违规能发现并去重 | 同上 | 往库里写一个没定义的参数键：full 报出 `config.N17`，对象是那个键；再跑一次仍只有一行未解决，`last_seen_at` 前移，`invariant_run_id` 仍是首次那次 |
| 3 | 三种自愈策略 | 同上 | `none` 不写自愈时间；`heal_and_alert` 写自愈时间、仍未解决，下次没自愈即清空；`heal_only` 自愈即关闭（`resolution = auto_healed`），已有未解决行时关的是那一行；已解决后再次发现新建一行 |
| 4 | 调度口径 | 同上（不连库的一份） | quick 只跑登记了 quick 的；`every: hour` 只在整点那一期、`every: week` 只在周一的 full；`modules`、`codes` 能限定 |
| 5 | 运行本身出错与中断 | 同上 | 一个检查项抛错不影响别的检查项，运行行记 `failed` 与错误摘要；超过完成期限仍 `running` 的行被下一次运行标成 `abandoned` |

## 10. 默认（本任务书定）

1. 检查项一项一个事务：检查、自愈与写违规同一个事务，要么都成、要么都不成；一项抛错只回滚它自己，其余照跑，运行记 `failed`。
2. 运行出错时周期任务的处理器抛错：定时器按登记的次数重试（full 3 次、quick 1 次），耗尽即 `failed` 并由 timers 报 `timer.failed`。
3. `every` 只对定时触发（`trigger = schedule`）生效，按计划时刻判定；发布后、演练、手工触发跑该方式的全部检查项。
4. quick 的 `since` 取上一次**成功**的定时 quick 运行的开始时间（上一次失败时有检查项没跑，起点不能跟着前移）；没有即不限。
5. `ops.retention` 的“每日项在当日第一轮”按计划时刻判定：北京时间 0 点那一期。任务登记 `catchUp`，停机跨过 0 点、1 点前恢复时这一期会补上。
6. 清理项单轮上限 1,000 行；一项一个保存点，出错只回滚它自己并经告警端口报一条，别的项照常提交。
7. 检查项的 `run` 多收第三个参数 `{ now }`（注入的时钟）：config 的断言要“现在”。已有的登记不用改。
8. 上报端口的实现要数据库连接，`register.ts` 是静态的：实现里留一个绑定点，`createRuntime` 与 `buildWorkerServices` 建好连接后绑上；没绑时只记日志。它用连接池直接发一条语句（自己就是一个短事务），不经 `tx.run`，所以调用方在事务里也能报，事务回滚了违规照样留下。
9. `staff.I8` 一并登记（移交表第 26 行原定 W1-01b）：断言已经写好，登记只是一行，免得种子的六条断言里有一条不在框架里。
