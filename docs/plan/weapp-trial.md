# 微信小程序体验版登录准备

本清单收口首轮单老板、单门店试用前的登录准备，不替代部署、微信平台审核或真实商家验收。账号设置与真实手机号组件已经随 W2-13 合入；本轮只补平台登录码失败处理、空协议错误与体验版参数自检，不新增短信登录、后端接口或试用权益规则。

## 本地与平台边界

- 小程序先经已有隐私授权、协议同意，再使用原生手机号组件的一次性 code；另取平台登录码。平台失败不生成或复用本机凭证，原会话与迟到回调守卫保留。
- 普通 H5 明示不支持号码验证。离线场景只验证界面与错误交互，不能证明真实号码授权成功。
- 缺 API 配置或登录协议为空时显示可重试错误；游客浏览仍可用。协议更新后重新阅读与勾选，登录成功保留原返回路径和查询参数。
- V19 手机号验证与 V03 云上传仍按各自外部验证台账执行。本次没有调用真实微信、短信或云端公开接口。

## 构建与只读检查

使用 Node 24，在受控环境提供公开的 `WEAPP_APPID`、`WEAPP_API_BASE_URL`，可选 `WEAPP_VERSION`。不从 `.env` 取值，不把真实密钥交给会话。

```sh
pnpm --filter @liyoxi/weapp trial:check
WEAPP_TRIAL=1 pnpm weapp:build
```

`trial:check` 检查 AppID 格式与 HTTPS 域名根地址，拒绝游客 AppID、保留示例域名、IP、凭证、查询参数与 API 路径；缺配置退出 2。`WEAPP_TRIAL=1` 同时拒绝 H5、watch 和组件陈列构建，在写 project.config.json 或清理旧产物之前失败。既有源码映射分离与包体检查保持执行。

这些静态检查不能证明 AppID 归属、DNS、证书、微信合法域名或后端驱动已经可用。部署后获授权才执行：

```sh
pnpm --filter @liyoxi/weapp trial:check --probe
```

`--probe` 只 GET 引导与登录协议，使用所配客户端版本，不登录、不创建账号、不输出响应体，拒绝重定向；公开接口探测失败退出 1。登录协议须有 1–2 个生效且不同 key 的版本，待生效条目不计入。部署资源与平台配置以 [平台台账](platform-config.md) 的当前核对结果为准，不沿用旧工作树的环境结论。

| --- | --- | --- |
| 微信后台 | AppID 归属、合法域名及隐私申报与实际能力一致 | 待外部核对 |
| 首次登录 | 未同意不请求；拒绝后可重试或浏览；真实授权登录后返回原路径 | 待 iOS/Android |

| 后续试用 | 建档、审核、订购及真实云上传各自完成端到端验收 | 待各包外部验收 |
