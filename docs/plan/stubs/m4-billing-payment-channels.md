# 微信、孤儿与补单共用付款入账入口

| 项 | 内容 |
| --- | --- |
| 状态 | 留桩中 |
| 留桩内容 | 微信渠道、孤儿与补单入账；差异处理 |
| 骨架里的做法 | 只接受对公收款；微信与无付款单交易抛内部错误；差异只开不处理 |
| 登记的工作包 | W1-11a 第二段 |
| 回补里程碑 | M4 |
| 回补的工作包 | G4-A、G4-B（待拆包后填编号） |
| 依据 | W1-11a 任务书第 5、7 节；08 第 7.3 节微信支付、续费升级、退款、对账、发票一行 |

`createPayment(...).applyPayment(tx, { paymentTxnId, ctx? })` 是公共入账入口，W1-11b 对公确认在自己的事务内调用。M1 只接受 `bank_transfer` 的成功交易；微信渠道、没有付款单的孤儿交易立即抛 `INTERNAL`，不误作已入账。数据守卫、付款原状态、收款入账位与 fulfill 操作键三层防重已经实现。

M4 回补 `recordChannelSuccess`、微信付款人/回传数据校验、孤儿开单、恢复补单选项，及成功收款订阅者、查单/对账/未入账扫描等入口。四类差异开单已落地，但差异处理、重试履约后关闭差异、退款、restore 均未实现；处理入口不通过重放 `applyPayment` 自动关闭旧差异。

实现入口与完整约定见 `packages/services/src/billing/payment/README.md`。这项与既有 `m4-billing-fulfill-upgrade-topup.md` 同属计划第 7.3 节 M4 留桩。
