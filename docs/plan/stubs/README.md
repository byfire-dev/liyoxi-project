# 留桩清单（stubs）

依据：[开发计划](../../08-development-plan.md) 第 13 节“留桩清单”行、第 5.7 节“实现进度”行、第 7.3 节留桩清单、第 9.3 节“端口”行、第 10.2 节“四个计数与归属”行。

## 1. 用途

| 项 | 规则 | 出处 |
| --- | --- | --- |
| 记什么 | 故意先不做、用替身、桩或空实现顶替的东西；写明骨架里的做法与回补的里程碑 | 计划 第 13 节 |
| 粒度 | 一项一个文件 | 计划 第 5.1、13 节 |
| 留桩数 | 由 CI 统计，是四个计数之一；M1 起“留桩清单检查”进 PR 必过检查 | 计划 第 5.5、13 节 |
| 与“已落地”的关系 | 接口“已落地”= 挂载了真实处理器 + 至少一条接口层测试引用该 operationId + 不在留桩清单 | 计划 第 5.7 节 |
| 清零 | 回补的里程碑退出前，应在该里程碑回补的留桩为 0 | 计划 第 5.7、10.2 节 |
| 不许留桩 | 内核、账本、鉴权链；提交校验这类正确性逻辑 | 计划 第 7.3、11 节 |
| 不算留桩 | “入口隐藏”的页面不算留桩：不在本目录建文件，单列在页面清单 `docs/plan/pages.md`（该文件由 W0-27a、W0-28 生成） | 计划 第 13 节 |

## 2. 何时登记

| 时机 | 谁登记 | 出处 |
| --- | --- | --- |
| 工作包按计划留桩 | 留桩所在的工作包，在同一个 PR 里建文件，并在 PR 描述的“留桩与偏差”一栏列出 | 计划 第 5.3、7.3 节 |
| 端口的实现方未到 | 定义方先合并接口与空实现；用桩顶替的一方登记 | 计划 第 9.3 节 |
| 服务包里端口实现未到的调用点（通知场景解析、提醒、直记埋点） | 该服务包 | 计划 第 10.1 节 |
| M1 合流 | W1-21 核对留桩清单已全部入库 | 计划 第 7.3 节 W1-21 一行 |
| 回补 | 默认：回补的工作包在同一个 PR 里把该文件的状态改为“已回补”，在“回补的工作包”一行填编号与 PR；文件保留不删。PR 描述的“留桩与偏差”一栏写明（W0-04 定） | 计划 第 13 节只写“一项一个文件”，回补后删不删没写 |

计划 第 7.3 节的留桩清单是登记的范围。本目录随 W0-04 交付时不预建条目：M0 的一项（两条内网探活）由 W0-22 登记，其余由 M1 的各包登记。默认：清单之外要新留桩的，先改计划 第 7.3 节的留桩清单，并按 [changes/](../changes/README.md) 记一条，类别写“留桩”（W0-04 定）。

## 3. 命名规则

本节的命名、第 2 节的时机、第 4 节的计数以本文为准；文件里的键以[留桩登记模板](../templates/stub.md)为准。

默认（W0-04 定）：`<回补里程碑>-<模块>-<短名>.md`，全小写，短名用英文与连字符，如 `m4-ops-probe-funds.md`。模块取 `packages/services` 下的模块目录名；页面形态的留桩写 `weapp`、`admin` 或 `portal`。

- 同一个回补里程碑、同一模块有多项的，短名取不同的。
- 一个回补点一个文件。计划清单里一行有多个回补里程碑的，按回补点拆成多个文件（如建档首页三个聚合项拆三个：成员摘要 M2、素材总数 M3、广告三态计数 M5），里程碑退出时才能按文件核对清零。
- 登记它的工作包写在文件里的“登记的工作包”一行，不进文件名。

## 4. 文件格式与计数

| 项 | 规则 |
| --- | --- |
| 格式 | 复制[留桩登记模板](../templates/stub.md)填写。键：状态、留桩内容、骨架里的做法、登记的工作包、回补里程碑、回补的工作包、依据。不改名、不加列、不调序 |
| 状态取值 | `留桩中`、`已回补` |
| 计数 | 默认：留桩数 = 状态为“留桩中”的文件数（W0-04 定）。读留桩清单的脚本只认“留桩中”的文件，如“已落地”的判定 |
| 里程碑清零 | “回补里程碑”为本里程碑、状态为“留桩中”的文件数 = 0 |
