- 变异重做（都在自己的临时实例上）。核对脚本一侧：第二轮复审另想的 63 种当时放过 20 种，现在这 20 种拦下 13 种，它重试的旧 18 种与抽查的 19 种仍全部拦下；仍放过的 7 种里，6 种写进了 `packages/db/README.md` 第 9 节“已知的限度”（触发器被停用、被删、触发器函数被换成空函数；行级安全两种；给不可登录的角色设口令），1 种按设计只列出（别的角色在常规读写的表上有授权）。第一轮的 30 种仍全部拦下，另加的 18 种里 16 种拦下、2 种按设计列出。迁移一侧：第一轮的 14 种加 5 种全红；第二轮复审试的 36 种红 35 种，不红的 1 种（别的角色在只增表上有 `DELETE`）由核对脚本的用例在同一次 `pnpm test` 里拦下。

没有验的：

- CI：第一轮修订的头 `7a75a6b` 在 GitHub 上跑过一次（运行 37285855895）：`verify` 在“测试”一步红，红的恰是偏差第 2 条那一条，其后各步被跳过；`gate-classify` 通过。所以 `gates:selftest`、密钥扫描等几步在 GitHub 的执行机上还没有结果。第二轮的提交没有推送（由调度会话推），还没有 CI 运行。本地在仓库外的干净克隆里，从 `pnpm install --frozen-lockfile` 起按 `verify` 的顺序整套跑了三遍：照本分支原样，`pnpm test` 恰好红偏差第 2 条那一条，其余各步都过；在克隆里变基到 PR #32 的合并提交 `31ddc8d` 上，各步都过；做的过程中 main 又合了 #33、#30，再变基到当时最新的 main `41478c3` 上（多“登记表对账”“枚举与库 CHECK 一致”两步），各步也都过。变基时 `package.json` 的根脚本末尾（1 处）与 `CLAUDE.md` 第 9 节（3 处）有冲突，两边都是加行，都留；`CLAUDE.md` 最后一处要取本包 `pnpm db:verify-grants` 那一行的新写法，不要留成两行。变基之后 CI 会跑后台冒烟（根 `package.json` 在它的受影响范围里，与本包的内容无关）：本机没有 Playwright 要的那一版浏览器，没有下载，改用已装的 Chrome 跑通。
- 托管库上没有跑（V5 等 E4 的实例）。ADR“理由”末尾列了九项留给它实测；其中管理账号不是超级用户的几种在本地另一个临时实例上试过。
- 版本：17.11、16.15、14.21 实测过（上面“已做的”）；15、18 没有跑。16 上钩子的用例过不了：`pnpm db:verify-managed` 自己只认 17（W0-05 定的）。

合并后别的会话要知道的：

- 迁移目录多了一个迁移：共享实例上的 `lyx_migrate_check` 要再跑一次 `pnpm db:deploy`。跑过之后，还没同步 main 的分支上 `packages/db/src/index.test.ts` 会红（它拿迁移目录与库里的记录逐个对），同步 main 即好。
- 实例上从此有 `lyx_app`、`lyx_readonly` 两个角色（整个实例共用，不可登录；删库不会删角色）。
- 加表、加以属主身份执行的函数：在建它的迁移里补授权，并在 `packages/db/src/grants.expected.json` 里加一行，否则 `pnpm test` 红（权限测试与核对脚本的用例都读它）。加自增列另改 `packages/db/src/grants.test.ts` 里的清单。`infra/ci/` 下的核对脚本与它的用例是门禁文件，不用改也不要改。做法见 `packages/db/README.md` 第 9 节与 ADR。
- 受限的表（不是全套读写的，或只增表）另要在下限清单 `infra/ci/grants-floor.txt` 里加一行，漏了 `pnpm test` 红；加行是只增，与迁移放同一个 PR。要放开一张已登记的表，先开单独的 `gate-change` PR 把那一行的上限改大，合并之后再改迁移与期望。
- 加视图、物化视图：应用要查它才授 `SELECT`，并在 `grants.expected.json` 的 `views` 里登记；只读角色自动带上，不用写。
- 应用与备份的登录账号要另建并加为 `lyx_app`、`lyx_readonly` 的成员；不要把这两个角色改成可登录（核对脚本会报不通过）。登录账号不要给超级用户、不要带 `ADMIN OPTION`、不要再加入别的角色、不要当库的属主；平台收回了库的 `CONNECT` 时把它授给这两个角色。这几条核对脚本都查（给 G2-D）。
- `pnpm db:verify-grants` 核对预发、生产上的库要加 `--database <库名>`，用跑迁移的账号跑；服务器要 PostgreSQL 16 及以上。
