第一段于2026-11-04交付`spikes/weapp-probe`独立工程：四页Taro探针、Hono四组端点与真实最小Provider/替身、受限STS、写前脱敏、fixtures/report、README/CHECKLIST。新增按路径触发的独立workflow，不接入required；CLAUDE第9节补命令。根workspace、根package和根lock不变。没有从固定参考库借源码，没有依赖应用/services/contract包。

本地只用fake/注入假HTTP和假平台：独立冻结安装、`typecheck`、`test`、`build`通过，四页产物可导入开发者工具；5个测试文件共31例通过；实际fake服务进程启动后health/desktop均200，SIGTERM自然退出0，fake fixtures/report命令均退出0。类型提升检查对独立app通过，根格式/ESLint规则作用于新增源码通过。测试覆盖四组端点、密钥守卫、扫码过期/错配、对象范围/大小、统计、下载并发/恢复/清理和凭据刷新失败。最终命令结果交调度，远端CI链接待草稿PR运行后补。不读取任何真实凭据或原始日志，不带真实配置启动、不调真实付费接口、不生成上传真实测试片、不部署/发布。真实HTTP、三台真机、蜂窝可达性、合法域名复测均未验；无结论ADR、退路决定或V关闭变更。

唯一独审指出离线fake记录与恢复队列可在切换real服务后污染统计；2026-11-04已修复：尝试、下载队列和上传恢复状态在创建时绑定模式与服务地址，补传/恢复时校验当前服务；不同模式、不同地址和缺少来源的旧数据保留在本地隔离区，不改标、不计入新轮次。服务端拒绝缺少或不匹配的probeMode，写盘保留原模式。新增确定性回归覆盖fake离线→real汇总隔离、fake已保存队列→real重开从零及旧/跨来源上传恢复；本轮类型、格式、ESLint、31例测试和四页构建均通过。

## 偏差

| 原要求/事实 | 处理 |
| --- | --- |
| 独立安装中Taro Vite4被提升为Vitest4的peer，测试启动缺`vite/module-runner` | probe根显式使用本仓库已有Vite8.3.1供Vitest，app仍Vite4.5.14；调度已确认这项小偏差。两个Babel构建插件7.29.7（根锁已有）也显式声明，避免依赖根提升；只改独立锁 |
| X-01要求下载并发2、两种落盘与全档压力；D7生产user_dir降级为并发1/≤150MB | 探针按任务书测并发2与全档，README明确它不是生产降级参数，结论需区分模式 |
| `ListMultipartUploads`为桶级动作，D5第5.4节已列桶级语句加前缀条件的可选方式 | 根据官方COS策略/条件键文档独立语句+`cos:prefix`严格等于当前对象键；写权限仍仅`incoming/{fileId}/*`，不据替身宣称真实STS越权验证已通过 |
| 微信官方文档页面本轮抓取受限；尚未真实调用 | 对照任务书与main已合微信驱动的稳定版接口形状，README保留官方链接和获取限制；假HTTP用例不替代真实联调 |
| 测试片需要精确体积且不消耗长视频编码时间 | fixtures由业主生成竖屏H.264/AAC、moov前置短片，用MP4 free box补齐十进制MB；用于传输/相册字节边界，不据此推出长视频播放或码率结论 |
