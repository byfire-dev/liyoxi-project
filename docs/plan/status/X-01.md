## 偏差

| 原要求/事实 | 处理 |
| --- | --- |
| 独立安装中Taro Vite4被提升为Vitest4的peer，测试启动缺`vite/module-runner` | probe根显式使用本仓库已有Vite8.3.1供Vitest，app仍Vite4.5.14；调度已确认这项小偏差。两个Babel构建插件7.29.7（根锁已有）也显式声明，避免依赖根提升；只改独立锁 |
| X-01要求下载并发2、两种落盘与全档压力；D7生产user_dir降级为并发1/≤150MB | 探针按任务书测并发2与全档，README明确它不是生产降级参数，结论需区分模式 |
| `ListMultipartUploads`为桶级动作，D5第5.4节已列桶级语句加前缀条件的可选方式 | 根据官方COS策略/条件键文档独立语句+`cos:prefix`严格等于当前对象键；写权限仍仅`incoming/{fileId}/*`，不据替身宣称真实STS越权验证已通过 |
| 微信官方文档页面本轮抓取受限；尚未真实调用 | 对照任务书与main已合微信驱动的稳定版接口形状，README保留官方链接和获取限制；假HTTP用例不替代真实联调 |
| 测试片需要精确体积且不消耗长视频编码时间 | fixtures由业主生成竖屏H.264/AAC、moov前置短片，用MP4 free box补齐十进制MB；用于传输/相册字节边界，不据此推出长视频播放或码率结论 |
