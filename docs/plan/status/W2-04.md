## 偏差

1. 实际 WecomProvider 缺扫码 code 换 userid 的公共能力。经调度批准只补 `exchangeWebLoginCode({ code }) → ProviderResult<{ userid }>`、真实公开方法清单/外呼guard、不配置实现及本地fake/samples回归；不接真实驱动或改配置/依赖。默认手填审计 manual，不声称平台核验。真实驱动归 W2-31 所拆 G7-A，非 W2-19 消息页面。
2. 正式 a01 第3.41节合法目标 agreement_consent 未在 AUDIT_TARGET_TYPES 登记。经批准只在数组末尾添加并回写03分组；实际来源写侧 `docs.assertConsents` 原样复制 merchant_user.phoneEnc / entity.usccEnc，兼容读按原始AAD解密，授权独立走同意记录主体scope。真实两种来源及启动自检已验证，不改写侧或加密协议。
3. 正式 a01 要求 PII 超限details/告警，原中间件只抛无details的429。经批准仅该operation的专用档位超额分支加入实际window/limit及告警尝试；RateLimited可选details，旧分支、配额、顺序保留。Redis降级按实际减半额度，维度只员工id；alerts未配置持久实现，不宣称已送达，告警失败保留429/Retry-After。
4. 既有 `admin.auth.me.confirmTotp` 的幂等理由明示恢复码重放脱敏，机器登记遗漏。经批准补本路由 `x-redact-on-replay: ["recoveryCodes"]`，所以不能笼统称metadata零改；其余既有冻结字段不变，docs-check零差异。真实HTTP同键重放null且幂等库不存恢复码明文。enroll/confirm复用原专用档位，没有重复加rate-limit元数据。
5. L0 kernel PII端口若type-import authz.DataScope会形成禁止的循环。经批准端口持opaque unknown，既有 `assertIssuedScope(unknown)` 公口恢复真实WeakSet签发scope并保留原TypeError，authz/index追加出口；不改判定、scope算法或layers规则，真/伪handle回归已补。
6. 审计自身能证明的归属仅staff操作员。采用调度批准的窄默认：own/group只见ctx.scope.staffIds对应staff actor行，未知merchant/system归属不扩大可见；详情同口径404，无L0反向查业务表。同意真实来源组合测试放本域 `docs/pii-fields.db.test.ts`，其余L0测试复用testing公开helper，不放宽层规则。
7. 新API的后台权限golden由既有生成器增加10行，旧表头/角色格逐行保持；gate-files只追加其append登记。真实分类由调度在提交后验证，若loosen停止。作者跑gates:selftest首次未给DB环境失败；实际框架部分反例需lyx_selftest库和默认lyx_migrate_check，调度随后准许原脚本的专用自测库，但本轮不再全量重复；缺省lyx_migrate_check环境不由作者另建，交正式CI核验，未改规则绕过。
