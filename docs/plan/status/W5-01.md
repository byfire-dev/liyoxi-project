## 偏差

实际 main 的唯一 executeCancel 仅支持广告，订单所需 ticket.terminate、发布终止、既有 ZIP 失效、系统跟进关闭与未登记 producer 的审批执行事件尚缺。由调度限定补齐所属域最小事务公口与机器接线（delivery/publish/media/staff/approval），不新增 W5-02 提交审批 producer，不提前实现 M6 API；共享 index/runtime 仅本包装配。执行结果读取需要 support 同主体门店的客服引用只读公口。不修改原权限定义、层白名单、全局锁序或 DDL。admin-matrix 用官方命令生成，仅新增 execute 对应行；既有五个 owner 事件只补严格载荷 schema，不新登记事件。

Q9 已由 #203/#205 实现播放器及窄恢复，不在本包重复。E8/E11与签后V12仍按外部台账，不因替身成功或文书合并关闭。

任务书“全部业务迁移后退款”与“终态及实际退回数同次 UPDATE”在现有 CHECK 下不能字面并存：本包先关闭全部 owner 资源，后按账本实际结果同次更新各项/广告终态与金额，均在一个事务；父订单售后指针和派生状态也同次更新。`resultSnapshot` 的三去向来自实际 ReturnResult，实际逐批明细未由账本提供，`lots=[]`，与预览区分；已回写 a05、09 和 order README。

测试仅将未实现 W5-02 的提交审批输入准备为合法快照，未伪造成功资金、媒体已检或执行终态；W5-02 必须补真实 producer 集成。

调度批准本次单机制超出约600行的默认体量：非生成非测试源码约2072行新增、102行删除，主要增加实际 main 缺失的各 owner 收尾、完整回执和授权校验。保留一个资金事务与一次原子合入，不混入后续申请 producer、页面或新业务机制。
