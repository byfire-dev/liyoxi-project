## 缺字与诊断

缺字是确定性失败：该次认领将版次置已有 failed，不浪费四次相同渲染；后台提示
修正资料或字体后重试。字体修正重试同版，资料修正新建不可变版次。
无材料/字体/正式正文配置保持 queued，不把缺配置消耗成失败。

无新增数据库列/技术状态/API。缺字和清除结果在同一认领条件事务追加 audit，
使用已登记 license_letter 目标，meta 带 revisionId/认领身份。授权书下载也以
该目标携带 revisionId 留痕，不能使用未登记的 license_letter_revision 审计目标。
诊断最多32个不同码点、每项最多4个固定字段路径，完整 meta≤8KiB；超出部分
明确给出总数和截断标记。业务读侧先判权限，再读最新实际认领结果，服务重启不丢失；
成功或再次认领后不显示历史错误。普通运维日志只写受控分类。

## 文件和生命周期

完成时重新检查租约/认领序号/法律事实；当前版本只向较新 ready 版移动。
最终签署字节计算哈希，对象键包含版次和该哈希。迟到完成不能覆盖当前版本。

数据模型原文“条件更新0行即删除刚上传对象”不适用于现有 putSystemFile：
该公口会按确定对象键复用已登记文件，同内容的其他认领可能已经引用它。
本包保留已登记但未被引用的对象，交已有 media 保留与清除流程处理；后续同内容
重试可安全复用。禁止绕过引用、保留期与清除规则直接删除可能属于胜出认领的对象。
上传成功但数据库登记未知的对象同样不臆造删除成功，保持存储的既有未知结果语义。

先停止 docs 准入并取消、等待真实在途操作结束，再关闭渲染/签署/材料读取，最后
关闭事实、转换器、存储等依赖。Storage.putObject 无取消口，等待真实完成而不是
用 Promise.race 假装取消。原消费者30秒预算及 M1 90秒总判据不放宽。
