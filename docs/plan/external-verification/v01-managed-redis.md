## 怎么跑

在能连到那个 Redis 实例的机器上（有本仓库的检出，已 `pnpm install --frozen-lockfile`）：

```sh
export REDIS_COMPAT_URL='<实例的连接串>'   # 只放在这个环境变量里：不入库，脚本不打印它
pnpm redis:compat
```

- 全程约 65 分钟：第 2 项要让消费者空转 60 分钟。先想快速过一遍可以加 `--idle-minutes 1`，正式的结论用缺省值。
- 第 3 项（主从切换）、第 5 项（写满）会停下来等人：按提示在云控制台操作，做完回车；输入 `s` 跳过，该项记“需人工”。
- 第 6 项（数据全丢后的自愈）在不是本机的实例上不自动做：确认可以之后加 `--allow-wipe`。它只删脚本自己前缀 `lyx:compat:` 下的键，不用清库命令。
- 跑完逐项打印结论（通过、不通过、需人工），报告写在 `apps/worker/dist/redis-compat-report.json`（可用 `--report <路径>` 换地方）。输出与报告里都没有连接串、主机与口令。
- 把那份 JSON 回传给调度会话或维护会话，由它开台账 PR 把结论、证据记到本文件。有“不通过”：走“每节点自建 Redis”的退路，开变更工作包。
- 七项对应 [D7](../../appendix/design/d7-platform.md) 第 7.3 节的验证清单。第 6 项在这个脚本里只验“队列的键没了之后消费者不重启也能恢复”；“各队列在途任务 30 分钟内继续”由 `apps/worker/test/fault/redis-flush.test.ts` 在每次 CI 里验。

业主事项的状态见 [业主清单](../owner-checklist.md)。填写规则见 [README](README.md)。
