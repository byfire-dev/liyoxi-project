# 本文 ADR-041 审核版本取到的版本类型

| 项 | 内容 |
| --- | --- |
| 编号 | 本文（ADR-041） |
| 来源 | [计划](../../08-development-plan.md) 第 8.6 节表二；[ADR-041](../../adr/0041-预发先行-单机预发-共用AppID.md)“决定”第 3.1 节 O4、第 4.9 节 |
| 验证什么 | 审核人员用的版本取到的是开发版、体验版、正式版里的哪一种（请求头 `X-Env-Version`），连的是哪套后端 |
| 通过标准 | 取到的是正式版：建生产后按版本类型选后端时，送审版本与正式版连同一套后端 |
| 依赖的业主事项 | E2、E3；一次提审（V2 试提审即可） |
| 谁来做 | G2-D 的环境包 ⑨ 出最小可提审版本；业主提交审核；审核期间按送审版本号筛预发的访问日志，读 `X-Env-Version` 的取值 |
| 最晚关闭点 | 建生产后第一次提审指向生产的版本之前；建生产之前不受影响。不通过：送审包改为构建时固定指向生产 |
| 不通过的退路 | 送审包与正式包在构建时固定指向生产，不在运行时按版本类型选（D7 第 7.1 节原来的退化方案） |

备注：业主 2026-10-04 的说法是用“开发版、审核版、线上版”隔离预发和生产。小程序接口给出的版本类型只有开发版、体验版、正式版三种，审核版本取到哪一种没有核实；把业主说的三种版本对应到版本类型是会话的理解。生产建好之前只有一套后端，本项不挡任何包。本项随 V2 试提审一并验：V2 的最晚关闭点是 M8 进入前，所以本项可在 M8 进入前关闭，赶得上计划 第 6.11 节 M8 进入条件对表二各项的要求。
