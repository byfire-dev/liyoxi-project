## 执行方法（W2-29，待业主执行）

1. 在选定的实际 main 提交上完成平台核对表第6节17项；第17项先确认退役责任与流程。E3/E5须为完成，四个具名支付/媒体包、M0/M1/M2接口及真实预发健康均满足。缺项时停止，不填写虚构凭据或完成事实。
2. 由业主打开仓库与节点的冻结，核小额演示价目、审核测试主体白名单和自动退款。review-flags只写与契约默认不同的键；购买入口是受控财务策略，不在feature flag清单里。按当前合规默认同时核对微信与对公入口。
3. 手动触发送审上传，输入完整main提交和X.Y.Z；流程核readiness、创建weapp-v标签，再调用节点机器人2。消费同提交正式制品，不另造构建变体。仅确定尚未进入上传的失败可核同SHA后删除本轮标签；一旦调用节点，SSH失败或回执丢失/不符都不能证明未上传，保留标签、人工核对，禁止自动重试，避免移除仍在役版本的兼容保护。
4. 业主在微信后台把机器人2对应版本设体验版（自动更新体验版能力尚待核）；只给内部体验成员。三台设备按真机清单在Wi-Fi/4G回归，填同版本记录与P0结果。
5. 业主把本次审核说明、测试账号直接填审核后台并提交。文档不记口令；同步核手机号组件和O4。审核期间不恢复导入、不清Redis、不放大数据，保持白名单测试资料可用。
6. 结果记平台配置第7节往返记录及本文结论/证据/关闭日；支付定性仅能记录“目前未被判定”。过审后不发布；结束后由独立PR登记retired.json，核兼容后解冻。

本包只交源码与方法，未上传、设体验、提审、操作平台后台或验证真实支付。本项仍未开始；本机替身目标不能作为平台结论。
