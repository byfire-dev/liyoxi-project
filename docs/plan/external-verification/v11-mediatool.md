备注：抖音、视频号的上传页能否读到写入的标识（D5 第 16 节 P9 的后半）不在 X-02 里验：业主把加标后的片子各传一次，结果由维护会话记到这里。业主的真实样片到了之后放 `~/.lyx/samples/x02/`，重跑 `pnpm mediatool:verify` 加测。开发机上把 mediatool 的内存上限调到 256MB（不给交换区）时约 200MB 的片子三个操作照常，调到 128MB 时加标的 ffmpeg 被内核杀掉、服务继续可用：预发调低上限时参考，以预发复测为准。

预发是单机，不是生产同款拓扑；节点内存 1.87GB，`mediatool` 的内存上限在预发调低并依赖交换区（[ADR-041](../../adr/0041-预发先行-单机预发-共用AppID.md)）。预发节点与对象存储跨云，下载与回传都走公网：预发复测要分别量下载、回传两段耗时，以及传输期间接口的时延，必要时给 worker 的传输限速；节点的公网带宽没有核实。M3 按实测再定是否升配。

业主事项的状态见 [业主清单](../owner-checklist.md)。填写规则见 [README](README.md)。
