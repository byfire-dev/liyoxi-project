# 复审模板

依据：[开发计划](../../08-development-plan.md) 第 5.3 节“复审”“合并条件”行；[README.md](../README.md) 第 3.5 节第 2、3 项。2026-10-05 按业主的话精简过（[变更记录](../changes/plan-lean-process.md)）。

## 1. 怎么用

| 项 | 规则 |
| --- | --- |
| 几轮 | 每个 PR 一轮、一份，甲类也是。限时，时长由调度会话派工时给；到点就交 |
| 谁做 | 调度会话启动的、没有参与实现的会话。不改代码，不推提交，不碰 PR；全文交给调度会话贴到 PR 评论 |
| 看什么 | PR 差异、任务书、`CLAUDE.md` 第 6 节。只找真问题（第 2 节） |
| 不做什么 | 不整套重跑：CI 跑过的看 CI 运行的结论，要验证一个具体的怀疑时才跑那一条。不逐条抄任务书对表。不挑措辞、命名与文书格式 |
| 阻断项修完之后 | 不再补一轮复审：由 CI 把关，修得对不对由调度会话判断 |
| 意见不一 | 复审与作者意见不一时由调度会话定 |

## 2. 什么算阻断项

只有这四种。别的意见写进“备注”，至多 5 条，挑最要紧的。

| 类别 | 什么算 |
| --- | --- |
| bug | 会出错的代码；测不到它声称测到的东西的测试 |
| D 违反硬性规则 | `CLAUDE.md` 第 6 节任一条（沿用原来“D 类”的叫法） |
| 验收核心没做到 | 任务书“验收”要的东西没有实现，或 CI 没有跑到它。证据的格式、文书填没填全不算 |
| 门禁放松而理由站不住 | 放松类改动出现在工作包 PR 里（硬性规则 22）；或单独的 `gate-change` PR 说不清放松了什么、为什么 |

超出任务书范围、体量超限、与任务书的出入不是阻断项：写进备注，由调度会话定。

## 3. 评论模板

```markdown
## 复审：<编号> <名称>

- 复审的提交：<提交哈希>
- 结论：无阻断项 / 有阻断项 N 条

### 阻断项

1. <类别>：<文件或位置>。<问题>（依据：<文件 第 N 节>）

### 备注（至多 5 条）

-

### 没看的范围

<!-- 如实写：没读的文件、没法在复审里验证的事（真机、外部账号、带密钥的运行）。 -->

-
```
