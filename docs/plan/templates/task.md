# 任务书模板

用法：复制为 `docs/plan/tasks/<编号>.md` 后填写，删掉本段与各处的填写说明。依据：[开发计划](../../08-development-plan.md) 第 5.3 节“任务书”行、第 7.1 节。

- 任务书要自包含。会话不带记忆，只凭任务书、`CLAUDE.md` 与状态汇总开工，不向业主追问。
- S、M 包可以是“清单行 + 模板补全”：把计划第 7 节该包的一行抄进“清单行”，再补全其余各节。L 与甲类包单独成文，业主过目。
- 引用文档写“文件 第 N 节”，不写行号。不排日历日期。
- 计划里已写明的规则照抄其含义；计划没写而必须定的，写成“默认：……（本任务书定）”。
- 补全任务书前先查 [tasks/README.md](../tasks/README.md) 第 5 节的移交表：别的任务书交给本包的事项，写进“目标”与“验收”。本包要把事项交给后面的包时，同 PR 往移交表加行。
- 任务书另加了计划依赖列没有的前置时，按 tasks/README.md 第 6 节办，不只写在任务书里。

## 9. 交付与收尾

- 一个工作包一个 PR；超过可评审体量（计划 第 5.3 节“粒度”行）即拆成 a、b 两个可独立合并的 PR，并记一条计划变更。
- PR 描述按 `.github/pull_request_template.md` 填全。
- 同 PR 更新 `docs/plan/status/<编号>.md`。
- 先交付可读的中间成果；遇到阻塞即停，把原因写进状态文件并报告。
- 不自行合并。
