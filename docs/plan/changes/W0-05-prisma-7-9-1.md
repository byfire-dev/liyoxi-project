# Prisma 的锁定版本由 7.10.0 退到 7.9.1

| 项 | 内容 |
| --- | --- |
| 改了什么 | [开发计划](../../08-development-plan.md) 第 5.2 节技术栈固定表“服务端”一行：Prisma 7.10.0（三包同版） → Prisma 7.9.1（三包同版）；文末修订记录加一行。同一个 PR 里跟着改的不在计划里，列在这里备查：[02](../../02-tech-selection.md) 第 2、3.3、5.2、5.5 节（锁定清单三行连同发布日期，行数没有增减）；`CLAUDE.md` 第 4 节同一格；[06](../../06-data-model.md) 第 1 节“校验结果”、`docs/data-model/README.md` 的文件清单、`docs/data-model/working/catalogue.json` 里写校验所用版本的一句；`tools/schema-check` 的 `package.json`、锁文件、`README.md` 与 `check.py` 开头的注释；W0-05 任务书 第 2、4、6 节；[D7](../../appendix/design/d7-platform.md) 文末勘误加一条（正文未改）。包数、规模、级别、依赖、接口数都不变 |
| 原因 | 业主 2026-10-05 定，原话：“Prisma 版本：退到 7.9.1。”起因是 W0-05 装依赖时被仓库自己的可信级别检查（`pnpm-workspace.yaml` 的 `trustPolicy: no-downgrade`）拦下：命令行包 `prisma@7.10.0` 由 `prismabot` 账号发布，没有可信发布者，也没有来源证明；7 线上此前的正式版（7.0.0–7.9.1）都由可信发布者发布并带来源证明；7 线上没有 7.10.1。三个包的 7.9.1 都发布于 2026-07-27，都带可信发布者与来源证明。两条路（加豁免、换版本）里业主选了换版本，不加豁免。02 第 5.5 节锁定清单的规则是“主次版本不动”，7.9 换了次版本，所以按计划变更记，先改文档里的写法，再由 W0-05 照着装 |
| 影响的包 | W0-05：阻塞原因解除；任务书 第 6 节钉的版本改为 7.9.1，装依赖不需要可信级别豁免；`tools/schema-check` 的两个文件已对齐，任务书 第 4 节那一行开工时不用再动；依赖、规模、级别不变。之后连库的包（W0-05b、W0-06a、W0-06b、W0-07 等）：照锁定清单装 7.9.1，交付不变。W0-07：05 第 5 节 V4（Prisma 7 交互式事务里的保存点）届时在 7.9.1 上验。关键路径不变 |
| 类别 | —（拆并、顺序、估算、归属、留桩五种都不合：改的是技术栈固定表里的一个版本号） |
