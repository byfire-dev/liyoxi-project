# W2-29：独立提审上传与受限版本日志前置

| 项 | 内容 |
| --- | --- |
| 改了什么 | 新增冻结后机器人2节点入口、同源制品消费者和固定SDK调用；网关补受限客户端/环境版本日志。原机器人1开发上传保持独立。 |
| 原因 | 原入口仅接收sha标签、机器人1且冻结时拒绝；原网关没有记录两版本头，不能支持提审与O4统计。 |
| 影响的包 | W2-29；任务书、清单、readiness、分组统计与工作流继续由本包交付，此前置不代表可提审或已上传。 |
| 类别 | 边界 |
| PR | 本地codex/w2-29-review-upload-prereq；正常提交后交唯一非作者审查，远端由ROOT串行处理。 |

节点新增 `weapp-review-upload <40位source> <64位manifest摘要> <weapp-vX.Y.Z>`。每个版本段为0或无前导零的1–6位非负整数，拒绝路径、命令和额外参数。必须明确启用、已配私有桶、`STG_FREEZE=true`、当前部署为对应sha标签；缺条件失败，不跳过。固定COS工具、私有两对象、摘要与安全解包、上传器镜像事实和成功发布记录沿用原消费者检查。只将上传私钥只读挂到一次性容器，不挂COS凭据或整个节点目录。

共用事实验证从原消费者原样抽出。机器人1的入参、sha版本、冻结拒绝及结果不变。机器人2消费者独立加载固定2.1.31 SDK，只接收固定项目/密钥挂载路径；SDK版本为标签去前缀后的X.Y.Z。回执同时保留tag、完整source、原制品的sha客户端版本与robot=2。不会为提审重构建变体或改客户端版本头，也不在节点中创建Git标签。

网关的 `client_version` 仅接受sha12、上述语义版本或其weapp-v标签，其余为unknown；`env_version`仅接受develop/trial/release。JSON日志仍不记查询串。两字段是客户端诊断信息，不能作为鉴权、真实平台环境或提审通过证明。O4由后继工具通过tag/source/sha版本绑定并按环境分组核对。

本机新增6个目标、原消费者受影响2个目标通过；infra类型、Bash语法、ESLint/格式和缓存gateway镜像的真实 `nginx -t` 通过。SDK与凭据均为公开测试替身，无真实云/上传/提审；旧接口其余未受影响目标未重复。首轮lint仅测试的两处类型import语法失败，按现有规则修正后通过，不改规则。唯一独立审查及最终分类由固定提交核对，未宣称远端CI完成。

工作流的凭据消费者若被官方判为放松，另走独立gate分支；本片不改工作流、受信凭据名单或原门禁。真实配置、出包、设体验版与提交审核仍按原业主清单执行。
