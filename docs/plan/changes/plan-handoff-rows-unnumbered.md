# 移交表新加的行不再编号，首列写“—”；台账 PR 在行尾括注办结

| 项 | 内容 |
| --- | --- |
| 改了什么 | [tasks/README.md](../tasks/README.md) 第 5 节（移交表）的两条做法，开发计划正文没有改。① 原来：新行接着往下编号，别处按“移交表第 N 行”引用。现在：新加的行不编号，首列写“—”，加在所属小节的表尾；引用时写“接收方是某某的一行”。已有编号的第 1–66 行编号不变，照旧可以按行号引用。② 原来：“办结后在本包状态文件写一句，本表不回改”。现在：各包照旧不回改本表；台账 PR 整理时在行尾括注办到哪了，不删行。同一个 PR 里顺带做的：三行重号改成第 64、65、66 行（原来分别与第 62、63、61 行重号），按行号引用它们的两份状态文件（W1-06、W1-10）跟着改；照各状态文件的“往后移交”补 27 行（M0 的 10 行、M1 及以后的 17 行），都不编号；24 行已有的行加了括注。[任务书模板](../templates/task.md)文首说明与 tasks/README.md 第 7.4 节各补半句 |
| 原因 | 几个会话并行往表尾加行，各自取“下一个号”，合并后第 61、62、63 号都各出现过两次（W1-01a、W1-03、W1-06、W1-10 的 PR），状态文件里写的“移交表第 62 行”指不准是哪一行。W0-22、W0-29 为了不撞号干脆没有往表里加行，改成在状态文件里写“请调度会话补”；连同表不在允许目录里的几个包，共有八份状态文件的“往后移交”一直没进表。不编号就没有号可撞。括注是因为表越来越长，接收方分不清哪些行已经办掉。调度会话定，业主事后看 |
| 影响的包 | 各包的依赖、顺序、规模、级别都不变。之后每个往后移交事项的包：加行时首列写“—”，引用时写接收方。W1-06、W1-10：状态文件里的行号改了（第 62、63 行改第 64、65 行；第 61 行改第 66 行）。W1-01b：移交表第 26 行的前一半（登记 `staff.I8`）已由 W0-24 办掉，任务书第 4、7 节两处行内改成“不再登记” |
