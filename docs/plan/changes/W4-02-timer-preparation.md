# W4-02 到期关单的事务外准备前置

微信关单必须在事务外查询渠道；现有主体定时器处理器与完成标记同事务执行。
只包裹 worker 的队列入口会漏掉 Redis 不可用时的关键定时器进程内执行。

调度批准独立增加 `TimerRunDeps.beforeRun(ref)` 可选端口，两条运输路径共同经过
`runTimer`，在原业务事务前等待准备；失败沿原失败短事务及退避。原主体事务仍重读
认领序号与状态，处理器、完成标记、锁序与 job 模式均保持。调用方必须核对真实认领、
主体和期限，允许重复准备；此端口不授权跳过业务守卫或直接完成定时器。

W4-02 仅接入自己的 `po.expire` 准备，其余任务无操作。本前置不调用真实渠道。
一个真实库目标覆盖队列、关键类进程内降级、外呼不在事务、失败原退避以及准备期间取消。
结果随本分支实际验证记录，不扩大原测试轮次。
