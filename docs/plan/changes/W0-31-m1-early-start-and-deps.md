| 项 | 内容 |

| 原因 | 业主 2026-10-05 晚的原话：“这个进度太慢了，你做了大量的没必要的确认和验证。接下来的大部分情况，你都无须让我确认。我是希望你能尽快把系统开发出来，这样我能尽快给你反馈。”①⑤ 是调度会话照这句话定的，不是业主的原话，业主可以改回：M0 还剩合流、看样与几个没合并的包（定这一条时是 W0-22b、24、25、29、30），而 M1 的后端包大多只用得到已经合并或在排队的内核包，等 M0 整体退出是空等。② 是把“M0”展开成实际用到的包，并补上清单行漏写的 M1 内前置（多数是“原来经别的包间接带上，现在点名”）。④ 是这些包估出来的非测试代码超过第 5.3 节“粒度”行的上限（甲类一个机制约 600 行、乙类 20 条接口、丙类 8 页），照该行预先拆好，免得开工后再停下来商量 |
| 影响的包 | M1 全部 27 个包与 W0-31：依赖见下表，顺序由“等 M0 退出”变为“依赖齐了即可”。规模只有 W1-23 变了；级别都没变。预拆的包：第一个 PR 合并时状态写“进行中”，最后一个写“完成”；只等第一个 PR 的下游在“依赖”里写成文字条件，汇总脚本把它列在“另需核对”。体量仍超上限而没有再拆的三处留给调度会话定：W1-04 的第一个 PR 约 1,100 行、W1-15 的第一个 PR 约 1,200 行、W1-08 的第一个 PR 约 1,900 行（乙类，按接口数 13 条不超） |
