# 补发期间成片批次上传授权修复

| 项 | 内容 |
| --- | --- |
| 改了什么 | 工单在 awaiting_launch、launch_verify、in_service 且有本工单同范围 open 补发时允许成片批次上传准备 |
| 原因 | W5-13 真实初包推送及补发创建成功后，批次创建仍被旧的仅首次交付守卫以 409 拒绝 |

上传准备仍以订单项为目标，不隐式绑定某次补发。实际成片登记继续在工单锁内校验显式 reissueId、同工单/主体/门店的 open 状态、补发集号范围和真实媒体/批次就绪事实。普通 media 批次 commit 仅用于原片，成片仍由 delivery 消费事务建立引用后提交；本片不改变这些路径。

新增定点数据库回归沿真实初包交付、补发创建、批次创建/开始和补发取消验证；无 open 或非本工单剪辑师不能新增，取消后继续上传和登记均拒绝，缺显式补发 ID 或未完成媒体不能提交，旧当前成片保持。新增目标 1/1 通过，原文件其余 12 项未选取；services 类型检查通过。新增输入修正了范围外员工的 NOT_FOUND 期望及 schema 默认的 isContentChanged=false，原守卫与断言不变。本片待唯一独立审查和远端 CI；完整替换质检和补发发布仍由 W5-13 后续真实浏览器链路验收，不将本片写成整包完成。
