# 留桩、变更、外部验证三张汇总不入库：需要时现生成，CI 只核对单项文件合不合规

| 项 | 内容 |
| --- | --- |
| 改了什么 | [开发计划](../../08-development-plan.md) 第 9.3 节“台账”行。原来：状态汇总不入库，“其余汇总表按生成物处理”（入库，冲突时变基后重新生成）。现在：留桩、计划变更、外部验证三张汇总同样不入库，用 `pnpm plan:summaries` 现生成到各目录的 `SUMMARY.md`（被 git 忽略）；CI 的 `verify` 加一步“台账单项文件核对”（`node infra/ci/plan-summaries.mjs --check`），只查单项文件的键、状态取值、回补里程碑合不合规。修订记录加一行。[docs/plan/README.md](../README.md) 第 1、3.3、4.4 节与三个子目录的 README 跟着改。里程碑范围、退出条件、前提、包数、规模、接口数都不变 |
| 原因 | [移交表](../tasks/README.md)第 9 行 ⑧ 让 W0-30 定这三张入不入库。入库的话，M1 的每个包加留桩文件、记变更时都要重新生成同一份汇总，并行的 PR 之间要么在它上面冲突，要么合并后汇总过期：与状态汇总当初的问题相同（[plan-status-summary-not-committed.md](plan-status-summary-not-committed.md)），业主当时同意那一份不入库的理由在这里同样成立。会话照同一个办法定了，业主事后看，可以改回 |
| 影响的包 | 各包的依赖、顺序、规模、级别都不变。之后每个工作包：加留桩、记变更、记验证结论时只改单项文件，不生成、不提交汇总。W1-21 起的合流包：留桩数与各里程碑应回补的项用 `pnpm counts:report` 核对。外部验证目录 README 里 W0-04 给的两张手工表不再更新 |
| 类别 | —（台账做法，不属拆并、顺序、估算、归属、留桩） |
| PR | 随 W0-30 的 PR |
