## 范围

- tenant 所属内部表七列：id、inviter_member_id、client_request_id、invitation_id、entity_id、store_id、created_at，均非空、无数据库默认值。
- 原邀请保留创建键；新唯一键覆盖同 inviter 的全部成功请求。四个 RESTRICT FK 核实体、门店、邀请人和同一邀请完整归属，不级联删证据。
- 新表复用原公共函数禁止 UPDATE/DELETE/TRUNCATE，app 仅 INSERT/SELECT。无新枚举、函数、角色、序列、CHECK、部分索引或锁级。
- 单条新迁移显式事务并锁原邀请，所有旧状态回填原创建键 A→原卡；不推断未记录的历史复用键 B，不改旧迁移、冻结底稿或门禁逻辑。
- 保留原 natural 模式、创建唯一键及鉴权边界，新增真实映射唯一键登记；不写 idempotency_record，不存响应缓存或请求哈希。
- 映射与邀请长期保留，终态不删、不改绑；未来生产必须在业务同事务写入且先查绑定。结构 FK 不替代生产原子性与业务守卫。
