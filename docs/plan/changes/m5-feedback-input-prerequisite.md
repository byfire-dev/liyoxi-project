W5-13 页面接入实际接口时发现输入与读侧断链：`adminSampleView.actions` 未提供已实现的 `admin.sample.requestChange`，`ticket_attachment` 仍不允许后台上传，而样片/广告代录都要求本人上传的真实截图。补发登记/质检 writer 已支持三个交付后阶段，但 GET 也未给出相应入口。本片独立补输入与读侧投影，不把后端权限改动夹进页面 PR。

- 样片仅在未暂停、当前最新推送版、`sample_confirm`、制作与水印就绪、已有 `delivery.sample.feedback_on_behalf` 权限下返回 `request-change`。写侧原版本、当前员工、范围、截图及广告计次守卫不变。
- 后台 `ticket_attachment` 仅允许 admin 真实同一员工上下文、交付模块可见且具有既有代录权限，必须给范围内门店；给定主体须匹配该门店，拒绝商家代传标记和制作上下文。文件仍属于上传员工，沿原上传/入库/引用流程。
- 通用下载入口只给当前有代录权限且在范围内的上传本人现签此分类；其他员工和商家工单附件不因本片扩大读取。业务反馈附件仍由所属样片/广告读侧授权。原 `admin.file.get` 本人上传状态恢复路径保持。
- 未启用 M6 客服工单的 `service.ticket.reply` 上传或更广泛读取；a01 的该部分仍是后续所属包计划。商家上传能力不变，无新权限点、接口、DDL、依赖或公共框架。

定点验证：新增 `media/feedback-upload.db.test.ts` 走真实登记、重放、入库与现签；权限/身份/跨范围/错主体/代传及他人读取拒绝。`delivery/sample-feedback.db.test.ts` 新目标由真实制作/推送驱动，核动作随权限、媒体状态与代录结果变化，并保留后台可选时间点。使用独立测试库和Provider替身，不代表云上传或渠道送达已验。W5-13/W5-14 在本片实际合 main 后消费；本片不宣称页面包完成。

补发仅在实际 open 补发存在的 awaiting_launch/launch_verify/in_service 阶段投影逐集登记与质检动作，沿原模块、暂停、负责人和权限限制；不授予整包质检，不改补发 writer。既有合法补发全链目标追加申请前/后/取消后 GET 断言，三个阶段的只读谓词目标保无 open、他人编辑、暂停、缺权限与只读拒绝。
