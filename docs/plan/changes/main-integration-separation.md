# main 与 integration 分离

| 项 | 内容 |
| --- | --- |
| 改了什么 | 补充 `CLAUDE.md` 第7节：本地main只跟踪经PR发布的远端main，PR合入后仅快进同步；未发布成果普通合入独立integration保存与联调。开工先核当前分支、工作树及实际已发布依赖，不能把integration中的完成状态当作main交付 |
| 原因 | 业主于2026-10-27明确授权实施main收敛方案。将未发布成果与已发布主干分开，避免本地集成状态被误读为远端已合并或任务依赖已满足 |
| 影响的包 | 在途及后续工作包按已发布main核实依赖；既有未发布成果保留在integration，继续按各包原发布顺序交付。工作包编号、范围、依赖、规模、级别、里程碑及退出条件不变；分支保护、独立复审、required与门禁保持原规则 |
| 类别 | 顺序（仅本地集成与已发布主干的同步流程；工作包依赖及发布顺序不变） |
| PR | —（由调度创建PR后补编号） |
