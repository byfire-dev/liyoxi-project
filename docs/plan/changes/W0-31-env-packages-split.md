# G2-D 的 5 个环境包拆出：W2-25–W2-29

| 项 | 内容 |
| --- | --- |
| 改了什么 | [开发计划](../../08-development-plan.md) 第 7.5 节 G2-D 行的环境包 ⑤–⑨ 拆成五个工作包，表加在第 7.5 节的表后：W2-25（⑤ 预发环境，L）、W2-26（⑥ 发布编排与回滚，L）、W2-27（⑦ 日志、错误上报与告警接通，M）、W2-28（⑧ 契约兼容检查与混跑冒烟，M）、W2-29（⑨ 真机清单、提审核对表与最小可提审版本，S）；五个都是乙类。包数与规模同第 7.5 节（环境 5：L、L、M、M、S），没有变。编号的个位数与圈码相同；没有用 `W2-D1` 一类带字母段的写法，因为汇总脚本的编号正则认不出，写进“依赖”会被当成文字条件。状态文件的“里程碑”写“环境泳道”，不计入“M2 退出”。与计划、ADR-041、D7 字面不同的六处：① 第 5.6 节预发行与 ADR-041“决定”第 4 节开头列的开工条件（E1–E4 的预发各项、参考工程已停、镜像仓库已建）读作“上服务器”的条件，五个包写脚本、本机演练与合并只等代码侧的依赖（第 5.6 节预发行加了一句）；② ⑤ 先交最简的合并即部署（缺省关），⑥ 把它改为调编排脚本；③ ⑦ 的“错误上报”只做配置接线，两条 M2 的转发接口归代码包；④ 真实客户端 IP 先用访问日志验（ADR-041 第 4.3 节写的那条调试接口归属是 M7）；⑤ 单环境阶段没有 `v*` 标签，混跑冒烟的“上一个版本”取 main 上一个提交，回滚目标取节点上发布记录里上一条成功的；⑥ 预发库仍叫 `liyoxi`，核对脚本带 `--database liyoxi` |
| 原因 | 计划 第 7.2 节 W0-31 一行交给它的事。① 的理由：工作包会话本来就不登录服务器，只交脚本、Compose 与演练说明，这些在本机能照原样演练；业主那边的事（域名、证书、密钥、镜像仓库）晚到，不耽误脚本先就绪。服务器上的每一步仍写在各任务书第 8 节，先经业主同意。②–⑥ 是按现状落到能做的写法 |
| 影响的包 | W2-25–W2-29：新建任务书与状态文件。W2-25 只等 W1-22、W0-06a、W0-21；W2-28、W2-29 经 W1-21 等 M1 退出。W2-27 依赖里两个还没有编号的代码包（G2-D 的探针与告警包、落地两条错误上报转发接口的包）先写成文字，由 W1-23 换成编号。W1-23：M2 其余包的编号避开 W2-25–W2-29，照 W1-22 的实际交付核对这五份任务书。计划 第 5.5 节“M2 起加”的每晚 P95 基线没有归到任何包，交 W1-23 定 |
| 类别 | 拆并 |
| PR | W0-31 的 PR（编号由调度会话开 PR 后填） |
