本片是业主显式授权的既有代码迁移，基于冻结的安全壳提交
`670a3ec2f531f9a62864f515c1c3907d2384ad6e`，再普通同步实际main。
该基线仍是在途源码，不能据此宣称安全壳已经实际交付，也不能改变其它会话的开工条件。
原W6-10工作树与分支保持独立；本候选仅在自己的分支验证、保存，不合入在开发分支。

页面使用现有Ant Design二维码组件，不增加qrcode依赖，不保留本地另一套请求框架。
票据secret仅留内存；批准后交换Cookie，再从真实session接口读取授权结果。
二维码、短码和小程序审批流程属于迁移候选，不能把替身浏览器测试记为真实微信V8结论。

本片不包含设置页已授权电脑管理，也不关闭X-01、V8或其它真实环境条件。
正式进入main前仍需沿原工作包完成剩余范围与验收，整包状态保持原值。
为使小程序路由实际进入候选构建，该分支将审批页登记为已实现；这只是草稿分支的源码登记，
不能作为actual main页面交付计数。正式主干计数须以原验收条件满足并实际合入为准。
W6-11下载叶页在独立后继分支接入，不在本片加入另一份下载接口或提前实现W6-12页面。

PR288的首次CI发现迁移遗漏：页面实现登记已包含电脑授权页，但`pages.test.ts`仍精确断言旧46页。
本次只将候选构建集合、`sub/publish`分包及部分页面关闭场景的期望补上`portal-approve/index`，
并显式断言47个构建页。完整顺序、主分包、预下载和未实现页排除断言均保留；
不改页面实现、正式页面交付计数或M6状态，也不把路由测试作为V8结论。

## 草稿CI的接入条件

本次迁移的小程序路由清单测试已同步新增审批页的精确期望；候选工作树的47页结构不代表actual main正式页面计数。
当前草稿仍继承在途安全壳的CI接线缺口：web-live新增Portal验收步骤尚未与infra工作流清单测试同步；
以旧安全壳为PR基线时，普通同步main带来的已合four-counts改动被门禁分类器再次计入。
这些失败不能算作全套CI通过，也不通过加标签或修改门禁绕过；待原安全壳完成前置、同步main并修齐自己的CI后再接入此草稿。
本次页面迁移的本地测试与完整M6/真实整链验收分别记录。
