# 留桩清单加 16 行；两条后台接口由 M2 提前到 M1

| 项 | 内容 |
| --- | --- |
| 改了什么 | ① [开发计划](../../08-development-plan.md) 第 7.3 节留桩清单在末尾加 16 行（“M1 内的端口桩”一行起）：M1 各任务书写明要留、清单原来没有逐条写的桩。其中一行是 M1 内就去掉的端口桩（定义方先合并、实现方后到，共 11 处），W1-21 合流时核对全为“已回补”；其余 15 行回补在 M2–M7。② 两条接口的里程碑归属由 M2 提前到 M1：`admin.auth.activate`（随 W1-01a 的第三个 PR）、`admin.dictItem.list`（只读启用项，随 W1-06 的第二个 PR）。归属写在 `packages/contract/src/routes/milestones.ts`，是代码，本 PR 是纯文档改不了：由这两个 PR 各改自己的一行并重新生成第 8.2 节的表。两条都落地后 a01 的 M1 条数 20 → 22，M1 合计约 128 → 130，M0 + M1 约 131 → 133；第 6.4 节的“约 128”“约 131”是估算，没有改字，退出时以 `node infra/ci/landed.mjs --require M0,M1` 的输出为准 |
| 原因 | ① 留桩清单是 M1 开工前写的，各任务书把范围落到接口与字段之后多出这些项；集中由本 PR 加，免得二十来个并行的 PR 都往同一张表的末尾加行而互相冲突。② `admin.auth.activate`：设置密码的票据只有它发，`staff:bootstrap` 出的是激活码，而第 8.5 节要求首位管理员在 M1 就能登录并绑定动态口令。`admin.dictItem.list`：资质审核、账号核验、链接核验、对公收款四个工作台在 M1 都要驳回原因的单选，不提前就要在四个页面包里各放一份常量并留桩 |
| 影响的包 | W1-01a、W1-06：各多一条接口，改归属、重新生成，不用再记变更。W1-09、W1-12、W1-19、W1-20：驳回原因取接口，不放常量。W1-03、04、08、11b、13、15、16a、17、18、19、20：清单外的留桩不用再往计划里加行，只在 `docs/plan/stubs/` 登记文件。W1-21：核对留桩清单时按新的行；接口清零按 133 条。G2-A：字典只剩写侧与引用计数 |
