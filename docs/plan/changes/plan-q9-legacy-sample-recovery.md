## 恢复规则

- 仅当前最新、未决、已推送且原渠道不含 weapp 的样片，工单须在 sample_confirm、未暂停，订单及媒体仍可用。普通推送不隐式恢复。
- 请求显式提供期望旧版本、10–200 字原因及当前清单的本次质检结果。操作人须同时有推送和质检权限、处于原数据范围且不是原上传人；不复制旧质检作为本次复核。
- 锁内复查广告版本、源质检归属及通过事实、开关、制作记录和真正水印。旧版按状态机失效，保留原渠道、推送时间、查看与决定字段；新版本复用同一文件和广告快照，新建自己的 QC，并经 uploaded → qc_passed → pushed 推送。
- 工单 sample_confirm 自循环仅更新当前版本指针；保留现有环节、轮次、首次推送时间与时限。新样片不继承旧查看或决定证据；商家必须重新查看并主动勾选。
- 同键同请求重放只返回原结果，同键异请求拒绝；并发不能创建两版。任何业务守卫失败整体回滚，不伪造商家修改意见、观看或确认。

## 本地执行与验证边界

本次允许在用户已授权的本机开发环境开启样片播放开关，并恢复指定门店的旧样片。专用 CLI 默认只读预检，执行须显式 apply；仅公开 local PG/Redis/MinIO 回环配置，拒绝非本地环境，不读取 .env、私钥或会话令牌。员工从既有真实启用角色及范围装配，开关经配置服务写审计并更新缓存；现有规则保留，若新默认仍无法对目标主体启用则提前拒绝。

使用单 worker 的新增服务/HTTP 定点测试验证快照保留、独立质检、并发/重放、版本/权限/暂停/广告/水印守卫和 GET 零写；后台验证复核表单与按钮权限。沿既有完整 CI，不改预算、门禁或等待时限。本地实际恢复后核对新旧记录及可播放文件；不代商家提交真实确认。微信真机、云环境、法务与平台提审仍单列。

本变更不增加接口编号、页面、DDL 或依赖，不标 W5-03/05/08 整包完成，也不实现通用强迁、返工、修改意见或广告重开。后继包消费本窄恢复能力，仍按自身实际依赖开发。

## 本机验证与审查

Node 24，沿用公开本地 PG/Redis 的独立测试库；所有连库与浏览器目标串行、单 worker，不做压测。服务/API/worker/admin 类型检查、状态机对账、契约与接口登记对账、依赖方向检查通过。

- 服务定点：`sample-legacy-recovery.db.test.ts`、`q9-local-sample-recovery.db.test.ts`、`q9-local-sample-recovery-env.test.ts` 与最小旧回归 `production-path.test.ts`。覆盖拒绝零写、末端失败整体回滚、源 QC 归属、当前版本、暂停、水印、普通推送不隐式恢复、环境拒绝和 CLI 默认只读。
- HTTP：`apps/api/test/delivery-legacy-recovery.test.ts`，真实鉴权与幂等链验证双客户端竞争只一版、重放返回原新版本、响应裁剪、商家 GET/签发及必须勾选确认。
- 后台：`panels.test.tsx` 14 项与 `production-lifecycle.spec.ts` 的样片质检/恢复两项通过；复核入口须同时具备权限，原因、清单与明确确认缺一不可，版本变更清空旧结论，重取预览 URL 不清空。
- 本 PR 一轮独立审查提出一条 P2：完成恢复后若关闭主体规则，同键重放被当前开关拦截。已修正为完成重放跳过开关可执行性及写入，并以真实配置服务的“执行成功→关闭规则→重放零新增写入”测试通过验证。

定点测试另发现并修正恢复新增文件引用的锁升级顺序：首次即对源文件及水印文件整体按主键升序加排他锁，后续引用写重入已有锁；默认读取路径仍用共享锁。测试夹具使用实际存在但归属其他样片的通过 QC 验拒绝，不清空 pushed 行必有的 QC，也不修改数据库约束。类型循环改为依赖接口，测试置于既有履约夹具所在域；不放松分层检查。Worker 构建、改动文件 ESLint/格式检查通过；恢复机制、后台入口和严格 local 执行工具同 PR 交付，调度接纳其联动体量。

本机该门店素材已只读核对源文件、水印及体检事实；视频为现有联调素材、广告位为空。实际写入恢复前须明确按本地技术联调用途复核或由业主按正式交付标准复核，不能将文件可读推断为广告与许可内容通过。当前尚未执行本地恢复，未代商家确认。

首次 CI 的两项台账检查发现新工作包缺少规定表头字段，已按原格式补齐；密钥扫描将固定测试幂等键误报为 generic-api-key。该值仅为隔离测试请求键，不是凭据；改为运行时 uuidv7 生成，并从同一 main 基线新建干净提交替代原 PR，保留旧分支，不强推、不添加扫描豁免。原独审及修正结论仍适用于同一交付内容，调度核对替代分支差异，CI 以新 head 完整运行结果为准。
