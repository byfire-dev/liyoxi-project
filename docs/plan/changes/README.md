# 计划变更记录（changes）

依据：[开发计划](../../08-development-plan.md) 第 13 节“计划变更怎么记”行、第 5.3 节“粒度”行、第 5.7 节、第 7.3 节 W1-23 一行。

## 1. 用途

| 项 | 规则 | 出处 |
| --- | --- | --- |
| 记什么 | 对开发计划的改动：改了什么、原因、影响的包 | 计划 第 13 节 |
| 粒度 | 一条一个文件 | 计划 第 5.1、13 节 |
| 怎么改 | 小改直接改计划正文，同一个 PR 在本目录记一条 | 计划 第 13 节 |
| 汇总 | 汇总表由脚本现生成，不入库，不手改：`pnpm plan:summaries` 写到本目录的 `SUMMARY.md`（被 git 忽略） | 计划 第 9.3 节 |

## 2. 何时登记

| 情况 | 记在哪 | 出处 |
| --- | --- | --- |
| 包的拆并、顺序调整、估算修正 | 本目录一条 | 计划 第 13 节 |
| 接口、页面、x01 条目改归属的里程碑 | 本目录一条 | 计划 第 5.7、13 节 |
| W0-13、W0-14、W0-17 与其余甲类包开工后超过体量上限，按 a、b 拆 | 本目录一条 | 计划 第 5.3 节 |
| W1-23 拆出的包数与计划 第 7.5 节有出入 | 本目录一条 | 计划 第 7.3 节 |
| 计划留桩清单之外新增留桩，或改留桩的回补里程碑 | 默认：本目录一条，类别写“留桩”（W0-04 定；留桩清单在计划 第 7.3 节，改它属小改） | — |
| 大改：里程碑范围、退出条件、前提 | 不记本目录。PR 标 `plan-change`，须业主确认 | 计划 第 13 节 |
| 架构取舍 | 不记本目录。另写 ADR，放 `docs/adr/` | 计划 第 5.1、13 节 |
| 待确认事项有结论 | 不记本目录。先改文档里的默认做法，再改代码，同一个 PR；必要时开“变更工作包” | 计划 第 13 节 |
| 实现与任务书的出入，不改计划 | 不记本目录；写在该包状态文件的“偏差”一栏与 PR 描述 | 计划 第 5.3、13 节 |

与 01–07 冲突时以 01–07 为准，回改开发计划（计划 第 13 节）。默认：回改的内容属于上表小改范围的，照小改在本目录记一条（W0-04 定）。

## 3. 命名规则

第 2 节的时机与本节的命名以本文为准；文件里的键以[变更记录模板](../templates/change.md)为准。

默认（W0-04 定）：`<发起的工作包编号>-<短名>.md`；不由工作包发起的用 `plan-<短名>.md`。短名用小写英文与连字符。不用流水号，免得并行的 PR 撞号。

- 同一个包发起多条的，短名取不同的。
- 例：`W0-13-split-a-b.md`、`W1-23-m2-package-count.md`。

## 4. 文件格式

复制[变更记录模板](../templates/change.md)填写。键：改了什么、原因、影响的包（这三项是计划 第 13 节要求的）、类别、PR。类别取值：拆并、顺序、估算、归属、留桩。改了计划的哪几节、归属变化、包数变化都写在“改了什么”里，不另设键。

本目录随 W0-04 交付时有一条：[W0-04-post-kickoff-fixes.md](W0-04-post-kickoff-fixes.md)（开工后小改）。
