# M5 本地订单交付接口演示

本页随W5-15第一片交付可运行入口。分支本地第7轮为首个完整主链通过，首个正式demo也已退出0；当前正式CI/合入及最终验收位置见[状态页](../status/W5-15.md)。actual main十轮、main连续两次演示及业主看样尚未执行，不记作通过。

`pnpm demo:m5`与`pnpm e2e:m5`共用真实Hono业务链，复用M1独占测试库、Redis前缀及自然清理。外部文件、微信和签署使用已合公开测试材料，不读取本机真实密钥、连接云端或真实收费。

## 运行方式

沿根README的Node24与冻结依赖，先确认本机PostgreSQL/Redis已就绪。只使用公开开发连接，不读取`.env`：

```sh
export APP_ENV=test
export DATABASE_URL=postgresql://liyoxi:lyx-local-dev@localhost:5442/liyoxi
export REDIS_URL=redis://localhost:6389/0
pnpm e2e:m5
pnpm demo:m5
pnpm demo:m5
```

每条命令都新建自己的隔离库/前缀。每次demo在自己的同一数据库内第二遍重放原正文和原幂等键，验证业务零新增及完整字典不变；两次新建空库不作为幂等证据。原90秒上限包含初始化、主链、同库重放、所有full不变量与自然清理，使用单worker、不并行文件。

只支持`--help`，帮助不创建资源。非test环境在创建支架前拒绝；`prod`、`production`、`local`及未声明环境均不允许：

```sh
APP_ENV=prod pnpm demo:m5
```

本轮实际负向核验：prod及未知参数各退出1；prod下`--help`退出0且未创建资源。其余非test分支沿同一明确环境守卫，不把这些拒绝/帮助结果计作业务链成功。

不提供attach、任意业务库、保留资源或覆盖执行脚本的选项。testing支架还须核实际数据库/Redis范围与本机连接；原意图重放只接受本轮已有真实业务的scope。

授权的正向更正出新版、failed同版重生成复用已合PR #220和#244的真实验收记录，本综合链不声称再次完成这些正向场景。只修改note/correctionKinds不构成法律事实变化，正式更正公口应返回`LICENSE_LETTER_UNCHANGED`；综合链保留此409及版次/历史不变反例，不为制造新版本直接SQL改法律事实或临时扩大生产者。

## 同库第二遍与输出

业务成功后、最终full前，runner的`afterCore`交出本轮scope和原意图重放闭包。核验器先确认test、本机及当前数据库归属，再记录本轮明确业务表的逐项数量和完整字典，重放原种子及原HTTP正文/幂等键，消费真实事件后逐项比较。字典包括停用、扩展与版本；会话、投递及不变量运行等技术记录不能混作新增业务。

第二遍不重新报价后创建新意图，不把现签下载URL当成应幂等的业务写。只有业务表数量逐项相等、种子inserted=0且完整字典保持时才输出成功摘要。具体受核表和scope约束以`testing/m5-demo.ts`为准。

CLI只打印固定讲解和白名单整数/不变量摘要，不展开员工、登录头、口令、TOTP、cookie、连接、完整响应或签名URL。失败返回非零及固定脱敏说明，原支架在`finally`自然清理；异常时由操作员按本轮明确标识核验，不能重置共享开发库或清共享Redis。
