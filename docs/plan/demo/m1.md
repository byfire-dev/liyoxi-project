# M1 演示手册

接口主路径和演示命令共用一份流程：后台登录 → 商家建档与资质通过 → 对公开通 → 订购与开工 → 方案、样片和成片交付 → 链接核验上线。自动化运行与开发者工具、真机手验分别记录。

## 1. 本机接口演示

使用仓库锁定的 Node 24、pnpm，Docker 中共享的 PostgreSQL、Redis 已就绪。第一次准备按根 README 安装依赖并生成数据库客户端；已有共享依赖不用重复启动。

```sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm infra:up
APP_ENV=test \
DATABASE_URL=postgresql://liyoxi:lyx-local-dev@localhost:5442/liyoxi \
REDIS_URL=redis://localhost:6389/0 \
pnpm demo:m1
```

这些连接值是仓库公开的本机测试值。命令每次新建自己的测试库和 Redis 前缀，迁移、播种，再逐段讲解实际接口结果；结束后只清理本轮资源。重复执行得到同样的业务状态与计数，业务 ID 和运行时间可以不同。

| 段 | 应看到的结果 |
| --- | --- |
| 后台登录 | 首位管理员完成激活、设置口令、绑定动态口令和实际登录；制作与质检使用不同员工 |
| 商家建档 | 实际手机登录、协议同意、主体与门店创建，四步建档提交并通过资质审核 |
| 开通 | 对公转账凭证经后台确认，订阅生效且钱包积分到账 |
| 订购与开工 | 使用已核验发布账号订购演示短剧，拨业务时钟执行具名开工任务，积分实际扣减、工单实际创建 |
| 方案与样片 | 方案推送并确认，样片上传、质检、推送，实际取得可读下载地址后确认 |
| 成片交付 | 按演示剧实际集数逐集登记，集质检、整包质检通过并推送 |
| 上线 | 商家回填链接，后台核验通过，任务已上线、工单服务中、使用期开始；全量不变量无违规或执行错误 |

外部能力在接口演示中使用替身，业务请求经过实际 Hono 处理器、中间件、权限和幂等链。媒体事实只为本轮已上传并存储的固定测试视频登记；这不回补 M3 的生产视频探测。

单条自动化入口是 `pnpm e2e`。连续验收使用 `node infra/ci/e2e-repeat.mjs --times 10`；它保留逐轮退出码、时长和日志，失败不能以重试计为通过。合入后还须在实际 main 手动运行 `e2e-repeat` 工作流。

## 2. 为页面手验准备种子

按根 README 的本地整套环境说明启动 `pnpm stack:up --lan`，完成本机运行时与首位管理员引导。然后在本机 `lyx_stack` 的连接配置下运行：

```sh
pnpm demo:m1 --stack
```

这个选项只播种演示员工、协议、套餐和短剧，保留已有数据供手验；已有员工不重建、不重发激活码。新员工激活码仅现场打印，手册不记录口令。它不运行隔离库的自动化主路径、不重置手验库。

开工延迟的代码默认值已为 0。本包通过 config 服务核验现值，没有使用尚属 M2 的参数写接口；已有手验库配置非 0 时命令明确拒绝，保留原参数。

当前 `--stack` 的现场播种、开发者工具和真机结果须由业主执行后登记；接口自动化通过不代替这些结果。

## 3. 页面演示点 A、B

后台入口为 `http://admin.localhost:8080`；小程序按开发者工具、开发版真机的实际配置打开。先用首次引导或现场种子给出的激活码设置个人口令并绑定动态口令，再登录。

1. 商家登录并同意协议，创建主体、门店，完成基础信息、门店环境、主推服务和证照；后台在资质审核中通过，并指派交付经理。商家建档页显示审核通过。这是演示点 A。
2. 商家绑定发布账号并提交资料；后台核验账号，确认后才能订剧。
3. 商家对公开通、上传转账凭证；后台财务确认，商家钱包显示可用积分。
4. 商家选剧、确认报价并订购；订单进入制作，后台“交付 → 工单列表”出现对应工单。
5. 打开工单详情，编辑并推送方案；商家从订单详情进入方案页确认。
6. 制作员工登记样片，另一员工执行质检并推送；商家保存、查看样片后确认。未知视频元数据会被真实质检拒绝，生产在线探测仍属 M3，现场结果按实际记录。
7. 制作员工按实际集数登记成片，完成集质检和成片包质检；后台“发布 → 成片交付”核对清单并推送。
8. 商家逐集下载，填写发布任务的实际链接、日期和集数；后台“发布 → 链接核验”勾选检查项并通过，或选择原因退回补充。
9. 商家上线记录显示已上线，订单使用期开始，工单进入服务中。这是演示点 B。

小程序保存视频使用平台下载与保存相册能力；H5 截图环境不能证明真机相册保存。下载签名按每次操作重新获取，实际授权过期情况由页面和服务端提示。

## 4. 现场结果登记

将 A、B、开发者工具和真机的实际结果记入 W1-21 状态及既有外部验证台账。有失败就记录具体步骤、错误符号和页面表现，归所属工作包修复；不要修改数据库终态来完成演示。

M2 员工短信与分配池、M3 视频探测及 M5/M6 未来页面能力保留原留桩。对应范围和回补里程碑见 `docs/plan/stubs/`。
