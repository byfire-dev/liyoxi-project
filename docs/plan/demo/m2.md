# M2 本地接口演示

`pnpm demo:m2` 与 `pnpm e2e:m2` 共用 `apps/api/test/e2e/m2-runner.ts`。
沿 M1 登录、建档、入账、订剧、方案/样片/成片及上线全链，增加 M2 生命周期。
本包调用 M1 已有钩子，采用真实二十集演示剧；本机单路上传控制 Air 负载，
明确 `CI=true` 的专用 CI 沿原 M1 四路。集数、所有断言和 90 秒判据相同，原 M1 默认和原测试不改。

## 运行

使用根 README 的锁定运行时与依赖，生成当前数据库客户端，确认共享本机 PostgreSQL/Redis 已就绪。
公开开发连接值如下；不用读取 `.env`，命令不接受生产或远程业务库：

```sh
export APP_ENV=test
export DATABASE_URL=postgresql://liyoxi:lyx-local-dev@localhost:5442/liyoxi
export REDIS_URL=redis://localhost:6389/0
pnpm demo:m2
```

每轮由 M1 支架新建独占测试库与 Redis 前缀，先打印安全的资源标识，最后仅清理本轮资源。
`APP_ENV=prod` 拒绝，`--help` 只展示说明。密码、TOTP、验证码、凭据和签名地址只存在内存，不进入报告。
同库重播同键接受/换绑/已读/运输恢复，并复跑公共演示种子核对零新增；
不把下一轮新库内的重新造数称作零新增。

| 结束 | 保留 M1 live/in_service 终态，全量不变量零违规且零执行错误，自然清理本轮资源 |

## 运输与外部边界

生产 scanner 的退避/租约使用数据库时间，业务时钟不会自动推进它。
新增 `m2-transport.ts` 沿 M1 运输认领方式，只在独占库、真实本轮主体/目标、登记 kind/subscriber、
创建范围和实际期限/重试时间已由虚拟钟到期后，更新认领序号、租约与 dispatched/leased。
不写 attempts、failed/dead、fireAt、业务状态或历史；失败包装只抛固定测试错误，实际失败短事务、
告警和业务恢复均由生产 runTimer/consumeDelivery 完成。绕过期限或认领终态会直接拒绝。

长时间推进邀请期限前及结束时，`m2-background.ts` 在同一本轮独占库内有界消费正式种子与链路产生的媒体/通知。
它核创建范围、已登记处理器与次数上限，用正式 media.jobs.run；已逾期的任务用正式 expire 保留实际失败/取消原因，
通知走正式 scan/deliver（含 fanout），不继续拨钟、不改数据库终态、不先运行不变量自愈再重验。
本机最终运维段实际收尾三个 audit_image 成功与四个通知，随后一次全量不变量零违规。

微信订阅槽位仍未配置，本链断言 ignored 与幂等，不伪造授权额度或外部成功；
真实授权账本原目标保留在 W2-17。回调列表和未知目标恢复守卫走真实 HTTP，
成功 webhook 重投沿 W2-23 已合目标证据，主链不代替全部权限/并发/回调矩阵。
六类注销阻断与十项资质表驱动、完整店员/后台权限矩阵沿各 owner 已交证据，不在 Air 重跑整套。

连续十次正式验收由 ROOT 的独立门禁伴随接现有 e2e-repeat，单 job 串行、任一红即失败、无自动重试。
本机只做一次新增完整主链与必要聚合风险目标；分段证明使用原 beforeOrder 公开钩子的真实付费、资质和门店前置，
在同一 M2 完成函数及全不变量结束后用私有哨兵退出，不执行媒体段。它不替代完整链或正式十连。
本机通过不代表十连、远端 required、真实微信/短信/云、
预发、真机或可提审通过。正式容量与旧 P95 RED 仍在 D7-16，最晚 M8 退出。
