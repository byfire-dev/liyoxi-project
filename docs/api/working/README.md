# 接口契约：工作底稿

写接口文档时用的底稿。核对脚本（[tools/api-check](../../../tools/api-check/README.md)）读这里的文件；读者一般不需要看。

| 文件 | 内容 |
| --- | --- |
| [api-rulings.md](api-rulings.md) | 主负责人裁决，编号 A1–A156，共 138 条（A67–A69、A71–A75、A109–A118 未使用）：作者之间的分歧、约定稿的待确认、各轮复核与修订中交上来的问题，按轮次分节。优先级高于约定与各文档 |
| `routemap.json` | 路线图：全部接口一条一项（operationId、方法、路径、所属文档、鉴权、能力点或权限点、店员视图、幂等方式、对应画板、涉及的表、状态迁移、依据、版本、备注）。由各文档的路线图切片合并而成 |
| `resources.json` | 资源登记表：资源名与数据表的对应（约定 C10） |
| `frag/<文档>.json` | 各文档的结构化清单：接口、结构及字段、错误码、权限点与能力点、事件等，供脚本核对。格式见写作规范第 4 节 |
| [API-WRITER-GUIDE.md](API-WRITER-GUIDE.md) | 写作规范：依据的优先级、文档格式、清单格式 |

说明：

- 底稿与接口文档里的“文件:行号”引用以本次提交时的文件为准。数据模型在接口阶段回写时插过行，行号引用随之重排过，并列写法（“a、b、c”）里的行号另按内容逐条核对；以后改数据模型文档时尽量并入原有行，或同步改引用。
- 路线图最初分商家端、后台、下载页与回调三份，后来按文档拆成切片由各作者维护，定稿时合并为一份 `routemap.json`。
