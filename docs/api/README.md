## 每份文档的结构

| 节 | 内容 |
| --- | --- |
| 头部表 | 范围（覆盖的页面与功能）、接口数、依据 |
| 1 概览 | 一张表：operationId、方法与路径、用途、鉴权、幂等 |
| 2 公共结构 | 本文多个接口共用的请求与响应结构，每个字段写类型、是否必有、说明与来源（`表.列` 或计算规则） |
| 3 接口 | 每条接口：鉴权（能力点或权限点、店员视图）、幂等、乐观锁、对应画板；请求；响应；错误；副作用（状态迁移、出站事件、审计、定时器）；说明 |
| 4 枚举 | 本文用到的枚举，与数据模型同名枚举一致 |
| 5 错误码 | 本文定义的领域错误码（数值在本文的分段内） |
| 6 待确认 | 需要产品、业务、法务、财务决定的问题，各带默认做法 |
| 7 修订记录 | 每一轮改了什么、依据哪条裁决或请求 |

x01（事件目录与任务进程）不定义接口，结构不同：事件命名与载荷规则、事件目录、订阅者、定时器、周期任务、非接口触发的状态迁移归属、版本兼容规则、待确认。

## 工作底稿与工具

- [working/](working/README.md)：裁决（编号 A1–A156，共 138 条）、路线图、资源登记表、各文档的结构化清单、写作规范。
- [tools/api-check](../../tools/api-check/README.md)：整体核对与登记表生成脚本。

## 改接口的做法

1. 改分组文档，同时改 `working/frag/<文档>.json` 与 `working/routemap.json` 里对应的条目，三者保持一致。
2. 新的通用规则先改 [00-conventions.md](00-conventions.md)；涉及取舍的，在 `working/api-rulings.md` 追加一条裁决。
3. 跑 `python3 tools/api-check/check.py`，再重新生成登记表。
4. 动到表结构的，先改 [数据模型](../data-model/README.md) 并跑 `tools/schema-check`。
