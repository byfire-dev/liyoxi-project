### 1.5 与 PRD 的差异 / PRD 未写的规则
1. 【差异】PRD 7.4 第 1 条只列筛选项，没有**排序**；原型提供 3 种排序，且默认“按最近订购”。
2. 【差异】“套餐版本”筛选把**未开通、已过期**两个订阅状态混进版本枚举（`:40`）；“套餐到期日”在 PRD 是筛选维度，原型落成“7 天内 / 30 天内”两个快捷档而非日期区间。
3. 【差异】“累计实付按主体合计，显示在首家门店”（`:61`、`:157` 春熙店显示“—”）是原型新增的展示口径。
4. 【差异】页头区分“付费 213 家”与“套餐生效 186 家”两个口径，PRD 9.1 只定义了“付费主体数 = 当月套餐生效的经营主体数”。
5. 【推断】套餐可以在资质审核通过**之前**开通并付款：晴天洗衣“审核中 + 基础版 + 冻结 1,200”（`:92`）、阳光台球“已驳回 … 09-13 已全额退款”（`:109,111`）。PRD 2.4 第 2 条只说“资质审核可与订购并行”，对开通未明说；这会影响“开通转化率 = 开通主体数 ÷ 审核通过主体数”（PRD 9.1）的口径。
6. 【推断】“冻结”在原型里有**两种含义**：订购冻结（提交订购后占用，`frozen` 字段）与过期冻结（套餐过期后加购积分不可用，“加购 3,000 已冻结”）。数据模型必须分成“占用（hold）”和“停用（suspended）”两个概念，不能共用一个字段。
7. 【推断】交付经理按**门店**展示（同主体两家店各有一列，`:100-101`），而基础版新商家多为“未分配”（`:92-95`）。分配触发点见 2.5 第 9 条。

### 2.5 与 PRD 的差异 / PRD 未写的规则
1. 【差异】**代改档案的可改字段比 PRD 窄**：PRD 7.4 第 2 条说“可代改无须重新审核的字段”，原型只开放 6 个文本字段，品牌名称、主推服务、门店图片不在表单里（`:76-81`）。并且原型要求“各项内容均不能为空”（`:666`），而 PRD 6.3.3 中优惠活动、团购信息是选填。
2. 【差异】字段形态不一致：PRD 6.3.1 营业时间“支持多个时段”，原型是 ≤30 字的单行文本；PRD 6.3.3 核心卖点是“1～5 个标签 + 文本”，原型是 ≤100 字文本。**数据模型应以 PRD 的结构化定义为准**，后台表单需要相应升级。
3. 【差异】修改原因 4 项（商家电话委托 / 商家企业微信委托 / 资料有误经商家确认后更正 / 其他，`:82`）、转移原因 4 项（工作量调整 / 商家要求更换 / 人员调岗或离职 / 其他，`:302`）、积分调整原因 5 项（制作问题补偿 / 平台原因退回 / 纠正错误扣减 / 运营活动赠送 / 其他，`:321`）均为原型新增枚举，PRD 只说“须选择原因”。另：CreditAdjust 画板里同一原因写作“纠正错误**记录**”，与本画板“纠正错误**扣减**”不一致。
4. 【差异】素材标注的 4 组选项为原型新增（`:489-492`）：内容标签 8 项（菜品与产品、门店环境、人物出镜、活动优惠、菜单价目、品牌故事、顾客评价、创意想法）；用途 5 项（片头片尾广告、剧情植入、口播台词、方案参考、封面海报）；时效 4 项（长期可用、国庆 10-01～10-07、秋季、限时活动——含**日期区间型**取值）；可用性 4 项与 PRD 6.16.3 一致。
5. 【差异】素材状态：后台用“待整理 / 已整理 / 已采用”，商家端显示“整理中 / 可用性”（`:107`）——同一状态机两套展示文案。
6. 【推断】素材的系统自动处理结果在原型里很具体（`:498-507`）：图片识别（“4 张菜品特写，竖图、光线良好”）、录音/音频转写并提炼要点、视频规格识别（“竖屏 1080P，画面稳定”）、文档内容抽取（“已提取 12 道菜品与价格”）、人脸检测（“画面含顾客正脸，已提醒补充肖像授权”）。PRD 6.16.3 第 1 条只概括为“自动转写、识别内容并打上内容标签”。**这是 V1.0 就需要的异步 AI 处理管线**（ASR + 多模态识别 + 文档解析 + 人脸检测）。
7. 【推断】一条素材 = 一组文件（“图片 4 张”“文档 3 页”）；新增门店可**复制**素材（春熙店“12 条 由万达店复制”，`:112`），应按引用复制而非复制文件。
8. 【差异】“食品经营许可证 … 到期前 30 天提醒商家更新”（`:136`）——**证照到期提醒**在 PRD 全文未出现（已全文检索），需要证照有效期字段 + 定时任务；到期后门店资质状态如何变化也未定义。
9. 【差异/推断】交付经理的分配时点：操作日志写“08-13 09:16 系统 开通专业版后，按城市轮询分配交付经理：林晓”（`:480`），即**开通套餐后**触发；而 PRD 5.2 第 1 步写的是“工单生成后自动或由主管分配”，Orders 画板也有“工单待分配 / 交付经理：待分配”的订单（`Orders.txt:116,118`）。两个触发点并存，规则需拍板。另外这 7 个画板里没有“手动分配”入口（只有“转移”）。
10. 【差异】工单状态名：原型用“**服务中**”（`:449-451`、`:294`），PRD 5.2 第 10 步叫“**使用中**”，而 PRD 7.4 第 4 条又写“在办工单（含服务中）”——PRD 自身不一致，需统一枚举名。
11. 【差异】“渠道账号认证主体须与营业执照主体一致”（`:117`、`:156`）在 PRD 6.10.2 没有明写（只写“核验账号归属与认证状态”）；个人认证/未认证账号如何判定未说明。
12. 【推断】时限按**工作日历**计算而非自然日：视频号 09-30 10:12 重新上传截图，“须于 10-08 10:12 前完成核验”（`:168`）——跨过国庆假期后的第 1 个工作日。SysParams 画板也写“工作时间：周一至周五；调休上班日按工作日计”。需要节假日/调休日历服务。
13. 【差异】跟进记录在 PRD 7.4 第 8 条属 V1.1，原型页签已可用（带 V1.1 角标）；而“套餐到期”画板的续费跟进属 V1.0（PRD 7.5 第 6 条）。两处表单字段不同（本页：方式 + 内容 + 下次跟进；Renewals：方式 + 续费意向 + 说明），方式枚举也不同（“到店拜访” vs “上门拜访”）——应合并为一个 FollowUp 实体。
14. 【推断】操作日志是**以门店为主语的活动流**，混合了商家端行为（订购、加购、绑定、邀请、上传）、系统事件（发放积分、扣减、分配）与员工操作（`:459-487`）。不是单纯的“后台操作审计表”，需要统一的领域事件落库。
15. 【推断】订购提交到扣减之间有 3 分钟间隔（冻结 10:32 → 扣减 10:35 → 生成授权书 10:40，`:421-422`、`OrderDetail.txt:110-112`），即使资质早已通过。说明“开始制作”是**异步任务**（扣减、生成工单、分配、生成授权书分步执行），不是提交订购的同步事务；是否存在“可无损撤销的窗口”PRD 未说明。
16. 【资料】成员名额含待接受的邀请、老板不占名额；邀请 24 小时有效（`:113`“10-01 09:40 前有效”，与 PRD 6.16.2 一致）。

### 5.5 与 PRD 的差异 / PRD 未写的规则
1. 【差异】**分阶段扣除比例的具体值**：方案确认阶段 10%、广告准备与样片制作 30%、样片待确认 50%（OrderDetail `:101-102`；Params 画板默认值 `c1=10, c2=30, c3=50`，且要求“扣除比例应随交付阶段递增”）。PRD 2.8 只说“扣除比例由运营后台配置”。
2. 【差异/缺口】**样片确认之后、上线之前**（批量合成、成片交付、待上线）取消如何处理，PRD 与原型都没有定义：PRD 2.8 只覆盖“制作中（样片未确认）”和“已上线”。
3. 【差异】取消原因 3 项枚举、说明不少于 5 字，为原型新增。
4. 【差异】退回去向写“套餐积分（本期 09-13 至 10-12 内有效）”；PRD 2.3 第 3 条另有“原周期已结束的套餐积分按加购积分退回”，实现时退回目标桶需按原扣减来源 + 周期是否结束动态判断，且需拆到每个来源桶（一笔订购可能同时扣了套餐与加购积分）。
5. 【差异】发起取消后订单主状态：本画板保持“制作中”+ 徽标“取消审批中”（`:40`）；而 Orders 列表中同类订单显示“**售后处理中** · 取消审批中”（`Orders.txt:124`）。原型内部不一致，需明确“提交取消申请是否立即把订购单置为售后处理中”。
6. 【推断】取消是**整单**发起、按剧分别核算；是否支持只取消其中一部剧，PRD 与原型均未说明。
7. 【资料】授权书“授权方信息以双方签章版本为准”（`:119`）——涉及电子签章；PRD 10.5 第 7 条要求“双方签章”，签章方式（电子签平台 or 盖章扫描件）未定。
8. 【资料】订购单终态补充（来自 Refunds 画板）：财务审批并执行后“订购单变为‘已退回积分’，交付工单关闭”；开始制作前取消则为“已取消”。

### 6.5 与 PRD 的差异 / PRD 未写的规则
1. 【差异】**凭证字段识别与系统比对**（户名、金额、附言是否含付款单号、时间先后）为原型新增；意味着银行回单也要做 OCR/结构化识别（或由商家填写）。PRD 7.5 第 3 条只说“核对凭证与银行到账后确认”。
2. 【差异】**银行流水号必填 + 勾选确认**为原型新增的强制前置条件。
3. 【差异】驳回原因 5 项枚举为原型新增；“驳回后状态不变、可重新上传凭证”为原型新增——意味着付款单之外还需要一张**凭证/收款审核记录**子表来保存每次上传与驳回。
4. 【差异】“开通时间以确认到账时间为准”（`:125`）为原型新增规则，PRD 未写对公转账的周期起算点。
5. 【缺口】对公转账付款单**没有超时规则**：微信支付 30 分钟自动取消，对公转账长期不到账如何关闭未定义。
6. 【缺口/风险】页头说明只列“开通、续费套餐与加购积分”（`:41`），未列“升级”。升级差价按“本期剩余天数”计算（PRD 2.2 第 5 条），若允许对公转账，创建日与到账确认日不同会导致差价失真——需明确升级是否只允许微信支付。
7. 【资料】资质审核中也可确认到账并生效套餐（`:137`），与 1.5 第 5 条互证。

9. 【推断】列表以“商家（门店名）+ 主体”展示，但套餐属于主体；多门店主体显示哪家门店未说明（商家列表的口径是“首家门店”）。
10. 【推断】原型在“7 天内到期”只展示前 8 家（`:268`），真实实现需要分页。

### 8.2 状态机

**门店资质**（PRD 6.3.5 + Review）
```
未提交 ──提交──▶ 审核中 ──通过──▶ 已通过 ──改资质/门店名/地址/品类──▶ 审核中
                   └──驳回(原因+说明)──▶ 已驳回 ──补正重提──▶ 审核中
```
通过的副作用：首店的冻结订购开始制作；新增门店解锁订购、绑定账号、上传素材。

**订购单**（Orders 状态条 8 种 + OrderDetail + Refunds）
```
待开工 ──资质通过/开始制作(扣减积分、生成工单)──▶ 制作中 ──成片交付──▶ 待上线 ──链接核验通过──▶ 上线中 ──使用期结束并下架──▶ 已结束
  └─开始制作前取消/资质无法补正(全额释放冻结)──▶ 已取消
制作中 ──客服发起取消(财务审批中)──▶ 售后处理中 ──审批通过并执行──▶ 已退回积分
                                              └──驳回──▶ 回到原状态
```
子状态取自交付工单：资质审核中 / 工单待分配 / 方案确认 / 广告准备 / 样片制作 / 样片确认 / 取消审批中。

**付款单**（Orders + Receipts）
```
待支付 ──微信支付成功──▶ 已支付 ──套餐退款(财务审批+执行)──▶ 已退款
  └─30 分钟未支付──▶ 已取消 ──(回调晚到)──▶ 对账差异 → 补单=已支付 / 原路退款
待确认收款(对公) ──财务确认到账(流水号)──▶ 已支付
        └──驳回──▶ 仍为待确认收款(商家重传凭证)
```

**订阅**：未开通 → 生效中 →（到期前 7/3/1/0 天提醒）→ 已过期（套餐积分清零、加购积分停用）→ 续费 → 生效中；升级即时生效；降级下周期生效；延长需审批。

**积分占用**：提交订购/广告需求 → 冻结 → 开始制作时转扣减；取消时释放或按比例退回；周期结束清零（冻结中的视为已使用）。

**审批类单据**
- 积分调整 TZ：待审批 → 已通过（入账）/ 已驳回。
- 退款/退回 TK：待审批 → 待执行 → 已退款/已退回；或 已驳回。
- 套餐延长：审批中 → 通过（顺延）/ 驳回。

**其他**：素材 待整理 → 已整理 → 已采用；渠道账号 待核验 → 可用 / 异常 → 已解绑；成员邀请 待接受 → 正常 / 过期；续费意向 待跟进 → 考虑中 / 已确认续费 / 暂不续费 → 已续费。

## 9. 风险与冲突（摘要）

1. 支付超时 30 分钟、证照到期前 30 天提醒、过期 30 天后移出续费列表、扣除比例 10/30/50%、延长档位 3/7/15/30 天等数值只存在于原型，PRD 未收录。
2. “冻结”一词两义（订购占用 vs 过期停用），不拆开会导致余额计算错误。
3. 周期用自然月、升级差价用 30 天，两套口径并存；月末开通的止期未定义。
4. 样片确认后至上线前取消的规则空白。
5. 取消申请后订购单主状态在两个画板中不一致（制作中 vs 售后处理中）。
6. 工单状态“服务中 / 使用中”命名不一致；积分调整原因“纠正错误扣减 / 纠正错误记录”不一致；跟进方式“到店拜访 / 上门拜访”不一致。
