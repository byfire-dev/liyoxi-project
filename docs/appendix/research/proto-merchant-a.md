### 0.2 原型的示例数据基线（canvas.json `notes.readme` 第 8、9 条）

- 【明】示例时刻 2026-09-30 上午；XX 餐饮管理有限公司为专业版（09-13 至 10-12），名下 2 家门店（万达店已认证、春熙店审核中），可用积分 2,920（套餐积分 1,920 + 加购积分 1,000），名下门店共用；万达店店员 2 位、1 个邀请待接受。
- 【明】套餐价格、积分数、折扣、剧目积分价均为示例，与 PRD 第 2 章一致，正式数值待定价（PRD §12.3 第 3 项）。
- 【明】订购路径：首页 → 商城 → 详情 → 选剧单 → 确认订购（扣积分）→ 订购成功 → 我的订单 → 订单详情 → 方案确认 → 样片确认 → 发布任务 → 上线记录（readme 第 2 条）。
- 【明】原型内数据自洽性核对（本报告验算）：
  - 8 月：+6,600 −6,120 −90 = 390，09-12 24:00 清零 −390（Ledger:L33、L36-38）。
  - 9 月：+6,600 −4,500 −180 = 1,920 套餐积分；加购 +1,000；合计 2,920（Ledger:L29-32）。
  - 上线中 3 部 = 36 + 45 + 80 = 161 集（Main:L44-45；Publish:L75-83）。
  - 《家有萌娃》可使用至 2027-06-30，自 2026-09-30 起剩 273 天（LaunchRecord:L19）。
  - 顶级模型：2,400 × 0.9 × 1.2 = 2,592；加购积分扣 672、剩 328（Checkout:L82-83、L94）。

4. 游客可浏览首页与商城、观看预告片（PRD §6.1 第 2 条；原型提供「先逛逛」入口）→ 目录类接口要支持匿名态，且匿名态无「折后实扣」。

```
制作中/待上线 ──客服发起取消（财务审批）──► 售后处理中 ──► 已退回积分
```

- 商家端分组（Orders:L37）：全部、制作中、待上线、上线中、已结束、售后。【推】映射：待开工 → 「制作中」或仅「全部」；已取消 / 售后处理中 / 已退回积分 → 「售后」。
- 【推】订单含多部剧时，订单状态取各订单项中「最靠前」的阶段（示例：两部剧分别处于样片待确认与样片制作中，订单显示制作中）；需业务确认。

**(2) 订单项 / 交付工单阶段**（【明】PRD §5.2，一部剧一张工单）

```
待分配 → 方案确认 → 广告准备 → 样片制作 ⇄ 样片确认 → 批量合成 → 成片交付 → 待上线 → 上线核验 → 使用中 → 到期下架 → 归档
```

- 触发点：系统/主管分配；商家确认方案（M22）；商家确认广告（M19）；剪辑师上传样片并质检；商家确认样片或提出修改意见（M23，退回样片制作）；发布专员交付成片包并生成上线任务；商家回填链接（M28）；发布专员核验；使用期结束前 30 天生成下架任务；商家确认下架、发布专员核查。
- 订单项上线状态（PRD §6.9 第 7 条）：待上线 / 上线中 / 已下架。

**(3) 交付方案 DeliveryPlan**（【明】Plan:L86-90）

```
（交付经理推送）待确认 ──商家「确认方案」──► 已确认
待确认 ──商家「联系服务经理修改」──► 修改中 ──（可多次「补充修改意见」）
修改中 ──交付经理更新并重新推送（新版本）──► 待确认
```

**(4) 样片 Sample**（【明】Sample:L69-82 + PRD §5.2）

```
制作中 ──上传并质检通过──► 待确认 ──商家「确认通过」──► 已确认
待确认 ──商家「提出修改意见」──► 修改中 ──重新上传（新版本）──► 待确认
待确认超过 2 天未处理 → 自动提醒（PRD §5.2 步骤 5）
```

**(5) 发布任务（上线子任务：订单项 × 账号）**（【明】Publish:L112 + PRD §6.10.1）

```
（成片交付时生成）待发布 ──商家回填链接并提交──► 核验中
核验中 ──通过──► 已通过（订单项 → 上线中，使用期自上线首日起算）
核验中 ──不通过──► 需补充（附原因）──商家重新回填──► 核验中
约定上线日次日仍未回填 → 逾期，服务经理跟进（使用期截止日不顺延）
```

下架任务：使用期结束前 30 天生成 → 待下架 → 商家确认下架 → 平台抽查核验（截图留证）→ 完成；逾期升级（PRD §6.10.1 第 4 条、§7.7 第 7 条）。

**(6) 付款单 PaymentOrder**（【明】5 种，PRD §5.3；`slim/admin/Orders.txt:L82`）

```
待支付 ──微信支付成功回调──► 已支付
待支付 ──选择对公转账并上传凭证──► 待确认收款 ──财务确认到账──► 已支付
待确认收款 ──财务驳回（注明原因）──► （回到待支付或已取消，未定）
待支付 ──超时未支付（后台原型示例 30 分钟）──► 已取消
已支付 ──退款审批并执行（套餐开通 7 天内且未用积分）──► 已退款
```

**(7) 套餐订阅 Subscription**（【推】，依据 Wallet / WalletExpired / PlanPick）

```
未开通 ──开通付款成功──► 生效中
生效中 ──续费 / 降级付款成功──► 生成「待生效」的下一期（当前期不变）
生效中 ──升级付款成功──► 生效中（版本立即变更，周期止日不变，补发积分）
生效中 ──到期日 24:00 且无待生效期──► 已过期（套餐积分清零、加购积分停用）
生效中 ──到期日 24:00 且有待生效期──► 下一期生效（00:00 发放新一期积分；上期剩余清零）
已过期 ──续费付款成功──► 生效中（立即恢复，发放新一期积分，加购积分恢复）
```

**(8) 积分预占 PointHold**：冻结中 → 已扣减（开始制作 / 剪辑师开始制作广告）；冻结中 → 已释放（取消、审核不通过）。已扣减后取消：按阶段比例退回（退回时原周期已结束的套餐积分按加购积分退回，PRD §2.3 第 3 条）。

**(9) 积分批次 PointLot**：有效 → 用尽；套餐积分批次在所属订阅周期结束时清零；加购积分批次在套餐过期期间停用、续费后恢复。

**(10) 选剧单项 CartItem**（Cart:L15-17）：有效 ⇄ 积分价已变动（确认新价格后回到有效）；任意 → 已失效（剧目下架 / 剩余授权期不足）；删除。

**(11) 渠道账号**（PRD §6.10.2）：待核验 → 可用 / 异常（重新上传截图 → 待核验）→ 已解绑；只有「可用」可在订购时选择（Checkout:L25）。

**(12) 广告视频**（PRD §6.4.3）：制作中 → 待确认 → 修改中 → 待确认 → 已确认（可复用）。

### 2.5 对技术选型有直接影响的要求

**A. 视频与文件**

1. 【明】竖屏 9:16、1080×1920（PRD §6.4.3 第 5 条、§8.3 第 5 条）；预告片 ≤ 3 分钟（PRD §7.2），原型示例 01:12～01:30；样片约 2 分 05 秒（Sample:L23）；单集约 2 分钟（Detail:L16）。
2. 【明】预告片首帧 ≤ 1.5 秒、多码率自适应、CDN 加速（PRD §10.1）；预告片与样片加水印，播放地址签名并设有效期、防盗链（PRD §10.2 第 2 条）→ 需要**视频点播/转码 + CDN 鉴权**能力（HLS 多码率 + URL 鉴权 + 水印转码）。参考工程已用腾讯云 COS 做对象存储（`timavia-liyo-project/README.md:43`），是否加云点播需架构师定。
3. 【明】成片包体量：80 集约 2.6 GB、60 集约 1.9 GB，下载链接 7 天有效、可重新生成（Publish:L95-96；PRD §6.10.1）；仅订单商家可下载（PRD §10.2）。
4. 【外部约束】微信小程序 `wx.downloadFile` 单次下载允许的最大文件为 200MB（官方文档表述，见 https://developers.weixin.qq.com/miniprogram/dev/api/network/download/wx.downloadFile.html ；社区讨论 https://developers.weixin.qq.com/community/develop/doc/00026a2b114dc02fbc33877b266400 ）；`wx.request` / `wx.uploadFile` / `wx.downloadFile` 最大并发 10 个、默认超时 60 秒、域名须 HTTPS 且经 ICP 备案（https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html ）。→ **整包（GB 级）无法在小程序内打包下载**，只能「逐集下载 + 保存到相册」的下载队列，或提供电脑端下载入口（H5 / 复制链接）；每集约 32 MB 在限制内。上线前须再次核实这些限制。
5. 【推】每份成片为门店单独定制、保留到剧目授权期结束（PRD §2.5），每单 2～3 GB 且互不相同；后台示例「上线中」订单 1,028 单（`slim/admin/Orders.txt:L159`）→ 成片存储为 TB 级并持续增长，需要对象存储生命周期（低频/归档）与成本评估。
6. 【明】图片单张 ≤ 5MB（超出先压缩）、视频单个 ≤ 200MB、支持断点续传（PRD §10.1）；本组画板的上传只有转账回单图片（PlanPick:L39），PRD 另要求样片修改意见可带截图（§6.9 第 6 条）。大文件上传主要在建档/素材画板（另一组报告）。

**B. 交易与一致性**

7. 【明】积分为整数，四舍五入取整（PRD §2.4）；「提交时以服务端重新计算的积分为准」（PRD §6.8 第 2 条）→ 计价在服务端用整数/定点运算（如折扣用千分比），避免浮点误差（示例 2,400 × 0.9 × 1.2）。
8. 【明】冻结 → 扣减 → 退回，先扣套餐积分（快到期先用）再扣加购积分，跨周期冻结不清零，退回时原周期已结束的按加购积分退回（PRD §2.3）→ 需要**关系型数据库事务 + 行级锁**的账户/批次/预占/流水模型；提交订购、支付回调、清零/发放任务之间存在并发，必须串行化到主体账户级。参考工程为 PostgreSQL 16 + Prisma 7（README.md:27），可满足。
9. 【明】微信支付为默认方式，另有对公转账 + 财务确认（PRD §6.15 第 1 条）；每日自动下载微信账单对账（PRD §7.9 第 5 条）；退款先审批再执行、原路退回（PRD §7.9 第 2 条）→ 需要微信支付商户号、回调公网地址、证书管理、对账任务。参考工程源码中检索 `requestPayment|wechatpay|wxpay|jsapi` 无命中（apps/mobile/src、apps/api/src、apps/worker/src、packages/services/src、packages/contract/src）→ **支付是新增能力，无可复用实现**。
10. 【明（示例）】金额范围：单笔最低 ¥1,000（加购），最高示例 ¥144,000（旗舰版年付 12,000 × 12，PRD §2.2）；大额走对公转账。
11. 【推】所有写接口（订购、付款单、确认方案/样片、回填链接）需幂等键；支付回调按微信交易号去重。

**C. 定时与异步**

12. 【明】按月发放、到期 24:00 清零、到期前 7/3/1 天提醒、使用期结束前 30/7/1 天提醒、下架任务提前 30 天生成、样片 2 天未确认提醒、上线日前 1 天与当天提醒、次日逾期（PRD §2.2、§2.3、§2.5、§5.2、§6.10.1）；后台原型另有「待支付 30 分钟自动取消」→ 需要可靠的**定时 + 延时任务队列**，任务须幂等、可补偿。参考工程有 BullMQ worker 与 maintenance / push / downloads 队列（README.md:25）。
13. 【明】核心接口 P95 ≤ 500 毫秒、可用性 ≥ 99.9%、小程序首屏 ≤ 2 秒（PRD §10.1）。
14. 【推】本组画板**没有实时性要求**（无聊天、无实时进度推送）：状态变化靠页面进入时拉取 + 订阅消息/短信触达，不需要 WebSocket。

## 5. 待拍板问题

**业务**

1. 多部剧一起订购时，发布账号、定制重点、顶级模型、广告视频、上线日期是整单一份还是逐剧设置？订单级状态如何由各剧阶段汇总？
2. 资质已通过的商家，下单后是否立即「开始制作」并扣减积分？是否需要一个可取消的缓冲时间？
3. 降级是否必须立即预付下一期？季付/年付中途升级，剩余已付月份如何补差与补发积分？套餐过期后续费，新周期从付款日起算还是接续原到期日？「10-13 起按旗舰版续费」是否意味着自动续费？
4. 对公转账的金额门槛；待支付与待确认收款的超时时间（后台原型示例为待支付 30 分钟）；财务驳回后付款单回到哪个状态。
5. 样片修改意见的分类（合成问题 / 广告内容）由谁判定，计入广告修改次数并可能扣积分时如何提示商家；修改意见是否需要截图上传（PRD 有、原型无）。
6. 回填链接的粒度：每部剧每个账号一个合集链接，还是也支持按集批量粘贴；是否必须填写实际上线日期。
7. 《定制内容授权书》按订单 × 平台还是按剧 × 账号出具；是否需要电子签章；《广告制作与交付服务协议》在哪一步签署。
8. 商家端是否展示核验人/巡检人姓名与巡检明细；是否展示冻结中的积分。
9. 积分明细中，一笔订购同时扣两类积分时如何展示（拆两条还是一条带拆分）；「退回」「调整」归入哪个筛选；冻结是否在明细中出现。
10. 商家端订单页签与后台 8 种状态的映射（待开工、已取消、售后处理中、已退回积分分别归到哪里）。
