# 运维探针循环

正式 worker 每60秒执行一次 probe。独立读池最多3个连接，每条查询和写事务上限2秒，
整轮预算20秒；读侧不占租约续约池。初始化及 `--check` 不建立此读池。
持有新鲜 primary 租约才测量；每次落库重新共享锁租约并核对 holder/heartbeat，
取消或被接任不写迟到事实。完成全部测量尝试后以完成时刻更新 `probe_at`。

当前实装15分组前四组：outbox未展开/投递滞后/死信、timer滞后/失败/入队后租约失效、
未解决不变量按P1/P2拆分、webhook失败或积压。四条聚合SQL共九个指纹目标，
派发失联采用租约过期超过两分钟仍未被扫描接管的行，避免正常接管窗口瞬时告警。
无结果或类型错误按测量失败，不能充当健康零值。连续三次测量失败开 `probe.failed` P2；
一次失败即打断所属业务及失败告警的正常计数。只通过已有唯一 alert-facts writer写事实，
三次不同的连续正常观测恢复，重复/过期样本不推进次数，不覆盖认领与通知历史。

轮次合并执行；超时返回后仍等底层有界查询退出才接受下一轮。关闭先取消、收完在途任务，
再由进程入口断开专用读池；服务不会关闭借用连接。测试只用5组DB和1组worker，
短预算/受控延迟验证取消，数据量与并发不作为MacBook Air上的生产性能结论。

后续按W2-24补队列/计费测量、机器人/短信发送及备份。当前切片没有完整
覆盖W2-24，不改变原性能验收标准，不执行外部真实通知或部署。

新增运行规则使用本环境实际周期登记：选择最近已超过完成期限的计划期次，避免周期
短于期限时永不报警；任何历史failed仍报本登记级别。Redis采用已装配通道真实ping。
长事务SQL只覆盖同库、同登录角色的连接，按数据库实际时间量60秒；其他角色与主机
指标仍交外部监控。SET ROLE不改变session_user；统计状态不可见时报告采样未知，
三轮进入probe.failed，不能记健康或恢复原告警。部署统计可见性需后续环境核验，
本片没有给账号加权限。没有等待60秒制造长事务，真实角色可见性由两个隔离连接核验。

每轮完成前，同主租约事务至多恢复100条静默超过6小时的事件（含已认领）；保留认领、
通知及发生次数，新增_recoveryReason=quiet，边界恰好6小时和probe型不自动恢复。
再发生创建新历史。这里只写恢复事实，发送恢复通知仍待后续。
