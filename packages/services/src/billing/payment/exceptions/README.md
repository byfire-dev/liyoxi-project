# 付款差异矩阵（W4-11）

正式依据为a07§3.76–3.79/4.3、08§2.6、07§2.9。四资源、十四类型，新增x01为零；现金退款一律消费W4-10的同TX申请公口，不在差异处理入口直接调用支付退款。

`matrix.ts`仅给open列出正式允许方式，已关联付款单的bill_only留给真实入账重分类，written_off仅超级管理员。列表、详情同一scope构造，孤儿只在ALL范围可见；GET只读。事实JSON只投影正式安全字段，兼容旧键但不把openid/银行账号或任意JSON整体下发。未决时长使用真实日历与只读计算，不把固定24小时当工作日。

写路径已落地：restore/rebuild_order/record_channel_refund通过既有C51占用并在事务外取得可信查询；锁后重验版本、范围、单号金额、状态与矩阵。其他分支单TX，先低阶审批/退款申请所需锁，再order290→receipt300→proof310→refund320→invoice330→exception340→file410→account420，不在差异340后补取低阶锁。灾备重建按可信attach中的原订单ID预取290锁后再进入差异锁集；退款未执行关闭回open由已合W4-10负责。

外部退款的权益包装按07:562/A156复用既有回收，不占用新闸门、不恢复权益；闸门在途不回收，已用/冻结/转出数量不伪造归零，资金事实、refund_over与entitlement_unrecovered独立保留。全部本机证据只用公开替身，未执行真实银行/渠道操作。


告警窄伴随：`alerts.ts`只读聚合未决/两高危数量及真实工作日临界，既有`ops.sql_probes`薄消费专用`billing.payment_exception`，不借用退款卡住规则。新增即P1，critical与超过1工作日的overdue有独立维度，已解决后沿原三次健康观测恢复；财务/超管铃铛与原研发运维P1通道保持去重，真实E18未验。工作日使用公共日历/工作时段，读侧事务沿原探针查询预算有界，失败不会当健康。该必要伴随经调度批准，未新增x01/循环/DDL。

Node24最小真实DB验证覆盖十四类型独立矩阵、非法方式零写、原付款/退款公口、恢复/重建/关联履约、外部退款回收和两客户端竞争；三个外部退款场景的既有billing/payment/refund共17条资金不变量均为零。四HTTP接口穿实际鉴权与幂等管线，告警新增、工作日临界、接收归属和健康清除均有定点证据。本机替身验证不代替真实渠道、银行回单或通知通道联调。
