## 0. 怎么用这份规范

**做一个页面时**，布局、文案、交互看原型（`prototype/<端>/screens/` 的截图与 `src/` 的源码）；颜色、字号、尺寸、圆角、状态色按本规范取值，不照抄源码里的零散数值。

**说法冲突时的优先级**：平台约束与业务确认（第 11 节）＞ 本规范 ＞ 原型源码 ＞ 截图。

**本规范的取值原则**

1. 不改变原型的观感。原型里两端一致、用法稳定的值，原样采用。
2. 同一个意思在原型里有多个相近的值时，收敛成一个。收敛了哪些、取了哪个，全部列在第 13 节。
3. 两端有意不同的地方（卡片圆角、按钮形状、字号基准）保留差异，分端定义。
4. 原型没画的状态（加载、失败、悬停、聚焦等），第 12 节给出默认做法，开发按此实现，不必等补稿。
5. 需要产品或设计拿主意的事项列在第 14 节，每项都带默认做法；没有回复就按默认做法执行。

文中“M:Orders”指商家端画板 `prototype/merchant/src/Orders.dc.html`，“A:Tickets”指后台画板 `prototype/admin/src/Tickets.dc.html`。

## 2. 文字

### 2.1 字体

| 变量 | 值 | 用在哪 |
| --- | --- | --- |
| family-sans | `-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif` | 全部界面文字 |
| family-serif | `'Noto Serif SC', 'Songti SC', serif` | 品牌字“狸有戏”、封面占位的剧名、头像首字；商家端的展示型标题（剧名、套餐名、门店名、横幅标题）；后台的页面标题与统计数字 |
| family-mono | `ui-monospace, Menlo, monospace` | 后台的编码字段 |

衬线字体在原型里从 Google Fonts 外链加载，正式环境不能这样做：

- **后台**：字体文件自托管，随静态资源发布。中文字体体积大，要用按字符范围分片、按需加载的打包方式，不要整包加载。只需 700 与 900 两个字重。
- **小程序**：不加载整套衬线字体。品牌字“狸有戏”做成图片；封面占位剧名、头像首字、展示型标题这类动态文字直接用上面的字体栈，系统没有宋体时回落为黑体。这是默认做法，见第 14 节第 2 项。

### 2.4 字重与数字

- 400 正文；600 标题、按钮、表单标签、状态标签；700 只用于数字强调与后台衬线标题；900 只与衬线体搭配。
- 所有数字（金额、积分、数量、时间）加 `font-variant-numeric: tabular-nums`，保证纵向对齐。原型只加了一部分，实现时补全。
- 字间距只用于衬线的品牌字、封面竖排剧名、展示型标题（1px），以及深色卡片上的眉标（12px 字，字间距 2px）。正文、按钮、标签不设。

## 3. 间距、圆角、描边、阴影

**间距阶梯**：2、4、6、8、10、12、14、16、20、24（px）。页面边距、区块间距、卡片内边距、栅格间距从这十个值里取。组件内部的尺寸不受此限，以第 4、5 节的组件规格为准（如标签内边距 `1px 6px`、分段控件轨道内边距 3、二级菜单缩进 40、空状态留白 56 与 72）。

| 用法 | 商家端 | 后台 |
| --- | --- | --- |
| 页面边距 | 左右 16；顶 4（有副栏时 0），底 20 | `20px 24px 24px` |
| 区块之间 | 12 | 16 |
| 卡片内边距 | 16；内部分组间距 12，表单卡 16 | 内容卡、图表卡 16；队列详情卡与页签面板 20；表格卡无内边距 |
| 表单字段 | 字段之间 16；标签与控件之间 6 | 字段之间 14；标签与控件之间 6 |

**圆角**

| 档位 | 商家端 | 后台 |

| 2px | 进度条、波形条 | 图例色块、进度条 |

| 8px | 宫格封面、广告视频缩略图 | 全部控件：按钮、输入框、下拉、菜单项、提示条 |

| shadow-modal | `0 24px 48px rgba(29, 26, 22, 0.24)` | 弹窗 |
| shadow-drawer | `-12px 0 32px rgba(29, 26, 22, 0.18)` | 右侧抽屉 |
| shadow-knob | `0 1px 2px rgba(29, 26, 22, 0.25)` | 开关滑块 |

## 4. 商家端小程序

### 4.1 尺寸换算

原型按 390 宽绘制。实现时 **Taro 的 `designWidth` 设 375，原型里的 px 数值原样写进样式文件，不乘换算系数**。这样在 375 宽的手机上正好是原型的数值，在更宽的手机上等比放大；NutUI 的组件也按 375 出样式，两边比例一致。原型的横向布局几乎都是弹性的，内容区从 358 变成 343 不会破版。

- 尺寸写在 `.scss` 文件里，不写行内 `style`（行内样式不参与单位转换）。只有来自设备的数值（胶囊位置、状态栏高度）才用行内样式。
- 状态色用类名修饰符（`--success`、`--info`、`--warning`、`--danger`、`--neutral`，与样式变量同名），页面里不直接写色值。
- 原型里依赖 844 屏高的绝对值要改写：弹层 `max-height: 760px` 改为屏高的 90%；全屏预览 `390 × 693` 改为满宽加 9:16 比例；聊天气泡 `max-width: 286px` 改为按容器宽度计算。

### 4.2 页面骨架

```
导航栏（原生）
副栏（可选）：页签 / 步骤条 / 筛选条，吸顶，不随内容滚动
内容区：卡片纵向排列，间距 12，页面滚动
底部操作栏（可选）
底部标签栏（四个主页面）
```

| 区域 | 规格 | 实现 |
| --- | --- | --- |
| 导航栏 | 标题 17px / 600；底色与页面底色相同 `#F6F3EE`；右上角胶囊区不放任何操作 | 用**原生导航栏**（PRD 8.3 第 1 条）。标题写在页面配置里，页面内不再画原型里那条 48px 的页头。页面带白底副栏时（订单列表、发布任务），导航栏底色设为白色，与副栏连成一体 |
| 需要自绘导航的页面 | 首页（品牌字标题）、登录页（无标题） | 自定义导航，运行时读取胶囊位置避让；胶囊左侧留 8px 以上 |
| 副栏 | 步骤条 `padding: 6px 16px 12px`；下划线页签通栏白底；分段与筛选条 `padding: 0 16px 10px` | `position: sticky`，底色必须不透明 |
| 内容区 | 左右边距 16，卡片间距 12，顶 4、底 20 | 页面级滚动，不套整页的滚动容器。局部滚动只用于横向筛选条、横滑推荐、弹层正文、客服对话区 |

## 6. 状态与颜色

### 6.1 规则

6.2 的表是规范性的：页面里的状态标签按这张表取色，状态与颜色的对应关系集中写成一份常量，页面里不写色值。

表里的颜色照原型。只有原型自相矛盾的地方（同一个状态在不同页面颜色不同）才做了裁决，裁决用下面的判断方法：

| 颜色 | 含义 | 判断方法 |
| --- | --- | --- |
| 橙 | 待处理 | 轮到**查看者这一方**动手，而且还没开始 |
| 蓝 | 进行中 | 已经在处理，或者在等对方 |
| 绿 | 成功 | 已完成、已生效、正常可用 |
| 红 | 出错 | 未通过、被驳回、异常、已过期、超时、逾期，需要补救 |
| 灰 | 已结束 | 已结束、已取消、还没到时间、草稿、中性分类 |
| 紫 | 补充分类色 | 仅后台，见 1.4 |

按这个方法，同一个状态在两端可以是不同颜色。例如“待商家确认”，商家看到的是橙色（轮到我），运营看到的是蓝色（在等商家）。

这个方法也用来给表里没有的新状态定色。原型里有几个状态并不完全符合它（商家端客服工单的“待受理”为橙；后台退款单的“待执行”、素材的“待整理”为蓝；“待巡检”“待对账”为灰；续费跟进的“待跟进”为红），这些在原型里没有矛盾，保留原型，不为了套用方法去改（见第 14 节第 6 项）。

这几种颜色优先用来表示状态。原型也用它们给少量分类标签上色（套餐变更类型、付款类型、消息类型、日志类型、封面角标、后台的短剧热度、套餐版本、服务商等级），这些保留原型的配色；今后新增的分类标签默认用中性灰（见第 14 节第 10 项）。

### 6.3 状态的叫法

同一个状态在同一端只用一个叫法。原型里并存的叫法按下表统一：

| 统一为 | 原型里并存的叫法 |
| --- | --- |
| 已通过（审核流程的结果） | 审核通过、已通过、资质已通过 |
| 待商家确认（后台） | 待确认、待商家确认 |
| 已核验 | 核验通过、已核验 |
| 提出修改意见（入口按钮） | 提修改意见、提出修改意见 |

不在统一范围内的：

- 两端对同一个状态的叫法可以不同：商家端说进展（审核中、开票中、整理中、核验中），后台说待办（待审核、待开票、待整理、待核验）。这是原型有意的写法。
- “样片确认”是交付工单的步骤名和商家端的页面标题，“样片待确认”是单部剧的状态名，两个都保留。
- 门店状态标签的取值是“审核中”与“已认证”；“已认证”不并入“已通过”。
- “提交修改意见”是表单里的提交按钮，与入口按钮“提出修改意见”不是一回事，保留。

## 7. 文案与格式

| 项 | 规则 | 例子 |
| --- | --- | --- |
| 称呼 | 对商家一律用“您”（原型唯一的例外“为你推荐”改为“为您推荐”） | “平台整理好后会通知您” |
| 金额 | “¥”开头，不留空格，千分位。商家端：整数不带小数，非整数保留两位。后台：交易、对账、结算金额固定两位小数；标价与门槛（套餐月费、等级门槛）整数不带小数 | 商家端“¥3,000”；后台付款单“¥3,000.00”，套餐“¥3,000 / 月” |
| 积分 | 整数，千分位，数字与“积分”之间留一个空格 | “2,160 积分” |
| 增减 | 积分与金额：获得用全角“＋”，扣减用“−”（U+2212，不是连字符）。百分比与环比：半角“+”与“−” | “＋1,000”“−180”“环比 +11.1%” |
| 时间 | 默认 `MM-DD HH:mm`；跨年或需要存档的（合同、发票、公告）用 `YYYY-MM-DD HH:mm`；有效期只写日期 `YYYY-MM-DD` | “09-28 10:12”“可使用至 2027-12-31” |
| 句中的日期 | 数字两侧留空格 | “10 月 12 日” |
| 日期区间 | 用“至” | “09-13 至 10-12” |
| 当日截止 | 写 24:00 | “10-12 24:00 清零” |
| 相对时间 | 当天的写“今天 HH:mm”，一分钟内写“刚刚” | “今天 09:12” |
| 时长 | `mm:ss`，两位分钟（原型里“0:42”与“00:42”并存） | “00:42”“01:12” |
| 数字与汉字之间 | 留一个空格 | “80 集”“1 个工作日”“9 折” |
| 量词 | 集（剧集）、部（短剧）、条（广告、素材、消息）、张（照片）、位（成员）、家（门店、商家）、笔（付款）、次（修改） | — |

| 省略号 | “……” | — |
| 主按钮 | 动词加宾语 | “提交审核”“加入选剧单”“确认订购” |
| 跳转按钮 | “去……”或“查看……” | “去选剧”“查看订单” |

| 取消键 | 一律“取消” | — |
| 操作结果 | 用“已”字句（“已……”或“某某已……”），带上后续 | “已上传，平台整理好后会通知您”“需求已提交，已冻结 45 积分” |

## 9. 图标与短剧封面

### 9.1 图标

两端共约 100 个线性图标，都是内联在原型源码里的 SVG。

- 画布 24 × 24，不填充，圆头圆角，颜色跟随文字色。
- 线宽跟随原型里这个图标的写法，抽取图标时原样保留：多数为 1.8；返回、关闭、14px 的小箭头，以及后台 16px 及以下的图标为 2；小尺寸的对勾为 2.4。新增图标：18px 及以上用 1.8，16px 及以下用 2。
- 常用尺寸：商家端 24（导航、标签栏）、22（行首、关闭）、20、18、16（行尾箭头）、14（链接箭头）；后台 18（菜单）、16、14。
- 管理方式：从原型源码里把图标抽成一套有名字的图标集，两端共用。小程序里做一个按名字输出的 `Icon` 组件（小程序不能直接写内联 SVG，用遮罩着色或图标字体）；后台做成 React 组件。
- 不换用 NutUI 或 Ant Design 自带的图标，线宽与风格对不上。原生标签栏的图标需要导出成图片（未选、选中各一套）。

### 9.2 短剧封面

正式封面为 3:4 竖图。原型里的“纯色块加竖排剧名”是占位样式，正式上线后作为加载中与加载失败的兜底。

| 项 | 规格 |
| --- | --- |
| 比例 | 一律 3:4，裁切方式为铺满 |
| 圆角 | 宫格封面 8；横滑卡封面 10；列表缩略图 6 |
| 缩略图尺寸 | 商家端：单张时 60 × 80（选剧单、我的短剧、订单详情等）；一行并排多张时 42 × 56（订单卡片、发布任务）。后台照原型：列表 30 × 40，详情 36 × 48 |
| 角标 | 左上角内缩 10；白底，12px / 600，圆角 4 |
| 左下角文字 | 12px，`rgba(255,255,255,0.9)`；用真实封面图时在文字下垫一层自下而上的暗色渐变（原型的纯色占位不需要，这是本规范补充的） |
| 失效态 | 整张图去色并降低不透明度到 0.45 |
| 占位样式 | 每部剧一个主色（后台数据里的颜色字段）作底；内缩 7 的白色细框（`rgba(255,255,255,0.28)`，圆角 5）；右上角竖排衬线剧名（22px / 900，字间距 4，白色）。有封面图时不显示细框与竖排剧名 |

## 10. 无障碍

| 项 | 规则 |
| --- | --- |
| 对比度 | 正文不低于 4.5。本规范的文字色与状态色组合都已达标（见第 1 节）。`#C4501B` 不作文字色；`#9A9084` 只用于禁用内容；禁用按钮文字用 `#4A433B` |
| 触控区域（商家端） | 可点区域不小于 44 × 44。小按钮（32）、筛选胶囊（34）这类视觉上较矮的元素，用内边距或扩大点击区补足；删除照片这类小按钮视觉 28、点击区 44 |
| 不单靠颜色 | 状态必须有文字；进度节点除颜色外用对勾、内点、空环区分；超时行除底色外有文字 |
| 图标按钮 | 没有文字的按钮必须有无障碍名称；纯装饰的图标对读屏隐藏 |
| 弹层（后台） | 弹窗声明为模态并关联标题；打开时焦点移入，关闭后焦点回到触发处；按 Esc 关闭 |
| 键盘（后台） | 所有操作可用键盘完成；可点的元素用按钮或链接，不给普通容器绑点击；聚焦时有可见的聚焦环（样式见第 12 节） |
| 状态播报 | 操作结果用状态播报，校验错误用警示播报；出错的控件标记为无效 |

| 画板 | 原型的写法 | 注意 |
| --- | --- | --- |
| M:Detail、M:Plan | 定制说明里有“写进剧情”一类的说法 | V1.0 的定制能力以广告植入为主，文案要与实际能力一致，由产品在做界面时收敛 |

## 12. 原型没画、开发按此补的状态

原型以主流程为主：空状态、表单校验错误、业务上的失败（核验未通过、证照无法识别）已经画了；加载、请求失败、悬停、聚焦这类状态没有画。下面是默认做法，开发直接按此实现。

**商家端**

| 状态 | 做法 |
| --- | --- |
| 首次加载 | 骨架屏：用 `#F0EBE3` 的色块占住卡片里的标题与文字位置，不转圈 |
| 加载失败 | 内容区居中：一行说明加“重新加载”按钮，样式同空状态 |
| 下拉刷新 | 列表页与四个主页面支持，用小程序原生下拉刷新 |
| 触底加载 | 列表底部一行 12px `#6F665B` 的文字：“加载中……”或“没有更多了”（后一句原型已画，见 M:Search） |
| 按钮提交中 | 按钮内显示加载图标，文字不变，不可重复点击 |
| 按下态 | 按钮与可点的行按下时不透明度 0.7 |
| 上传中 | 格子上覆盖半透明深色层与进度百分比 |
| 上传失败 | 格子上覆盖深色层，显示“上传失败”与“重试” |
| 无网络 | 浮层轻提示“网络不可用，请检查后重试”，页面保留已加载的内容 |
| 登录失效 | 回到登录页，登录后回到原页面 |

**后台**

| 状态 | 做法 |
| --- | --- |
| 悬停 | 表格行底 `#FAF8F4`；侧栏菜单项底 `rgba(255,255,255,0.06)`；主按钮底加深为 `#A63F12`；次按钮描边变 `#C4501B`；文字链加下划线 |
| 聚焦 | 输入框：描边变 `#C4501B`，外加一圈浅色光晕 `0 0 0 2px #FBEDE5`。按钮、链接、可点的行：用键盘聚焦时显示主色聚焦环 `0 0 0 2px #FFFFFF, 0 0 0 4px #C4501B`（浅色光晕在白底上看不见，不能单独用） |
| 首次加载 | 表格显示 5 行骨架；指标卡数字位置显示骨架 |
| 加载失败 | 表格区域显示说明与“重新加载”按钮 |
| 按钮提交中 | 按钮内显示加载图标，不可重复点击；弹窗在提交完成前不可关闭 |
| 无权限 | 菜单里不出现；直接访问地址时显示“没有访问权限”的整页说明 |
| 页面不存在 | 整页说明加“返回工作台” |
| 登录页 | 原型没有画板。按本规范的表单与按钮规格做一个居中的登录卡：手机号、密码，下一步输入动态口令；首次登录引导绑定动态口令 |
| 用户菜单 | 原型没有画板。点顶栏用户区展开：修改密码、动态口令设置、退出登录 |
| 全局搜索、通知面板 | 原型只有顶栏上的入口，没有结果页与面板。设计完成前隐藏这两个入口（见第 14 节第 12 项） |
| 日期筛选 | 原型用下拉与分段。需要按日期范围筛选时用 Ant Design 的日期范围选择器，套用主题 |

**原型没有的页面**

[风险文档](../docs/05-risks-and-open-issues.md)第 4 节列出了原型里没有、但 V1.0 需要的页面（商家电脑端下载页、通知设置、线下退款登记、系统健康等）。这些页面补稿之前：电脑端下载页与后台页面按本规范第 5 节的颜色、字号与控件规格实现；商家端页面按第 4 节实现。

## 15. 与 PRD 8.3 的出入

PRD 8.3 需要同步修改的地方：

| PRD 8.3 | 现状 | 建议 |
| --- | --- | --- |
| 第 1 条：页面顶部使用原生导航栏 | 首页用品牌字作标题、登录页没有标题，原生导航栏做不到 | PRD 注明首页与登录页例外（第 14 节第 4 项） |
| 第 2 条：字号四级（17、15、13、12），系统默认字体 | 原型常用六级，多出 16（卡片标题）与 14（表单标签、页签）；另用衬线体作品牌字、封面剧名与展示型标题 | PRD 补上 16 与 14 两级，并注明衬线体的使用范围；后台字号 PRD 没有规定，以本规范 2.3 为准 |
| 第 3 条：非整数保留 2 位小数 | 后台原型的交易金额带两位小数（含整数），套餐月费、汇总、门槛为整数 | 见第 14 节第 8 项 |
| 第 3 条：获得用“＋” | 商家端原型多处用半角“+” | 按 PRD 执行 |
| 第 4 条：五种状态色 | 原型另有紫色（后台的补充分类色）；“待处理”与“进行中”的界线 PRD 没有说明 | PRD 补上本规范 6.1 的判断方法 |
| 第 4 条：失效或错误用红色 | 协议与合同的“已失效”在两端原型里都是灰色，只有选剧单里的“已失效”是红色 | PRD 改为：需要商家处理的失效用红色，自然到期或被新版本取代的失效用灰色 |
| 第 5 条：移动网络下首次自动播放前提示流量消耗 | 原型没画；平台审核规范不允许自动播放，业务已确认点击播放 | PRD 删去“自动”：一律点击播放，移动网络下首次点击播放前提示 |
